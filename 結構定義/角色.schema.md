# 結構定義：角色（`story/設定/角色/`）

> **這是什麼**：定義「角色」設定的源→衍生兩檔格式。源是作者自由手寫的人物描述；衍生是 AI 依源生成的「需求衝突四象限＋預期弧線」分析，作為 `beat-test`「角色需求弧線」測試的基準。
> **方法依據**：`技巧知識庫/需求四象限.md`、`技巧知識庫/角色塑造.md`。
> **所有權**：見 `共同約定.md` 零（兩類檔案）與二（源→衍生）。取代舊的單一 `story/參照/角色需求.md`。
> **格式閘門**：`char-lint --book <書>`（源側存在性／必填節不得是佔位／front-matter 欄語意／rollup 視圖／形態並存／幕綱角色欄 token）＋`derived-sync validate`（節枚舉、裁決 blockquote）＋`derived-sync check` 的成長哨兵（檔案大小與單行長度）。**沒有檢查器的保證只是口頭承諾**（`設計原則.md` E1）——本檔每一條格式承諾後面都標了誰在守。

## 檔案佈局

```
story/設定/角色/
  <角色名>.md         # 人管·源【單檔形態】預設：作者自由寫，無格式要求
  <角色名>/           # 人管·源【目錄形態】檔名即切面選擇器（封閉五枚舉，不必全建）
    核心.md           #   他是誰／氣質／聲音          ← 幾乎每次都讀
    來歷.md           #   出身／深背景                ← character、揭底時才讀
    能力.md           #   武學／境界／隨身物          ← write 動作幕讀
    關係.md           #   與誰對衝／與誰羈絆
    水下.md           #   秘密／終局落點              ← 揭底前 write 拿不到
  <角色名>.ai.md      # AI管·衍生：需求四象限/弧線/馬斯洛/對衝關係（重生自對應源）
```

> **這一層沒有 rollup 索引**：`_index.ai.md` 2026-07-28（功能 12）廢除，全書角色清單改跑 **`char-lint --book <書> --emit`**（投影、一律 exit 0）。**別把它建回來**——`derived-sync check` 對它報「已廢除」並計入需處理，`stamp` 直接 raise。

### 兩種形態怎麼選（2026-07-27 功能 06 抉擇 3 B 改寫）

**大小與水下是兩條獨立的規則**，別把它們綁在一起：

| 規則 | 觸發者 | 強制？ |
|---|---|---|
| **因為大** → 升目錄形態 | **`derived-sync check` 的成長哨兵報 `源檔肥大`**（`SOURCE_BYTES=25000`） | 是（但**先搬後拆**，見下） |
| **因為有秘密** → 開 `<名>/水下.md` | 作者拍板某條資訊「揭底前 AI 不該讀到」的那一輪 | 是，**與大小無關** |

- **一律單檔起步。**「定位＝主角／反派」只是**建議**先分好切面（他們的源檔多半會長），**不是預設形態**。
  > **為什麼從「預設」降級成「建議」**：舊 schema 寫「定位＝主角／反派 → 預設目錄形態」，實測 **0/24 支是目錄形態**——而且兩個觸發者都已經成立過：`血刀頭陀` 的定位一直是反派，成長哨兵也一直在報它太大（32,650 B），仍然沒有人升級。**一個從未生效過的宣告式判準就是宣告，不是規則**，所以強制觸發者改成機械的那一個（哨兵），定位那一條退回建議。
- **`水下.md` 與大小脫鉤**：一個 800 B 的配角也可以有秘密。要放就升目錄形態，**只建實際用得到的切面**——五切面是**封閉枚舉，不是必填清單**，最小的目錄形態就是 `核心.md`＋`水下.md`（原單檔整支搬進 `核心.md`）。
- **`<名>.md` 與 `<名>/` 不得並存。誰守：`char-lint`。**
  > **為什麼要明文禁止**：`settings_select.load_entities` 逐項掃資料夾，並存會建出**兩個同名 Entity**，在 `by_name` 裡互相覆蓋，而覆蓋方向取決於 `iterdir` 的排序——結果是**目錄形態的切面永遠選不到，而輸出一切正常**。所以「小角色也能有水下」不靠「單檔＋一個切面目錄」硬湊，而靠最小目錄升級。（selector 那一側 2026-07-27 起遇到並存以目錄為準、跳過單檔，只為了 deterministic；**報並存是 `char-lint` 的事**。）
- **升級是搬移不是重寫**：`git mv <名>.md <名>/核心.md`（保住歷史），再把段落分派到其他切面，**內容不改寫**。原單檔不留。
- 兩種形態的衍生檔都是同一個 `<角色名>.ai.md`。

### 目錄形態的 digest（2026-07-27 補上實作）

- `<名>.ai.md` 的源 digest：單檔形態＝`<名>.md` 的內容 hash；**目錄形態＝`<名>/*.md` 的「檔名:內容hash」排序後再 hash**。
> **rollup digest 那一條隨 `_index.ai.md` 一起廢除**（2026-07-28 功能 12）。它曾寫「同層所有源的集合，**含目錄形態**」——**規則本身是對的，只是它保護的那支檔不存在了**；投影（`char-lint --emit`）是當場從資料夾與各檔 front-matter 算的，結構上不可能與源漂移，所以不需要 digest。

> **這一段 2026-07-27 之前是一條零實作的承諾**（E1 的教科書案例）。舊 schema 就寫著「rollup 的 digest 對目錄形態取其下所有切面檔的集合」，而 `derived_sync/core.py` 對非 rollup 一律找同層 `<名>.md`、rollup 只 `glob("*.md")`（不遞迴）——**目錄形態整個是壞的**：`check` 把 `<名>.ai.md` 報成 `orphan`、`stamp` 直接 raise、改動切面不會讓 rollup 變 stale。0/24 實測所以從沒撞到；把升級改成哨兵驅動之後第一支升級的角色就會撞上，所以同輪補上實作。

### 切面為什麼是這五個

前四個是「讀取頻率」分群——`write` 寫日常幕只要 `核心`，寫動作幕加 `能力`，`character` 設計時才要 `來歷`。

**`水下.md` 是存取控制，不只是分大小**：它讓 `write` 在揭底前的章節**拿不到**揭示層資訊，比物件檔的 `揭示層級`（一個給下游看的提醒，AI 讀得到、只是被要求別用）強一級。實作在 `settings_select` 的 `UNDERWATER_FACET`（預設不給，要 `--include-underwater`）。切面清單是封閉枚舉，**不得自創第六個切面**——要放的東西找不到切面，通常代表它根本不屬源檔（見下）。

## 源檔（人管·自由源，無 schema）

作者自由描述這個角色即可——**沒有格式要求，重點是好讀好改**。以下只是「可以寫什麼」的靈感，不是欄位：

```markdown
# 凱

一個怕水的鐵匠，年輕時欠了公會一屁股債。表面粗豪、其實膽小。
最想的是把債還清、贖回當掉的祖傳鐵砧，但他真正缺的是承認自己
需要別人幫忙。跟艾拉是舊識，兩人有心結。
（想到什麼寫什麼，一段話、一串 bullet、幾行對話都行。）
```

- **沒有格式要求 ≠ 沒有大小與行長限制**（`共同約定.md` 零）：自由源必須整檔讀，所以檔案大小受 `SOURCE_BYTES`（25,000 B）管、**單行受 600 字元管**。**不加 lint**——自由源沒有欄位可驗，也不該有。

### 源檔不該住什麼（三類，各有正確落點）

源檔寫的是**作者設計的角色**。下列三類雖然也跟這個角色有關，但都不屬源檔——它們是 AI 產生的、隨劇情累加的，寫進來會讓一支必須整檔讀的檔無限長大：

| 不該住源檔的 | 正確落點 | 觸發者·什麼時候搬 | 誰守 |
|---|---|---|---|
| 共創過程的**逐題問答紀錄**（Q1…Q9、本輪拍板記錄、未用備案） | `story/參照/裁決流.md`（理由）＋源檔只留**結論** | **`character` Phase 2 步驟 6，落檔的同一輪**；且**本次動到的源檔若已有舊的問答節，一併搬** | `decision-lint`；目的地存在性＝`derived-sync check` 的 `missing_destinations` |
| **正文已釘死的事實**（年齡、專名、道具語彙的定義） | 該章 `chapters/chNNNN.ai.md` 的 `## 本章事實`（`錨`） | `write`／`revise` 產出當輪 | `fact-lint` |
| **下游硬約束**（不得寫成 X、不許補和好戲） | `story/物件/<名>.md` 的「## 不得寫成什麼」 | `character` Phase 2 步驟 6，作者拍板的同一輪 | `object-lint` |

### 源檔觸頂怎麼辦：**先搬後拆**（2026-07-27 功能 06 抉擇 4 B）

1. **觸發**：成長哨兵報 `源檔肥大`。哨兵是 advisory——它示警，不擋路。
2. **先問「是不是有寄居內容」**，照上表把三類搬走。
3. **搬完再量一次**。多半就不必拆了。
4. 仍超標才**升級成目錄形態**（搬移不是重寫，見「兩種形態怎麼選」）。
5. **落理由**：怎麼拆、否決了哪些切法，append 進 `story/參照/裁決流.md`（標的寫 `設定/角色/<名>/`）。
6. **收尾驗證**：`char-lint --book <書>`（不得並存、衍生檔還在）＋`derived-sync check`（fresh、不再觸頂）。

> **為什麼順序是這樣**：這一格推翻了「觸頂＝該拆」的直覺。實測 `血刀頭陀.md` 32,650 B 觸頂，而它的直接原因**不是角色太厚，是寄居內容**——逐題問答 7 節 ＝ 4,766 字元（35.9%），加上帶日期的本輪拍板紀錄節 ＝ 8,126 字元（**61.2%**）。搬走之後剩 5,164 字元，遠低於門檻。**先拆等於把要搬走的東西分裝到五個切面檔。** 成長哨兵的單檔 hint 2026-07-27 起也是先問寄居內容、再建議升級（目錄形態那一支本來就是）。
>
> **這條程序尚未在任何活書上跑過一次**（一世之尊是刻意不遷移的病例書），所以它是規則不是經驗——同 `世界觀.schema.md` 的拆主題程序。

## 衍生檔 `<角色名>.ai.md`（AI 生成，嚴格）

```markdown
---
generated-from: <源 hash 或目錄 digest>   # 由 tools/derived_sync stamp 蓋，勿手填
generated-at: 2026-07-19
定位: 主角                        # 主角／反派／配角（char-lint 驗枚舉；rollup 那一欄的機械來源）
所屬arc: [arc01, arc03]           # 方括號清單（char-lint 驗可解析；rollup 那一欄的機械來源）
暫定: false                       # true＝待作者拍板（char-lint 驗布林；rollup 那一欄的機械來源）
伏筆: { 埋: [怕水], 收: [] }      # 名字須命中既有 registry，不得自由造字（char-lint 驗）
---
## 需求四象限
- 期盼（動力）：…
- 想要（誤導／假目標）：…
- 落差（阻礙）：…
- 需要（圓滿）：…
- （反派另給）正當需求：…（與主角同樣正確，讓矛盾更強）
- 兩難（選填）：A（想要）vs B（需要）——只能得一
## 預期弧線
盲目 → 挫折 → 醒悟 → 滿足（或標平弧線／負弧線）
## 馬斯洛層次
…
## 對衝關係
與 <角色> 在 <什麼> 上零和對撞
```

**front-matter 只有這六鍵。誰守：`char-lint` 第 3 項。**

### 為什麼砍掉 `角色`／`弧線類型`／`影響力` 三欄

> **2026-07-27（功能 06 抉擇 1 B，作者拍板）。理由是量出來的，不是偏好：**
>
> 七個宣告欄寫成機讀格式（`弧線類型: 正弧線`、`影響力: 高`），而 `tools/` 底下**零解析器**——`validate.py` 的 `REQUIRED_KEYS` 只有 `generated-from`／`generated-at` 兩個。**162 個欄位實例，程式讀取 0 個。**
>
> - **`角色`**：檔名的複本。檔名才是 ID（C1），兩者不一致時檔名為準——所以這一欄不能是真相，只能是漂移的機會。
> - **`弧線類型`**：24 支全填，**全 repo 零消費者、零假消費者**。grep 過 12 支 SKILL.md 與 7 個 tools 套件，除本 schema 與 `技巧知識庫/需求四象限.md` 外一次都沒提過。它比世界觀的 `升格哨兵` 證據更硬——那一欄至少 schema 寫了「供 beat-test/sync 盯」（一個**假的**消費者），`弧線類型` 連假的都沒宣稱。
> - **`影響力`**：05 已依同一條判準從世界觀刪掉同名欄，角色這邊 12 支還在寫。
>
> 依 **A4**「一支檔若被逐欄解析，就去找它的 lint；找不到，那支檔現在不配被解析」——這裡連解析者都不存在。**已駁回「為這三欄補 lint」**（守著一個沒人讀的欄；05 已駁回同形狀，理由見 `docs/重構/02-待用構想.md`）。
>
> **內容沒有消失，只是降級成散文**：`弧線類型` 想說的寫進 `## 預期弧線`（那本來就是它該待的地方）；`影響力` 寫進 `## 對衝關係`，或——若它是「這個角色抽掉三條線全塌」這種**作者拍板的承重判斷**——寫進 `story/物件/<名>.md` 的「## 為什麼存在」（那才不會被重生吃掉）。
>
> **既有書仍帶這幾欄的，`char-lint` 會聚合報一行**——那是預期的，不是 bug。同輪一併報 01 已搬走的 `🧊水下`（實測 14 支還在寫）。

### 留下來的四欄，每一欄都指得出讀它的那一行（E1）

**這是抉擇 1 B 成立的條件，不是加分項**——留下的欄若 `char-lint` 沒有真的讀它，就該跟著另外三欄一起刪。

| 欄 | 讀它的那一行 | 驗什麼 |
|---|---|---|
| `定位` | `char_lint.check_derived`（枚舉）＋`check_rollup`（≡ rollup 的 `定位` 欄） | ∈ 主角／反派／配角 |
| `所屬arc` | 同上（≡ rollup 的 `所屬arc` 欄） | 是方括號清單、可解析 |
| `暫定` | 同上（≡ rollup 的 `暫定` 欄，`true`↔`是`／`false`↔`否`） | ∈ `true`／`false` |
| `伏筆` | `char_lint.check_derived` 第 4 項（歸一到既有 registry） | 結構可解析、名字命中 registry |

> **`所屬arc` 的 token 格式（`arcNN` vs `卷一`）本 schema 不宣稱、不驗**——驗不到的就不宣稱（E1）。`char-lint` 只驗它是方括號清單且與 rollup 那一欄一致。

### `伏筆` 欄不是第三份名冊

同 `世界觀.schema.md` 的同名欄，判準完全一致：

- 它是對既有 registry 的**引用**，不是自己的名冊。名字只能命中 **① 幕綱裡既有的 `埋|收[[伏筆:x]]` 標記名，或 ② `story/物件/<名>.md` 的檔名**（C3：抽取器只能命中既有 ID，不得自由造字）。
- **誰守**：`char-lint` 第 4 項，與 `world-lint` 第 3 項、`beat-lint` 的伏筆近似名同一把尺。實測角色這一份 12 個宣告名有 1 個幕綱查無（`武道為何被毀`）。
- **它是提示不是門檻**：`物件.schema.md` 明訂「沒有物件檔的 ID 是合法的」，所以查無的名字報成可疑點、不擋路。
- **空的宣告是合法的**（`伏筆: { 埋: [], 收: [] }` ＝這個角色不牽伏筆）。
- **人不手打 `[[伏筆:x]]`**（C4）：人寫散文，AI 在衍生層標 ID。

### 節是封閉枚舉，而且**必填節不得是佔位**

**衍生檔只能有上列四個 `##` 節，一個都不能多**（誰守：`derived-sync validate` 的節枚舉＋成長哨兵 `unsliceable_derived`）。

**`## 需求四象限` 與 `## 預期弧線` 是必填，而且不得只寫佔位**（誰守：`char-lint` 第 1 項）。判準是**形狀不是詞表**：一個 slot 的值為空、或整個就是一段括號註記（`（源檔未載，待跑 character 補）`），它就是註記不是內容。

> **為什麼這一條要有守衛。** 實測 **12/24 支衍生檔的必填節是佔位**（84 處「（源檔未載，待跑 `character` 補）」）——而 `beat-test` 測試4「角色需求弧線」拿的就是這兩節當基準，**它拿到四個佔位字串而不會知道**。更糟的是**三支守衛全部回報正常**：`check` 印 fresh（源真的沒變，它報得沒錯）、`validate` 只驗節枚舉不驗節內容、`settings-select` 照樣把它算進「角色命中 N 筆」。**沒有任何一支做錯，病在沒有人負責問「選出來的東西有沒有內容」**——`設計原則.md` E2 的新推論（「覆蓋率行要能回答命中的裡面幾筆是空的」）就是從這一格立的。
>
> **不要為了讓工具看得見而建空殼檔。** 實測 13 支帶「甲批機械可見度檔」頭註的衍生檔，它們的頭註逐字寫著建檔理由：`derived_sync` 從衍生側掃描，「源檔有、衍生檔不存在」在定義上掃不到。**空殼檔是症狀，掃描方向才是病**——2026-07-27 起 `char-lint` 第 2 項從**源側**掃，這個代償不再需要（已駁回，見 `docs/重構/02-待用構想.md`）。

### 衍生檔不複製源

**不得開 `## 源檔既載要點（原話搬運）` 這類節**（實測 12/24 支有）。它不是「源的新表述」（第二問允許的那一種，字數十倍也仍是同步），它是同一段文字的第二份拷貝——源改了複本不會動（無人比對），而複本讓衍生檔的體積與源綁在一起長。**要看源就讀源**：`settings-select` 的 `read_paths` 本來就同時給衍生與源兩邊。

### 枚舉外的節：三個家與它們的觸發者

實測 24/24 支全帶枚舉外的節，共 24 種節名／64 個實例，**佔全部節內容的 72.2%**。三個目的地在 2026-07-27（功能 01／04）已經蓋好——**缺的一直只是「誰去搬」**，所以下表的第三欄是本節的重點：

| 曾經出現的自創節 | 那些內容其實是 | 該去哪 | 觸發者·什麼時候搬 |
|---|---|---|---|
| `## 硬事實`、`## 已落定的硬事實…不可翻案` | 正文釘死的年齡／專名／道具語彙 | 該章 `chNNNN.ai.md` 的 `## 本章事實`（`錨`） | **`character` Phase 2 步驟 5，重生的同一輪**：本次動到的角色，既有枚舉外節一併分派掉 |
| `## 下游硬約束`、`## 反派備註`、`## 分寸（最要守的一條）` | 不得寫成 X 的排除線 | `story/物件/<名>.md` 的「## 不得寫成什麼」 | 同上 |
| `## 🧊 水下`、`## 三重秘密` | 揭示層級 | `story/物件/<名>.md` 的 `揭示層級` 欄 | 同上 |
| `## 待裁決回饋` | 下游 skill 的觀察 | `story/參照/待裁決.md` | 同上（04 已定落點，**清理的觸發者是本輪補的**） |
| 檔末的裁決 blockquote（`> 2026-07-25（character 補厚…）`） | 為什麼這樣定 | `story/物件/<名>.md` 的「## 為什麼存在」（物件級）／`裁決流.md`（書級） | `character` Phase 2 步驟 6 |

**`.ai.md` 一律不得出現自由 blockquote 形式的裁決日誌**（誰守：`derived-sync validate`，只算第一個 `##` 之後的行）。

> **為什麼這件事比「檔太大」嚴重。** 那 48,515 字元裡有明說要保命的東西（`不准寫成隱忍的受害者，不准長出怨氣`、`那條鏈（順序寫死·不得重排）`、`已落定的硬事實·不可翻案`），而它們住在**下一次 `character` 重生就會清掉**的位置。哨兵看得見那些節，但它報的是體積與分類，沒說「下次重生這些會消失」。而**「重生把它吃掉」與「它被正常消化」在檔案系統上留下的痕跡完全相同**——`.ai.md` 沒有 diff 會被審。

### 揭示層級不住這裡（2026-07-27 移出）

原本有一個 `## 🧊 水下` 節，還有「逐象限分【表面】/【🧊 水下｜揭示於 收[[伏筆:x]]】兩層」的寫法。**兩者都刪了**，理由是它是**作者拍板何時揭**——不可重生的新資訊，住在會被重生的 `.ai.md` 裡下次重生就沒了（而且它有三種 schema 授權的語法，工具只認一種，實測 92 次出現 91 次隱形）。

現在：

- 四象限照樣寫**角色真實**（既有規則不變）。
- 「讀者現在還不知道」記在 `story/物件/<名>.md` 的 `揭示層級` 欄（見 `物件.schema.md`）。
- **`水下.md` 仍然是更強一級的機制**：它是存取控制，`write` 在揭底前**拿不到**那份檔，不只是被要求別用。**它與角色大小無關**（見「兩種形態怎麼選」）。

### 其餘格式規則

- **真動機後段才揭示的角色**：四象限**照樣寫角色真實**，不在這裡分【表面】/【水下】兩層。「讀者現在還不知道」記在 `story/物件/<名>.md` 的 `揭示層級`；「AI 在揭底前根本不該讀到」放 `水下.md`。
- 每個主角衍生檔至少填四象限（**期盼＝動力／想要＝誤導／落差＝阻礙／需要＝圓滿**）與**預期弧線**，**且不得是佔位**（見上）。
- 弧線建議對映四過渡心境：盲目 → 挫折 → 醒悟 → 滿足；平／負弧線明標並說明理由（見 `需求四象限.md` 附錄七、`網文與文學取捨.md` 角色功能化特判）。**寫在 `## 預期弧線` 的散文裡，不是 front-matter 欄。**
- **需要應堅持到故事最後才滿足**（可中段轉換，但別中段就滿足）。
- 反派建議也給**正當需求**。
- 用字：本系統統一用「期盼」。
- 「想要＝誤導角色自己的假目標」與「表面＝誤導讀者的偽裝」常重疊但**不是同一件事**——前者是角色自我欺騙，後者是敘事對讀者的資訊控制；分層時別混。

|---|---|

| `定位`／`所屬arc`／`暫定` | 各 `<名>.ai.md` 的 front-matter |
| `一句話` | 源 `<名>.md` 的 **H1 之後第一個非空行**（見下） |

### 為什麼廢除

它是**同一個結構性錯誤的五個實例**之一：rollup 是全系統唯一一支「關於全部東西」的檔，所以任何找不到家的內容都落在它身上，而它的 digest 守的是**同層源檔集合**、不是它自己的內容——於是**沒有任何東西會反對**。

實測這一支：**35,126 B、5 天長 12.2×（每條目 7.5×，而源檔數只長 1.4×）、69.1% 是本檔獨有**，12 列單行超過 400 字元（最長 1,071）。而**投影器的核心早就寫好了**——`char-lint` 第 5 項為了比對「視圖 ≡ 資料夾」，必須先算出正確的那一份，只是把結果拿去比對而不是印出來（抉擇 4 C：**誰重算誰印，同一行程式，結構上不可能漂**）。

### `一句話` 為什麼取源檔第一段，不取 H1

抉擇 3 B 的字面是「投影改印源檔 H1」，而**實測這一軸 24/24 支的 H1 就是檔名**（`# 真慧（俗名方阿七）`）——印它等於把 ID 欄抄第二遍。報告支持 3 B 的證據只取自 `大綱/_index.md` 的 `名稱` 欄（那一軸的 H1 是有資訊的標題），沒量這一軸。

**H1 之後第一個非空行**實測 24/24 非空、中位 29 字元、最長 202、**0 支超過 400**，而且內容正是舊 `一行需求` 要裝的東西（`妙音 → 卷二 arc06 出場的江湖線第三方變數…`）。它是**位置固定的純機械來源、零 LLM**。

> **這與 08 抉擇 4 C 被駁回的「從自由源抽基調那一句」不同**：那一格抽的是**一個具名語意欄**（位置假設承載語意宣稱），這一格抽的是**檔的開頭**（位置不承載語意），而且投影只印、不取值——印錯了作者一眼看得出，因為那句話就在源檔第一段。
> **依 E1 配守衛**：`char-lint` 第 9 項驗「每支源檔 H1 之後要有非空行」，覆蓋率行印「**N/M 支是空的**」（0 也印）。**不設長度門檻**——分佈連續、沒有空隙（同抉擇 5 A 的判準），行長由 `ROLLUP_LINE_CHARS` 統一管。

## 幕綱「角色」欄與這一軸的關係

`settings-select` 的角色側**以幕的「角色」欄為準**（幕綱對「這一幕有誰」的正式宣告），拿本資料夾的檔名去比對。這一側的命中依據是對的——它不像世界觀那側是拿檔名去掃全幕散文。

- **角色欄裡 registry 查無的 token，`char-lint` 第 8 項報**（**只報出現 ≥3 次的**，聚合一行，0 也印）。只看**括號外**的 token——那是位置判準：`孟奇（真定）、主宰（六道輪回之主）` 裡括號外的才是正式宣告，括號內是註記。
- 實測一世之尊：14 幕的角色欄寫的是集合名 `同伴組`，selector 展不開它，那些幕會少選 3–4 個角色——而它印「角色命中 8 筆」時真相是 11–12 個角色在場。
- **正解是在角色欄逐一列出成員**（或用該角色的檔名）。**不要建集合名對照表**——2026-07-27 抉擇 6 C 已駁回（形狀同 05 駁回的「世界觀主題別名表」：一份會漂移而無人維護的機讀資料，漂了不會有人發現）。

## 源→衍生分權

- 作者只改源；衍生 `.ai.md` 由 `character`／`develop`／`organize`／`expand`（皆作者確認後）重生。
- 下游 skill（`beat-sheet`／`beat-test`）發現問題，只在 `story/參照/待裁決.md` 追加一列（`標的` 欄寫該角色源檔路徑），交 `character` 提請作者改源後重生。
- 消化後：**結論落源檔／該章 `## 本章事實`／`story/物件/<名>.md`，理由落該物件檔的「## 為什麼存在」或 `裁決流.md`，回饋列刪除**（見 `裁決流.schema.md`）。
- 重生後以 `tools/derived_sync stamp <角色名>.ai.md` 封章（別手算 hash），接著跑 `char-lint --book <書>`。

## 檢查點

**機械可驗的（跑工具，不靠 LLM 判斷）**：

- `char-lint --book <書>`——八項：① `需求四象限`／`預期弧線` 存在且不是佔位；② **每支源檔（`<名>.md` 或 `<名>/`）都有 `<名>.ai.md`**（從**源側**掃）；③ front-matter——不得再有 `角色`／`弧線類型`／`影響力`／`🧊水下`，且 `定位`·`暫定` 是枚舉、`所屬arc` 可解析；④ `伏筆` 每個名字命中 registry（幕綱標記 ∪ 物件檔）；⑤ **舊 `_index.ai.md` 的殘留偵測**（2026-07-28 廢除；角色清單改跑 `--emit`）＋每支源檔 H1 之後要有非空行；⑥ `一行需求` 不含 `🧊`／`【表面】`／章號；⑦ `<名>.md` 與 `<名>/` 不得並存；⑧ 幕綱角色欄裡 registry 查無且出現 ≥3 次的 token。**覆蓋率行一律印，0 也印。**
- `derived-sync validate --book <書>`——節枚舉（四節）＋檔內不得有裁決日誌 blockquote。
- `derived-sync check --book <書>`——各 `<名>.ai.md` 是否 fresh；附帶成長哨兵（檔案大小、單行長度、搬移目的地是否存在）。**舊 `_index.ai.md` 若還在，`check` 報「已廢除」並計入需處理**（`ABOLISHED_ROLLUPS`）。
- `object-lint --book <書>`——搬進物件檔的約束與揭示層級的格式；`揭示層級` 是否解析得到對應的 `收[[伏筆:x]]`，或明標跨集留白。
- **選取覆蓋率**：`settings-select --arc arcNN` 印「角色命中 N 筆，**其中 M 筆是空殼**（衍生檔缺失或必填節是佔位）」。**M > 0 代表下游拿到的基準是空的**——那正是 `char-lint` 第 1／2 項要修的東西。

**需要 LLM 判斷的（可疑點提示，非 pass/fail；供 `beat-test` 參照）**：

- 「需要」是否被拖到最後才滿足？（中段就滿足 → 弧線塌陷）
- 角色轉變是否掙來的（歷經落差、想要被擊潰），而非機器神式突然開竅？
- 主角需求是否與他人（尤其反派）需求形成衝突？

| 衍生 `<名>.ai.md` | `DERIVED_BYTES` 12,000 B | **800 字元** |

## 沿革：這一軸的守衛是怎麼長出來的

> **2026-07-29（功能 15 抉擇 1 A）從 `結構定義/共同約定.md` 八 搬來。**
> 那一節是「context 取用契約」，而它 58.4%（32,087 B）是閘門說明書，**被 12/12 支 skill 無條件整檔載入**。依 `設計原則.md` **F2**，這幾段的射程是「這一個產物軸」，所以落點是本檔——它只被動這一軸的 skill 載入。
> 逐段量過與本檔既有內容的 8-gram 重疊（12–51%）：**沒有一段是純複本**，每一段都是第三份措辭，所以是搬不是刪（A5 的驗收步驟）。

**第 ② 項是 `設計原則.md` E1 新推論的實作**（「凡宣稱『每一支 X 都有一支 Y』就要從 X 側掃」）：`derived-sync check` 從 `rglob("*.ai.md")` 出發，「源有衍生無」**在定義上掃不到**，而系統的代償是手工建 13 支空殼衍生檔去餵它。**空殼檔是症狀，掃描方向才是病。**
