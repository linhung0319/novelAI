# 結構定義：角色（`story/設定/角色/`）

> **這是什麼**：定義「角色」設定的源→衍生兩檔格式。源是作者自由手寫的人物描述；衍生是 AI 依源生成的「需求衝突四象限＋預期弧線」分析，作為 `beat-test`「角色需求弧線」測試的基準。
> **方法依據**：`技巧知識庫/需求四象限.md`、`技巧知識庫/角色塑造.md`。
> **所有權**：見 `共同約定.md` 零（兩類檔案）與二（源→衍生）。取代舊的單一 `story/參照/角色需求.md`。

---

## 檔案佈局

源檔有**兩種形態**，依角色定位選用——這是「人類可讀可寫的檔必須整檔讀，所以要靠目錄結構分檔」的落地（`共同約定.md` 零）。

```
story/設定/角色/
  <角色名>.md         # 人管·源【單檔形態】配角用：作者自由寫，無格式要求
  <角色名>/           # 人管·源【目錄形態】主角／反派預設用：檔名即切面選擇器
    核心.md           #   他是誰／氣質／聲音          ← 幾乎每次都讀
    來歷.md           #   出身／深背景                ← character、揭底時才讀
    能力.md           #   武學／境界／隨身物          ← write 動作幕讀
    關係.md           #   與誰對衝／與誰羈絆
    水下.md           #   秘密／終局落點              ← 揭底前 write 不讀
  <角色名>.ai.md      # AI管·衍生：需求四象限/弧線/馬斯洛/正當需求（重生自對應源）
  _index.ai.md        # AI管·rollup：全書角色清單，源＝本資料夾所有源的集合
```

### 兩種形態怎麼選

- **定位＝主角／反派 → 預設目錄形態**。他們的源檔一定會長，一開始就分好，作者自然被引導把資訊寫到對的切面去。
- **定位＝配角 → 單檔形態**。路人角色不必開五個空檔；跨過成長哨兵門檻時再升級成目錄。
- **升級是搬移不是重寫**：把既有 `<名>.md` 的段落分派到五個切面檔，內容不改寫。升級後刪掉原單檔（`git mv` 其中一個切面即可保住歷史）。
- 兩種形態的衍生檔都是同一個 `<角色名>.ai.md`；rollup 的 digest 對目錄形態取其下所有切面檔的集合。

### 切面為什麼是這五個

前四個是「讀取頻率」分群——`write` 寫日常幕只要 `核心`，寫動作幕加 `能力`，`character` 設計時才要 `來歷`。

**`水下.md` 是存取控制，不只是分大小**：它讓 `write` 在揭底前的章節**拿不到**揭示層資訊，比物件檔的 `揭示層級`（一個給下游看的提醒，AI 讀得到、只是被要求別用）強一級。切面清單是封閉枚舉，**不得自創第六個切面**——要放的東西找不到切面，通常代表它根本不屬源檔（見下）。

## 源檔（人管，無 schema）

作者自由描述這個角色即可——**沒有格式要求，重點是好讀好改**。以下只是「可以寫什麼」的靈感，不是欄位：

```markdown
# 凱

一個怕水的鐵匠，年輕時欠了公會一屁股債。表面粗豪、其實膽小。
最想的是把債還清、贖回當掉的祖傳鐵砧，但他真正缺的是承認自己
需要別人幫忙。跟艾拉是舊識，兩人有心結。
（想到什麼寫什麼，一段話、一串 bullet、幾行對話都行。）
```

### 源檔不該住什麼（三類，各有正確落點）

源檔寫的是**作者設計的角色**。下列三類雖然也跟這個角色有關，但都不屬源檔——它們是 AI 產生的、隨劇情累加的，寫進來會讓一支必須整檔讀的檔無限長大：

| 不該住源檔的 | 正確落點 |
|---|---|
| 共創過程的**逐題問答紀錄**（Q1…Q9、本輪拍板記錄、未用備案） | `story/參照/裁決流.co.md`（理由）＋源檔只留結論 |
| **正文已釘死的事實**（年齡、專名、道具語彙的定義） | 該章 `chapters/chNNNN.ai.md` 的 `## 本章事實`（`錨`） |
| **下游硬約束**（不得寫成 X、不許補和好戲） | `story/物件/<名>.md` 的「## 不得寫成什麼」（見 `物件.schema.md`） |

## 衍生檔 `<角色名>.ai.md`（AI 生成，嚴格）

```markdown
---
generated-from: <源 hash 或目錄 digest>   # 由 tools/derived_sync stamp 蓋，勿手填
generated-at: 2026-07-19
角色: 凱
定位: 主角                        # 主角／反派／配角
弧線類型: 正弧線                  # 平／正／負弧線
所屬arc: [arc01, arc03]
影響力: 高                        # 選填：此角色抽掉劇情會不會垮
暫定: false                       # true＝待作者拍板（沿用舊 ⚠️暫定）
伏筆: { 埋: [怕水], 收: [] }
---
## 需求四象限
- 期盼（動力）：…
- 想要（誤導／假目標）：…
- 落差（阻礙）：…
- 需要（圓滿）：…
- （反派另給）正當需求：…（與主角同樣正確，讓矛盾更強）
- 兩難（選填）：A（想要）vs B（需要）——只能得一
## 預期弧線
盲目 → 挫折 → 醒悟 → 滿足（或標平弧線／負弧線）
## 馬斯洛層次
…
## 對衝關係
與 <角色> 在 <什麼> 上零和對撞
## 待裁決回饋
| 日期 | 來源 | 發現 | 建議回寫（改哪個源檔） | 狀態 |
|------|------|------|----------------------|------|
```

### 節是封閉枚舉

**衍生檔只能有上列六個 `##` 節，一個都不能多。** 這條是硬規定，由成長哨兵 `unsliceable_derived` 與 `derived-sync validate` 計量：`.ai.md` 出現枚舉外的節，代表有內容找不到家而寄生在此。

實測過的三種寄生節與它們的正確落點（`derived-sync check` 在 `一世之尊` 上實測到 13 支設定 `.ai.md` 共 70 行）：

| 曾經出現的自創節 | 那些內容其實是 | 該去哪 |
|---|---|---|
| `## 硬事實` | 正文釘死的年齡／專名／道具語彙 | 該章 `chNNNN.ai.md` 的 `## 本章事實`（`錨`） |
| `## 下游硬約束`、`## 反派備註`、`## 已落定的硬事實…不可翻案` | 不得寫成 X 的排除線 | `story/物件/<名>.md` 的「## 不得寫成什麼」 |
| 檔末的裁決 blockquote（`> 2026-07-25（character 補厚…）`） | 為什麼這樣定 | `story/物件/<名>.md` 的「## 為什麼存在」（物件級）／`裁決流.co.md`（書級） |

**`.ai.md` 一律不得出現自由 blockquote 形式的裁決日誌。**

> **為什麼這件事比「檔太大」嚴重。** 那 70 行裡有「不可翻案」「守死」這種明說要保命的東西，而它們住在**下一次 `character` 重生就會清掉**的位置。哨兵看得見那些節，但它報的是體積，沒說「下次重生這 70 行會消失」。2026-07-27 建了物件軸，它們才有家。

### 揭示層級不住這裡（2026-07-27 移出）

原本有一個 `## 🧊 水下` 節，還有「逐象限分【表面】/【🧊 水下｜揭示於 收[[伏筆:x]]】兩層」的寫法。**兩者都刪了**，理由是它是**作者拍板何時揭**——不可重生的新資訊，住在會被重生的 `.ai.md` 裡下次重生就沒了（而且它有三種 schema 授權的語法，工具只認一種，實測 92 次出現 91 次隱形）。

現在：

- 四象限照樣寫**角色真實**（既有規則不變）。
- 「讀者現在還不知道」記在 `story/物件/<名>.md` 的 `揭示層級` 欄（見 `物件.schema.md`）。
- **`水下.md` 仍然是更強一級的機制**：它是存取控制，`write` 在揭底前**拿不到**那份檔，不只是被要求別用。

### 其餘格式規則

- **真動機後段才揭示的角色**：四象限**照樣寫角色真實**，不在這裡分【表面】/【水下】兩層（那個寫法 2026-07-27 刪除，見上）。「讀者現在還不知道」記在 `story/物件/<名>.md` 的 `揭示層級`；「AI 在揭底前根本不該讀到」放 `水下.md`。
- 每個主角衍生檔至少填四象限（**期盼＝動力／想要＝誤導／落差＝阻礙／需要＝圓滿**）與**預期弧線**。
- 弧線建議對映四過渡心境：盲目 → 挫折 → 醒悟 → 滿足；平／負弧線明標並說明理由（見 `需求四象限.md` 附錄七、`網文與文學取捨.md` 角色功能化特判）。
- **需要應堅持到故事最後才滿足**（可中段轉換，但別中段就滿足）。
- 反派建議也給**正當需求**。
- 用字：本系統統一用「期盼」。
- 「想要＝誤導角色自己的假目標」與「表面＝誤導讀者的偽裝」常重疊但**不是同一件事**——前者是角色自我欺騙，後者是敘事對讀者的資訊控制；分層時別混。

## rollup `_index.ai.md`（AI 生成）

```markdown
---
generated-from: <本資料夾源集合 digest>
generated-at: 2026-07-19
---
## 角色清單
| 角色 | 定位 | 一行需求（期盼／反派正當需求） | 所屬arc | 暫定 |
|------|------|------------------------------|---------|------|
| 凱 | 主角 | 還清債、贖回鐵砧（真需要：承認需要人） | arc01,arc03 | 否 |
```

- **用途**：避免殘影、供 `beat-test` 核對全書角色一致性。
- **「一行需求」就是一行。** 這一欄是**摘要**不是副本——要展開就去讀該角色的 `.ai.md`。實測本欄被寫成 800+ 字的段落、把整份補厚紀錄複製進來，那讓 rollup 變成第二份真相，且無人能切（成長哨兵 `long_lines` 會報）。
- **只有這兩個節**：`## 角色清單`，以及需要時的 `## 待裁決回饋`（記跨角色問題，可加「對象角色」欄）。

## 源→衍生分權

- 作者只改源；衍生 `.ai.md` 由 `character`／`develop`／`organize`／`expand`（皆作者確認後）重生。
- 下游 skill（`beat-sheet`／`beat-test`）發現問題，只在衍生檔「待裁決回饋」追加一列，交 `character` 提請作者改源後重生。
- 消化後：**結論落源檔／該章 `## 本章事實`／`story/物件/<名>.md`，理由落該物件檔的「## 為什麼存在」或 `裁決流.co.md`，回饋列刪除**（見 `裁決流.schema.md`）。
- 重生後以 `tools/derived_sync stamp <角色名>.ai.md` 封章（別手算 hash）。

## 檢查點（供 beat-test 參照）

- 「需要」是否被拖到最後才滿足？（中段就滿足 → 弧線塌陷）
- 角色轉變是否掙來的（歷經落差、想要被擊潰），而非機器神式突然開竅？
- 主角需求是否與他人（尤其反派）需求形成衝突？
- 這個角色若有 `story/物件/<名>.md`，它的 `揭示層級` 是否解析得到對應的 `收[[伏筆:x]]`，或明標跨集留白？（由 `object-lint` 機械核對；`foreshadow-project` 出報表）
- `_index.ai.md` 是否 fresh（`derived-sync check` 不報 stale）？stale＝有角色源檔改過未重生。
- `derived-sync check` 有無報 `衍生檔不可切片`（＝出現封閉枚舉外的節）或 `源檔肥大`（＝該升級成目錄形態）？
