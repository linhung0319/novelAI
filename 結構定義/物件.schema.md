# 結構定義：物件（`story/物件/<名>.md`）

> **這是什麼**：定義「具名 ＋ 隨劇情推進會變狀態」的東西住哪、長怎樣。一物件一檔、**檔名即 ID、目錄即 registry**。物件檔寫的是**不隨劇情變的那一半**（這東西是什麼、為什麼存在、不得寫成什麼、什麼時候才向讀者揭）；隨劇情變的那一半是章 delta（見 `事實流.schema.md`）。
> **方法依據**：`結構定義/設計原則.md` G1–G4（狀態物件）、C1／C3（ID 即檔名、registry）、A1（源檔）、F2（理由與規則**跟著它的射程**，2026-07-27 改寫）。
> **所有權**：**作者利器·直改**——可以直接改、要守語法，格式由 `object-lint` 守（見 `共同約定.md` 二）。與幕綱同一列。
> **沿革**：2026-07-27 建軸；同日（功能 04）新增第八型 `方針`（＋保留檔名 `全書`），讓書級方針有家。它溶掉了四個落點：`story/參照/約束.co.md`（約束）、設定層 `.ai.md` 的三種 🧊 語法（揭示層級）、設定層 `.ai.md` 的枚舉外節（實測 13 支檔 70 行）、以及「伏筆名沒有 registry、抽取器自由造字」。

---

## 為什麼要有這一軸（動格式前先讀這段）

診斷輪在 `一世之尊` 上量到的：**六種不同的「一筆」在表達同一個抽象**（狀態 delta／錨／約束／伏筆標記／揭示層級／章末狀態快照），分屬 3 個 uv 專案、5 個 schema。而其中有一筆**根本沒有落點**：

> 「這個物件是什麼、為什麼存在」——不可量，因為沒有可枚舉的地方能放它。

沒有落點的內容不會消失，它會**寄生**。實測到三種寄生：

| 寄生在哪 | 實測 | 下場 |
|---|---|---|
| 設定層 `.ai.md` 的自創節（`## 硬事實`／`## 下游硬約束`／`## 反派備註`／`## 已落定的硬事實…不可翻案`） | 13 支檔 70 行 | **下次重生就沒了**，而哨兵報的是「檔太大」，不是「這 70 行會消失」 |
| 事件行的括號註解 | 44 行 | 內容欄從 76 字脹到 194 字（最長 645），括號佔比 36%→52% |
| 設定層 `.ai.md` 的 🧊 標記 | 92 次出現 | 三種語法、工具只認一種，91 次隱形，而檢查器印「0 條為可疑點」 |

那 70 行裡有「不可翻案」「守死」這種明說要保命的東西。**它們住在下一次 `character`／`worldbuild` 重生就會清掉的位置**——這是「把 A1 內容塞進 A2 容器」，`設計原則.md` A3 說這種衝突必須解掉、不能容忍。

物件檔就是那個落點。它同時滿足四條：**A1**（無 inbound 重算規則 → 人與 AI 混寫安全，作者的手改不會被覆蓋）、**C1**（檔名天生唯一、天生有存在性檢查）、**C3**（它就是 registry）、**D1**（檔名即選擇器，查詢成本 O(相關物件)、與書長無關）。

## 檔案佈局（扁平 ＋ 型別欄）

```
story/物件/
  小玉佛來歷.md        # 型別: 伏筆、道具
  真觀.md              # 型別: 角色（因為有「不得寫成什麼」才開檔）
  金剛寺.md            # 型別: 組織
  如來神掌第三式.md    # 型別: 設定規則
  全書.md              # 型別: 方針（保留檔名，書級方針的唯一落點）
```

**不分子目錄**（2026-07-27 作者拍板）。理由是實測：`小玉佛來歷`（伏筆）與 `貼身紅繩小玉佛`（持有的道具）在一世之尊裡已經是同一個東西的兩個名字——按種類分目錄會逼「一物多型」選邊站，或允許同一個東西開兩支檔，那就違反 C1「檔名天生唯一」。扁平＋多值型別欄讓它不必選。

> **已駁回**：按種類分子目錄（`物件/伏筆/`、`物件/道具/`）。好處是 `settings-select` 這類工具能用目錄當粗選擇器；代價是把「一物多型」永久化成一個要反覆裁定的問題。**不要再提案。**

### 檔名規則

- **檔名去掉 `.md` 就是這個物件的 ID**，delta 的命題名、幕綱的 `埋/收[[伏筆:X]]`、約束的實體全都用它。
- 不得含 `〔〕[]｜|:：/\*?"<>`——它會被引用，含這些字會讓引用無法解析。
- `_` 或 `.` 開頭的檔不是物件（保留給日後的說明檔／rollup）。
- **同一件事一律沿用同一個檔名**。實測病徵：`呆底下另有東西` 與 `呆底下另有東西（真慧）` 在同一本書並存，而 `知識前沿` 的命題名比對就掛在這個命名空間上——**一個括號註解就能讓比對失準**。`object-lint` 的近似名偵測在守這一條。

## 什麼時候該開一支檔（內容測試，不是次數門檻）

> **寫得出「不得寫成什麼」或「為什麼這樣定」就開檔；兩個都寫不出來，就讓它只以 delta 存在。**

這是 G4 的可執行形式（2026-07-27 一併改寫了原則本身）。它不是量化門檻，因為量化門檻在真實語料上決定不了任何事——實測 29 個實體裡，`孟奇` 顯然要開、`金剛寺使者` 顯然不要，中間那 27 個沒有任何數字能分。

`object-lint` 把它實作成：**`## 為什麼存在` 與 `## 不得寫成什麼` 兩節都空 → 報**（這支檔不該存在，刪掉它）。

**引用次數只是提示。** 一個名字被 delta／幕綱引用 ≥3 次卻沒有物件檔時，工具印一行「要不要開一支？」——**不擋、不計入問題數、不強制**。這符合「AI 是審稿員不是門檻」（`共同約定.md` 五）。

> **沒有物件檔的 ID 是合法的。** 只有狀態沒有故事的東西（他走到哪、他拿了什麼）只以 delta 存在就好，不必為了「登記」而被迫寫出其實不需要的內容。

## 邊界（不吸收別條軸）

物件檔**只**寫不隨劇情變的那一半。三條界線，每條都對應一個「不另立第二本帳」的既有紀律：

| 不寫進物件檔 | 它住哪 | 為什麼 |
|---|---|---|
| 埋在哪一幕、收在哪一幕 | `story/幕綱/` 的 `埋/收[[伏筆:X]]` | 幕綱是揭示／回收時機的唯一真實來源（`幕綱.schema.md`「伏筆不另立登記簿」）。`揭示層級` 只放一個**指向**收點的指標，不用散文複述「此條於結局引爆」 |
| 逐幕狀態變化（知道了什麼、拿了什麼、走到哪） | 該章 `chapters/chNNNN.ai.md` 的 `## 本章事實` | 那是**正文的函數**，可重生；寫進物件檔就沒人管得了正文改動（`事實流.schema.md`「為什麼拆軸」） |
| 這個角色是誰、他要什麼 | `story/設定/角色/<名>.md`（或目錄形態的五切面） | 源檔寫的是**作者設計的角色**；物件檔寫的是**下游不准寫成什麼**。前者可以改（改源→重生），後者已成既定（要解約束得填「解除於」） |

**所以一個角色可以同時有兩支檔**（`設定/角色/真觀.md` 與 `物件/真觀.md`），那不是重複——它們回答不同的問題。只有在「寫得出不得寫成什麼」時才會有後者。

## 格式

```markdown
---
型別: 伏筆、道具                                 # 封閉八型，`、` 分隔，第一個＝主型別
揭示層級: 水下｜揭示於 收[[伏筆:小玉佛來歷]]      # 選填，預設 公開
---
# 小玉佛來歷

## 是什麼
（一段散文。這東西在故事裡是什麼、讀者會怎麼認識它。）

## 為什麼存在
（作者拍板的理由，以及**已駁回的方案**——F2 第三列，讀者是 AI 不是人。
 沒落檔的駁回下次一定會被重新提案。）

## 不得寫成什麼
| 約束名 | 不得寫成 | 生效自 | 解除於 |
|--------|---------|--------|--------|
| 不得先於少年識破信物 | 他到收束前都只當那是尋常舊物 | 全書 | 幕051（arc03） |
```

（範例用中性泛例，不引任何實書內容——schema 範例一律不污染以該書做盲測的驗證。）

- **三個節都是選填，但不能兩個都空**（見上「內容測試」）。節是**封閉枚舉**，不得自創第四個節——要放的東西找不到節，通常代表它屬別條軸（見上「邊界」）。
- **沒有 `generated-from`**：它不是衍生檔，沒有東西會重生它，所以也不必 `stamp`。

### `型別`（封閉八型）

| 型別 | 例 |
|---|---|
| `伏筆` | 小玉佛來歷、原身身世 |
| `道具` | 護身玉牌、貼身紅繩小玉佛 |
| `角色` | 真觀（因為有排除線才開檔） |
| `關係` | 孟奇↔真慧 |
| `組織` | 金剛寺、水月庵 |
| `地點` | 少林後山 |
| `設定規則` | 如來神掌第三式 |
| **`方針`** | **書級方針，只住 `story/物件/全書.md`**（見下） |

- **多值以 `、` 分隔，第一個是主型別**（`型別: 伏筆、道具`）。
- **枚舉是封閉的**：`object-lint` 擋枚舉外的值。真的需要第九型 → **停下來問作者**，別自己加一個（比照 B3「開新節／加新欄一律經 AI＋作者核可」）。理由是 G3 的「投影按型別 fold」要靠這個枚舉，一個自由字串的型別欄等於沒有型別。

### `方針`（第八型，2026-07-27 功能 04 新增）

> 這一型是「要第八型＝停下來問作者」這條規則**第一次被執行**——功能 04 停下來問了，作者拍板新增。

**它裝什麼**：射程＝全書、**不綁任何單一實體或源檔**的作者通則（「這本書不寫感情線」）。

**為什麼它需要一個落點**：`設計原則.md` **F2** 2026-07-27 改寫成「理由與規則跟著**它的射程**走」——綁單一實體→物件檔、綁單一源檔→那支源檔、綁 arc→arc 檔、**綁全書→一個每次都會被無條件載入的落點**。書級方針落不到前三格：舊判準說理由要「跟著它保護的那條規則」，而書級方針**自己就是規則**，它不保護任何別的東西。

**為什麼是物件軸**：它要的兩樣東西這裡都現成——`## 不得寫成什麼` 的規則表形狀（射程由「生效自／解除於」兩欄決定），以及 `fact-project --for-beat` 的載入路徑。

**兩條綁定規則**（`object-lint` 守）：

1. **`型別: 方針` ⇔ 檔名 `全書`**，雙向。方針不綁實體，所以它只有一個合法住址。沒有這條，「方針」會退化成第二個約束軸：誰都能開一支方針檔，而 `--for-beat` 只無條件印 `全書` 那一支，**其餘會靜默不被載入**。
2. **方針檔不得有 `揭示層級`**。它是作者的創作通則，不是會被揭示的故事內容；容忍它會讓 `foreshadow-project` 去解析一個永遠不會有收點的指標。

> **這一型與其餘七型的性質不同，而那是已知並接受的代價。** G1 說物件是「具名 ＋ 隨劇情推進**會變狀態**」的東西，方針沒有狀態——它自己就是規則。把它放進物件軸是拿一個抽象去裝它原本不管的東西，換到的是「**不必新開一條軸、而且自動被載入**」。

> **實作上的必要條件**（別在重構時刪掉）：`fact-project --for-beat` 把每個 slot 過濾through 該幕「角色」欄導出的實體集，而**沒有任何一幕的角色欄會是「全書」**——所以 `format_projection` 必須在實體過濾**之前**把方針抽出來、獨立印一節。少了這一步，「方針會自動被載入」就是假的。形狀與 arc 排除線那一節相同（功能 02）。

> **已駁回三個替代**（`設計原則.md` F2；**不要再提案**）：
> - **沿用既有的 `設定規則` 型別**：`設定規則` 的例是「如來神掌第三式」＝**世界內**的規則，而書級方針是**世界外**的創作規則（「這本書不寫感情線」）。共用一個型別值，下次要按型別 fold 時就分不開。
> - **型別欄免填、`全書` 走白名單特例**：`型別` 必填是 `object-lint` 現有的一條檢查，開一個「某些物件檔不必有型別」的洞，換到的只是不動枚舉。
> - **改住 `story/00-摘要.md` 的新節 `## 全書方針`**：摘要是每支 skill 都讀的源檔，身分正確；但它是**必須整檔讀**的自由源、有大小限制，而方針會隨書變長而長。且要改 `摘要.schema.md`（功能 08 未診斷）。**若日後推翻本型別，這是退路。**

> **這一欄不是 G3 的 fold 型別。** `設計原則.md` G3 講的「集合／純量／區間／多態」是**折法**，那要把 delta 的 6 維改成型別參數才有意義——那件事**刻意留到有真實物件檔之後再做**（否則是憑空設計型別系統），見 `docs/重構/功能報告/01-狀態物件軸.md` 步驟 5。本欄是**種類**。

### `揭示層級`（原 🧊 水下）

**三種值，二選一的紀律不變**：

```
揭示層級: 公開                                  ← 預設，可整行省略
揭示層級: 水下｜揭示於 收[[伏筆:母愛護盾]]        ← 指向幕綱裡的回收點
揭示層級: 水下｜跨集留白                         ← 本書內不揭示
```

**為什麼搬到這裡來**（2026-07-27 作者拍板，抉擇 1 B）：

1. **它不可重生。**「何時揭」是作者的裁決，正文與源檔裡沒有這句話——把 `.ai.md` 全刪掉、只拿源檔重跑一次，這條回不來。它原本被規定住在 `<主題>.ai.md`／`<名>.ai.md`，那是「不可重生的放進 `.ai.md`」，下場是重生直接消失。
2. **三種語法只有一種有人守。** 原本 `共同約定.md` 授權行內 `（🧊 水下｜…）`、`世界觀.schema.md` 授權 front-matter 鍵 `🧊水下:`、`角色.schema.md` 授權 `## 🧊 水下` 整節，而 `foreshadow_project` 只認第一種。實測 92 次出現、解析出 1 條，工具印「0 條為可疑點」exit 0。

**代價（作者已知並接受）**：讀某條世界觀規則時，得多查一次物件檔才知道它揭沒揭。換來的是它終於住在不會被重生的地方，且只有一種語法要守。

**逐象限的水下分層沒有了**：`角色.ai.md` 的四象限照樣寫**角色真實**（既有規則），「讀者現在還不知道」由對應物件的 `揭示層級` 記。`角色/水下.md` 仍然是更強一級的機制（存取控制：`write` 在揭底前**拿不到**那份檔，不只是被要求別用）。

**解析規則**（沿用 `共同約定.md` 六）：

- **判先後不能比幕號大小。** 幕號是穩定 ID、不代表全書順序；走 `story/幕綱/_順序.md`「全書順序」比 arc 先後，同一 arc 內才以幕號序為準。
- **揭示點還不存在是合法狀態。** 指向的伏筆名在幕綱找不到 `收`，但該伏筆已埋、或還有 arc 沒拆 → 標「揭示點待落幕」列為**資訊、非可疑點**。只有「找不到、且沒有未拆 arc 可解釋」才是可疑點（疑似手誤或那條伏筆已被刪）。

### `## 不得寫成什麼`（＝原本的約束表）

一條一列的**規則登記表**，4 欄。完整的「為什麼是表不是 log」見 `事實流.schema.md`；搬家換掉的是**「實體」那一欄——它現在是檔名**。

| 欄 | 內容 |
|---|---|
| 約束名 | 這條排除線的名字。同一件事一律沿用同一個名 |
| 不得寫成 | 下游不准寫出來的東西，一句話 |
| 生效自 | `全書` 或 `幕NNN（arcAA）`。**寫 `全書` 就是回溯生效**——不必為了立一條約束而偽造一個拍板幕號 |
| 解除於 | `—`（尚未解除）或 `幕NNN（arcAA）`。**延長射程＝改這一格**，不新增列 |

- **as-of 判定**：`生效自 ≤ 目標` 且（`解除於` 為 `—` 或 `目標 < 解除於`）。解除那一幕起就不再管事。
- **刻意不設「狀態」欄**：狀態可由「解除於」導出。`裁決流` 那個必須人手動維護的狀態欄，正是「`射程` 欄程式從未讀、所謂『不必有人負責刪』不成立」的失效來源；同一個坑不踩第二次。
- **指向尚未排幕的 arc 是合法狀態**：約束天生會領先幕綱（`character` 替反派立排除線時那個 arc 通常還沒排）。投影印一行資訊，不 raise。
- **同一個約束名在同一支檔出現兩列 → 報**。那代表有人「新增一列」而不是「改那一列」，而那正是改成表要防的死行累積。

## 誰在什麼時候寫

| 動作 | 誰 | 時機 |
|---|---|---|
| 新開一支物件檔 | `character`／`worldbuild`／`beat-sheet`／`develop`／`organize` | 作者拍板某條「下游不得寫成 X」或「這條何時揭」時 |
| 新增／修改一條約束 | 同上，外加 `write`／`write-test`／`revise`（促升那一路） | 作者拍板後；延長射程或解除＝**就地改欄位** |
| 校訂內容 | **作者，直接改** | 隨時。它是源檔，沒有東西會覆蓋你 |

**都是事後回報，永不作為動筆前的閘門**（`共同約定.md` 七）。

## 查詢（別整檔讀，也別整個目錄讀）

- **生效中的約束**：`fact-project --for-beat 幕NNN`（由幕綱的角色欄自動導出實體，別讓 LLM 自己填）。約束與章 delta 會合流成一份 as-of 投影。**`全書.md` 的書級方針另立一節印，不受實體過濾**（見上「`方針`」）。
- **改／解除一條約束之前**：`fact-refs --constraint <約束名>`——列出它的射程、射程內**已寫成的章**、那些章提到該實體的地方、以及射程內動到它的 delta。
  > 為什麼需要這支：`設計原則.md` E3 說約束**不會自癒**（它只被讀、不被再寫，沒有東西會撞到它），E4 說「以後會發現」要成立的前提是有反向索引。兩條原則同時指名約束，而 `fact-refs` 原本只有 `--entity` 與 `--anchor` 兩條路。
- **揭示層級的解析結果**：`foreshadow-project`（印「掃到 N 處／解析 N 處／待落幕 N 處／無法解析 N 處」）。

## 檢查器與觸發時機（E1：每條格式承諾都要指名一個守衛）

| 承諾 | 守衛 | 觸發時機 |
|---|---|---|
| 檔名合法（可被引用） | `object-lint` | 新開或改名物件檔後 |
| `型別` 必填、每個值在封閉八型內 | `object-lint` | 同上 |
| **`型別: 方針` ⇔ 檔名 `全書`（雙向）；方針檔不得有 `揭示層級`** | `object-lint` | 同上 |
| **書級方針每次都會被載入**（`### 全書方針` 節，0 條也印） | `fact-project --for-beat` | `write` 取 context 時 |
| `##` 節在封閉枚舉內 | `object-lint` | 同上 |
| 兩節都空的物件檔不該存在（內容測試） | `object-lint` | 同上 |
| `揭示層級` 語法唯一（三種值） | `object-lint` | 同上 |
| `揭示層級` 指向的收點存在（或待落幕／跨集留白） | `object-lint`；報表走 `foreshadow-project` | 同上；`beat-test` 也會看 |
| 約束表 4 欄、表頭、位置格式、同名不重複列 | `object-lint` | 改約束後 |
| 引用名與物件檔名的近似變體（同一件事兩個名字） | `object-lint` | 每次 lint |
| **「我檢查了幾支／幾條」** | `object-lint` 與 `fact-lint` 一律先印檢查範圍 | 每次執行 |

- `object-lint --book <書>` 是**物件軸的聚焦入口**；`fact-lint --book <書>` 跑的是**同一組檢查**（同一份真相，不是第二套）外加事實信封行。`fact-project` 執行前會自己先跑一次完整的，所以漏跑 `object-lint` 不會讓壞物件檔溜進投影。
- 兩個名字共用實作是刻意的：新增一個要記得跑的閘門，就是新增一個會被忘記的觸發時機。

> **最後一列是這一輪最重要的一條。** 這個功能的病歷是「宣稱了沒人守」，而它最壞的一種形態不是沒有守衛，是**有一個守衛在報告一切正常**——`foreshadow-project` 對 92 個 🧊 印「0 條為可疑點」exit 0。所以 `設計原則.md` E2 現在明文要求：每個檢查器都要能回答「我在這本書上檢查了幾筆」，不能只回答「我發現幾個問題」。
