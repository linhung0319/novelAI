## 已定案

1. **放棄全自動。** 以人使用、AI 輔助為主。功能範圍是討論世界觀、輔助建構角色、建立大綱與幕綱、寫內文。
2. **方法論不預設載入。** AI 先自由回答，作者不滿意才主動觸發招數。
3. **不測招數是否勝過自由回答。** 會觸發就代表自由回答不夠，招數只是再試一種方式。
4. **不做平時同步。** 原本的主要用途是忘記前情時查角色變化，改由搜尋取代，前提是資料好搜。只同步搜到的部分屬於低優先 bonus。
5. **不做用程式硬算的統計與門檻。**
6. **上架與題材類需求目前不做：** 數值帳、起名、書名簡介、拆書、敏感詞、版本快照作為申訴證據。
7. **知識庫要精煉、結構化、去重，取用時走 progressive disclosure。**
8. **skill 遵守 Agent Skills 規格。** 名稱只用小寫英文、數字和連字號，並與資料夾同名；招卡放 `references/`；檔案參照只從 `SKILL.md` 往下一層。
9. **每本書用獨立 git。** `novel-desk` 的 `.gitignore` 忽略 `books/`，每本書在自己的資料夾 `git init`，並要有自己的備份。不用 submodule。測試用的書也照這樣做。

## 功能

名稱除了 `change-angle` 都還沒定。

| 動作 | 內容 |
|---|---|
| 討論 | 世界觀、角色、劇情共用一個入口。預設自由回答，只讀提到的卡片。作者說「記下來」才寫檔，寫之前先給作者看 |
| `/change-angle` | 討論中叫出的動作，換一種方式再答 |
| 幫我看 | 討論中叫出的動作，用問句檢查作者覺得怪的內容 |
| 落筆 | 組出 prompt 給作者過目，開乾淨對話送出；可出 3–5 稿並排，標出重複的梗，由作者挑句拼接 |
| 局部操作 | 選一段後擴寫、補感官、改對白、提三個下一步 |
| 問全書 | 例如「他第 3 章傷哪隻手」「哪些伏筆沒收」。回答必須附章號和原句 |
| 章表 | 從檔案算出章名、摘要、視角、字數、對白數，只給人看，不設門檻 |

**建議順序：** 先做 `/change-angle`（幾乎不依賴骨架），再定骨架，然後做落筆和問全書。

### skill 結構

```
change-angle/
├── SKILL.md          # 流程＋世界觀、角色、劇情三份選單，每招一行
└── references/       # 一招一檔，同一張卡可被多個選單引用，不分子資料夾
    └── 核心謊言.md
```

| 層 | 內容 | 何時進 context |
|---|---|---|
| 1 | 名稱和描述 | 常駐 |
| 2 | `SKILL.md` | 觸發時 |
| 3 | 招卡，只讀 1–2 張 | 選定招之後 |
| 4 | `Data/` 原文 | 作者說「再深入」時 |

第 4 層的前提是新專案帶著 `Data/`，否則拿掉這層，招卡要寫得夠完整。**這點尚未決定。**

**運作方式：** AI 判斷領域和狀況，選 1–2 招直接給 2–3 個具體候選，並說用了哪招。不評分、不填表、不落檔。作者可以說「換一招」或要它列出全部。沒有合適的招就直說，照自己的想法回答。

不做自動路由：舊實驗的路由佔總成本 85%，門牌會寫錯，也會漏抓。

### 招卡格式

```markdown
# 核心謊言
適用：角色動機太套路、想不出他為何走錯路
吃：這個角色現有的設定和處境
做：找一句他深信、但其實不成立的話（如「我即我所做」「世界是不安全的」），
    反推是什麼舊傷讓他信了這句話；若是反派，把同一句推到極端。
吐：2–3 組「謊言／舊傷／這句話會逼他做的具體事」
限界：只當發想，不分型、不填表
出處：技巧知識庫/需求四象限.md §八
```

### 精煉規則

- **回頭看 `Data/` 原文。** 知識庫有提煉失真。例如原文是「猜中會不屑、猜不到會不服、猜對一半會驚喜」，入庫後只剩「別被輕易猜中」。部分招數只存在於 `Data/`。
- **保留具體例子**，卡片不寫「必須」，也不寫評分標準。
- **一招一卡。** 已知重複：連問法（H2／選題二）、主題三角（C1／主題題旨四）、謎三角（D2／伏筆三）、限制與代價（E1／世界觀八）、幕尾停止點（F2／戲劇張力二）。完整清單要逐招讀過才能確定。
- **用量建議改成文字描述**，例如「一章 2–3 處」，否則可能被當配額執行。

## 資料夾骨架（提案，待確認）

```
novel-desk/
├── .gitignore             # books/
├── .claude/skills/
├── README.md              # 一頁存放慣例，取代結構定義
└── books/<書名>/           # 獨立 git
    ├── raw/               # 隨手丟素材，沒有格式
    ├── 摘要.md            # 一頁：主線、題旨、結局、基調
    ├── 卡片/
    │   ├── 角色/<名>.md
    │   ├── 世界觀/<主題>.md  # 道具、地點也放這裡
    │   └── 水下/<名>.md
    ├── 大綱/              # 總綱.md、arc01.md…
    ├── 幕綱/arc01.md
    ├── 範文/              # 作者挑的人類片段
    ├── 正文/ch0001.md
    └── 筆記.md            # 決定和被否決的想法，一句一條
```

固定格式只留兩處，其他自由書寫，沒有 lint：

```yaml
# 卡片開頭
別名: [塔主, 白袖先生]
---
# 章節開頭
摘要: 林澈發現墨斑洗不掉，被老抄寫員瞥見。
POV: 林澈
```

舊 `書本模板/` 的處理：

| 舊內容 | 處理 |
|---|---|
| `.ai.md`、`參照/`、`幕綱/_順序.md` | 刪 |
| `物件/` | 刪，道具併入世界觀，禁令不保留 |
| `風格/` | 刪，改成 `範文/` |
| raw、摘要、大綱、幕綱、正文、角色、世界觀 | 留 |

**搜尋需求：** 一章一檔、檔名帶章號、卡片有別名、每章一句摘要。搜不到關鍵字的問題先從摘要定位再讀章。

## 水下（待確認）

還沒揭露、AI 提前知道就可能寫壞的真相，放 `卡片/水下/`。業界有對應做法（Novelcrafter `never include`、oh-story「作者真相／讀者已知」、馬良框架），「水下」這個名字和獨立資料夾則是本專案自己的。

| 動作 | 能不能看 |
|---|---|
| 討論 | 能 |
| 問全書 | 能，但要標明來自水下 |
| 落筆包 | 不能，除非作者親手寫進事件 |
| 局部操作 | 不能 |

- 埋伏筆時，事件只寫現象和外在行為，不寫原因。
- 揭曉那章由作者把真相寫進事件；之後併進公開卡片，刪除水下那支檔。
- 只有落筆包會跳過這個資料夾，作者自己寫進卡片或事件一樣會洩漏，所以送出前要過目。
- 真相已揭給讀者、只有主角不知道時，移回公開設定，並在事件註明。
