# /settle 測試：設計（2026-11-09）

> 同日改版：水下改成只管寫手看得到的場景表和卡片，摘要、大綱可以寫真相；案例 C 改測角色卡上的真實身分，B 加 ⑪。

測 novel-desk 的 `/settle`、`knowledge/checks/故事弧.md`、`knowledge/checks/場景.md`。

## 要回答的問題

1. **水下：** 對話裡談到的真相，會不會留在寫手看得到的檔（`scenes/`、角色和世界觀卡）？它有沒有把句子列出來讓作者決定，而不是自己默默拆掉？反過來，寫在 `摘要.md`、`outline/` 的真相，它會不會誤拆（這兩處可以照實寫）？
2. **清單：** 埋進去的問題抓得到幾個？沒問題的地方誤報幾個？問句作者看了覺得有沒有用？
3. **選清單：** 寫 `outline/` 讀故事弧清單、寫 `scenes/` 讀場景清單、寫卡片和摘要不套清單，有沒有讀錯？
4. **不補劇情：** 對話沒談到的內容有沒有被補進去？補了的有沒有列在「你補的東西」？
5. **矛盾和沒收斂：** 和舊檔矛盾、對話裡兩種說法沒收斂、場景表沒交出大綱寫的結尾或轉折時，有沒有問作者，而不是自己選？
6. **寫入：** 作者說照寫後，舊檔沒定案的部分有沒有逐字保留？

## 測試書：從紅月開始（引子＋ch1–57）

從 `examples/` 裡選這本，理由：

- **有現成的水下。** 「陸辛的家人是不是真的」是全書最大的懸念，到 ch57〈家人是真實的嗎〉才正面碰。真相和「讀者看到的現象」分得很清楚，好判斷有沒有漏出去。
- **有一個完整的故事弧。** 041 號污染源事件（ch16–34）有起點、高點（ch25–27〈超一級精神怪物〉〈那我是誰〉）和收尾報告，可以拿來寫大綱和場景表。ch1–15 入職可以當前一個故事弧，用來測接不接得上。
- **是網文，不像《消失的密室》那麼有名。** Claude 對劇情記得越熟，越容易「補劇情」，又看不出來是補的。
- 本 repo 已有分析（`examples/_分析/從紅月開始.md`），建材料時可以省時間。

不選的：《消失的密室》劇情太有名；《一世之尊》《神秀之主》太長，懸念也沒這麼集中；其他幾本只有 13–40 章，不一定有完整的故事弧。

## 怎麼跑

- 每個案例開一個 subagent，用和主對話相同的模型。給它 `SKILL.md` 全文，以及模擬對話（當作「剛才的對話」），工作目錄設在 novel-desk 根目錄。
- 跑到第 4 步「給作者看」就停，回傳原文。只有案例 C 會再收到「照寫」。
- 每個案例跑 2 次，看結果穩不穩，共 8 次。
- 答案表（上面 ①–⑩ 和預期）在跑之前就寫好，放在 `01-材料/`，subagent 看不到。

## 怎麼評

- **Claude 逐份讀報告，**對照答案表：抓到、漏掉、誤報，原句列出來。
- **用腳本核對事實：** 寫入後 grep 真相的關鍵詞，`scenes/`、`cards/characters/`、`cards/world/` 都不應出現（`摘要.md`、`outline/`、`cards/hidden/` 可以有）；`git diff` 看舊檔有沒有動到沒定案的部分。
- **給作者看：** 挑案例 B 一份報告，請作者判斷問句有沒有用、誤報煩不煩。結論以作者的判斷為準。

## 限制

- 模擬對話比真的對話乾淨，真實使用時「對話裡幾種說法沒收斂」會更常見、更難判斷。
- 材料、答案表、評分都出自 Claude，只算方向。真正的測試是作者之後實際使用。
- Claude 可能記得部分劇情，可能低估「補劇情」的問題。
