# 交接：novel-desk 的招卡有沒有涵蓋這幾輪談到的技巧

給另一個 Claude Code session 用。開工前先讀 `docs/搬遷到novel-desk.md` 和本資料夾的 `01-作者回饋.md`、`第二輪/01-結果.md`、`第三輪/01-結果.md`。

## 背景

2026-11-07 作者讀《典籍有誤》第 1 章，中段就讀不下去。三輪重寫後，作者把問題分成兩種：

- **沒法看**：AI 特有，這幾輪在處理。
- **好不好看**：寫作技巧，例如注意力分配、句子結構和用詞帶來的感覺、一章內與多章的節奏。

作者的判斷：第二種是技巧問題，應該由從 `Data/`、技巧知識庫萃取出來的招卡負責，不放進落筆的寫手 context（novel-desk `knowledge/索引.md` 也寫明「正文類的卡不放進落筆的寫手 context」）。

## 要檢查的技巧

這幾輪實際談到、作者確認有感的：

| 技巧 | 從哪裡來 |
|---|---|
| 讀者注意力有限：懸疑處才讓讀者猜，普通劇情（背景、主角怕什麼、想做什麼）直接說 | 作者回饋 |
| 句子接得起來：保留主語和連接詞、不用逗號切碎、第一次提到人時交代身分、多個同性角色在場時用名字、說明緊接動作、對白和動作併成一拍、不把小反應單獨成段、狀態轉換給看得見的過渡 | 作者改寫，見 `01-作者回饋.md` |
| 每件事只講一次，再提到要帶新資訊；不寫用不到的場景細節 | 第二、三輪 |
| 一章的起伏結構：背景 → 接近危機（升）→ 過渡（落，可埋解法線索）→ 危機降臨（最高）→ 解決 | 作者回饋 |
| 危機段要給足篇幅和注意力，不要和背景段平均分配 | 第三輪作者回饋 |
| 事件量決定篇幅：拆幕或幕綱轉章時，判斷每件事要多長、一章放哪些事件 | 作者，2026-11-08 |

## 要回答的問題

1. 上表每一項，novel-desk `knowledge/cards/`（107 張）和 `索引.md` 裡有沒有對應的卡？有的話是哪張，內容夠不夠；沒有的話，`Data/`、`技巧知識庫/`、`docs/實驗/寫法與感覺對照表.md` 裡有沒有來源。
2. 哪些 skill 會用到這些卡：`/check`（幫我看）、`/passage`（局部操作），還是要新的「幕綱轉章」步驟？
3. 缺的部分，建議怎麼補，交作者決定。
