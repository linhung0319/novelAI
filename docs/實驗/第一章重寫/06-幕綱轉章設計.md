# 幕綱轉章：設計討論（2026-11-08）

作者定的範圍（搬遷文件待決定 4）：在這一步決定**一章放哪些事件、每件事多長、哪段是高點**。novel-desk 現在沒有這一步，`/draft` 第 1 步直接從 `beats/` 組 prompt，模板寫死「按順序講四到七件事」和「篇幅大約三千字，寧可多一點」。

這份只做設計和提案，novel-desk 未改。

## 已知的限制

| 限制 | 出處 |
|---|---|
| 給寫手標輕重沒用：標了只會讓重事件變長，形狀、拖尾、速度起伏都不變 | `docs/實驗/事件形狀/02-結果.md` |
| 事件量配篇幅有用：兩章併一章、每件事只講一次後，「繞」消失 | `第三輪/01-結果.md` |
| brief 只寫發生什麼，不寫意義、不寫抽象行文要求 | 搬遷文件「落筆要帶過去的實驗結論」 |
| 正文類的卡不放進寫手 context | `knowledge/索引.md` |
| 用量不寫成數字配額 | 搬遷文件精煉規則（針對招卡） |

## 一個觀察：第三輪的危機為什麼不突出

`第三輪/C-brief.md` 已經把五段標成「平／往上／回落／最高」，作者讀了仍說「危機那段不夠突出」。這和事件形狀實驗一致：**標籤不改形狀。**

再看 brief 給每段的事件：

- 第四段（最高）：翻到 214 頁發黑 → 比對父親殘抄本一字不差、明白錯的是原典 → 鈴響、塔洛開始核。大約三件。
- 第五段（解決）：三條路各一句、老赫姆爭到一炷香、看見三個點想起疑字符、照抄並點下三點、塔洛翻到 214 頁停半秒說「過」並留一句話。大約六件，而且明寫「三條路每條一句話，不要展開成長段」。

高點只有三件事，而且發現之後馬上鈴響，接著就進入解法。解決段反而事件最多。P7 說高點的力道來自三樣東西：結果被延後、前面有壓縮、其他地方不搶注意力。這份 brief 在高點沒有安排延後（從鈴響到核到他桌前，中間只有「三條路各一句」），又被解決段的事件搶走篇幅。

**推論（未驗證）：** 要讓高點突出，應該靠規劃時的事件安排，例如在高點多放幾步「試、擋、再試」或延後的時間，不是靠告訴寫手「這段最高」。作者第一輪回饋的第 5 點也是這個方向：「要再演一次危機降臨時主角多做了什麼」。

## 這一步做什麼

輸入是本章對應的幕綱、前情和角色卡，產出給作者過目的「排章」，作者確認後再組寫手 prompt。排章時 Claude 用下面這些問句檢查，結果列給作者看，不寫進寫手 prompt：

| 問句 | 來源 |
|---|---|
| 每兩件事之間填得進「所以」或「但是」嗎？只填得進「然後」的，可以併掉或一句帶過嗎？ | P8（編 7） |
| 每件事最晚從哪裡開始寫、最早在哪裡結束？ | P8（編 10） |
| 這章的危機在前三分之一立起來了嗎？ | P6（編 12） |
| 過渡段有沒有在往前推，例如埋線索或改變處境？ | P6（編 9、短 19） |
| 高點前有沒有延後，例如阻礙、時限、失敗一次？高點之前的事件夠不夠短，有沒有對比？高點之外，有沒有其他地方在搶注意力？ | P7 |
| 不交代的事，哪些是刻意的懸疑，哪些只是沒寫出來？ | P1 |
| 同一件事在事件段裡出現第二次時，有沒有帶新的資訊？ | P5 |

## 需要作者決定的

### 1. 這一步放在哪

| 候選 | 做法 | 代價 |
|---|---|---|
| a | 併進 `/draft` 第 1 步：先排章給作者看，確認後再組 prompt | 最小，沿用已有的作者過目點；但一次只看一章，看不到章與章之間的起伏 |
| b | 獨立 skill，一次排完整個 arc 的章，寫成檔，`/draft` 再讀 | 看得到跨章節奏，也能處理沒分章的幕綱（例如 `一世之尊-測試` 的幕 001、002）；多一個 skill、多一個要維護的檔 |
| c | 不做 skill，討論時做，招卡給 `/check` 用（03 的候選 D、E、F1） | 不動流程；但每章都要做的事要靠作者記得叫 |

**Claude 建議 a。** `雁門鏢-測試` 的幕綱已經一章一節，a 直接可用；遇到沒分章的幕綱，第 1 步就請作者指定哪幾幕放進這一章，或由 Claude 提分法。跨章節奏等作者實際寫到幾章、覺得需要時再考慮 b。

### 2. 寫手 prompt 怎麼表現排章的結果

| 候選 | 做法 | 代價 |
|---|---|---|
| a | 在事件段裡用事件本身表現：要演的事件拆成幾步寫，帶過的事件只寫一句並註明「一句帶過」 | 形狀交給事件安排，不用標籤；「一句帶過」是長度指示，事件形狀實驗顯示 Claude 會照長度指示做，但沒單獨測過 |
| b | 照 C-brief 標段落和起伏（平、往上、最高） | 第三輪和事件形狀實驗都顯示沒效果 |
| c | 只調事件和篇幅，不加任何註記 | 最乾淨；但寫手可能把該帶過的事也演成一場 |

**Claude 建議 a。**

### 3. 篇幅

| 候選 | 做法 |

### 4. 要不要先做實驗，再寫進 novel-desk

高點的寫法只是推論。建議用《典籍有誤》第 1 章做一次小實驗：

- 甲：第三輪的 C-brief 原樣。
- 乙：照這份設計排章，高點多安排延後和主角的嘗試，解決段壓縮，拿掉段落標籤。

兩臂各 1–2 稿，由作者盲讀，只問一題：危機那段有沒有比較突出。

| 候選 | 代價 |
|---|---|
| a 先實驗 | 多一輪作者盲讀；但設計錯了不會寫進每一章 |
| b 直接寫進 `/draft`，用實際寫作來驗證 | 快；但出了問題分不出是排章的錯還是寫手的錯 |

**Claude 建議 a。**
