# 判決句分類實驗：預註冊

**寫於任何判讀開始之前（2026-11-07）。** 事後對設計的任何偏離，要記在結果報告裡，不改這支檔。唯一例外是文末附錄「候選規則核對」：它在抽取規則定案時補上，仍在任何判讀之前。

## 問題與假說

第一輪（`../00-預註冊.md`、`../01-結果報告.md`）的主指標「自解釋率」（J1＋J2 每千字）沒過效度閘門：人類 3.27、舊 AI 4.65，只差 1.42 倍，門檻是 2 倍。第一輪結果報告第三節 1 的閱讀判斷是：人類也解釋，但解釋的是**讀者不知道的資訊**（「他所指的正是孟奇和真慧」）；AI 解釋的是**意義**，替讀者下判決（「他要的就是這個」）。

**假說：** 第一輪把「交代讀者不知道的事實」和「替讀者下判決」混在一起數，所以人類和 AI 的差距被稀釋了。只數「下判決」這一類，差距才看得到。

方法借自 lieflat-less-ai-tone 的冒號研究（`RESEARCH.md`「冒號：按用途分類才有意義」）：冒號總量人類反而多，拆成七種用途後只有「結論提示」一類是真信號。這裡把同樣的拆法套到解釋句上。

## 候選抽取規則（`code/extract.py`）

1. **切段與切句。** 以換行切段。段內按 `。！？!?…` 切句（連續的句末標點與緊接的 `」』` 併入同一句）；`「」『』` 內不切句，引號整段視為句子的一部分。
2. **敘述句。** 不含任何 `「」『』` 的句子，且至少 2 個漢字。含引號的句子（對白、對白引導「他說：『…』」）一律不當候選，但仍可出現在上下文裡。
3. **只抽三類**（一句可同時屬於多類，只算一條候選）：
   - **段尾句**：段落的最後一句，且是敘述句。
   - **單句成段**：段落只有一句，且是敘述句。（單句成段的句子同時也是段尾句，這一類列出只為了記錄類別。）
   - **含解釋標記的句子**：敘述句，含下列任一標記。

     其實、原來、意思是、也就是說、換句話說、這就是、那就是、這才是、這意味、意味著、代表著、之所以、正因為、說到底、歸根結底、要的就是、要的正是、無非、不過是、他知道、她知道、我知道、他清楚、她清楚、我清楚、他明白、她明白、我明白、他懂、她懂、他很清楚、她很清楚、心裡清楚、心裡明白、終於明白、才明白、意識到

     （第一輪 `code/metrics.py` 的 `EXPL` 清單，加上她／我的對應形、「要的就是／要的正是」「無非／不過是」「意識到」；去掉「不是因為」，那是否定對比句，第一輪另有指標。）
4. **上限與抽樣。** 每篇候選超過 80 條時，按出現順序等距抽 80 條（第 i 條取原序第 ⌊i·n/80⌋ 條），不用亂數，可重現。
5. **給判者的內容**只有：前一句、【目標句】、後一句（前後句可以是對白，跨段時以 `¶` 標示換段；篇首／篇尾就留空）。不給全文、檔名、組別。
6. **候選編號**用全域流水號，順序打亂（固定 seed），編號與來源的對照另存 `candidates_key.json`，判者看不到。

## 封閉標籤（五選一）

- **交代事實**：說出讀者從前文推不出來的資訊（背景、規則、人物過去、當下新念頭）。
- **下判決**：把前文已演出的行動或情境的含義、動機、意義、情緒定論直接寫出來，替讀者做了判斷。
- **重述**：把前面幾句已講的意思換句話再講一遍，或濃縮成短句。
- **其他**：以上都不是（純動作、純描寫、純對白引導）。
- **無法判斷**：上下文不足。

## 判者

兩個判者都是 `claude-sonnet-5-5`，同一份候選、同一份判據文字（`code/rubric.py`，兩支腳本共用）。

- **判者一（主）**：`code/judge_cli.py`，沿用第一輪 `code/judge.py` 的 `claude -p` 呼叫方式（乾淨 cwd、`--tools ""`、`--setting-sources ""`、`--effort medium`、`--no-session-persistence`），一條候選一個請求，可重入，結果落在 `judgments_j1/<候選編號>.json`。
- **判者二（對照）**：用 Claude Code 的 Agent 工具開 subagent，`model: sonnet`，每個 subagent 判一批（約 50 條）。`code/judge_agent.py` 負責切批、驗證 JSON、落盤到 `judgments_j2/`。subagent 的 prompt 只含判據與候選，不含實驗目的。批次內候選來自不同篇，順序隨機。

判據要求回傳 `{"label": 五標籤之一, "reason": 20 字內理由}`。理由只供事後親讀參考，不進統計。

**格式核對**：標籤不在五個之內、或 JSON 解析不到，記為格式錯誤並重跑一次；仍錯就記「無法判斷」，格式錯誤數另外報告。

**這樣量到的 kappa 是同模型（Sonnet 對 Sonnet）在兩種呼叫環境下的重測穩定性，不是跨模型共識。** 跨模型共識本實驗不測。

判據的判斷紀律（寫進判者 prompt）：只按定義判、每條獨立、不猜來源、拿不準選「無法判斷」、只能用這五個標籤。

## 指標

- **敘述字數**：該篇漢字數扣掉 `「」『』` 內的漢字。
- **主指標「下判決每千字」**：該篇被標「下判決」的候選數，若有抽樣則按比例放大（抽樣中的下判決數 ÷ 抽樣數 × 候選總數），再除以敘述千字。
- 附帶報告：各標籤比例、「交代事實」每千字、「重述」每千字。

## 判定規則（事前寫死）

### 效度閘門

**人類基準 12 段「下判決每千字」的中位數 ≤ 舊 AI 稿 8 章中位數的 1/2。** 以判者一為準，判者二只做對照。

- **不過閘門**：結論是「計數指標到此為止，以後實驗只用 Claude 讀者」。這個結論**不能被事後分析翻案**：換標籤組合、換分母、剔除某幾段、改用判者二、換候選類別，都不能把它改成「過了」。事後分析只能寫成線索。
- **過閘門**：「下判決每千字」可以作為後續實驗的計數指標，並帶著下面的一致性條件與限制。

### 判者一致性

把標籤二分為「下判決／非下判決」，兩個判者在共同候選上的 **Cohen's kappa ≥ 0.4**。低於這條線，**即使閘門過了也只算線索，不算證據**。另報五類 kappa 供參考，不作判定。

### 人類語料反查

判者一或判者二在人類基準 12 段裡標為「下判決」的句子全部列出，由 Claude 親讀。如果多數看起來確實是人類的正常寫法（也就是說，判據抓到的東西在人類文本裡並不刺眼），結果報告要寫明：**判據抓到的東西可能不是病**，閘門結果也要一起降級解讀。

### 受測稿

各臂（S1／S2 × A B C D H QA QB QC）的「下判決每千字」只看方向，n=3 不做顯著性宣稱。回頭對照第一輪 H1（C/A、D/B）與 H3（B/A、D/C）在這個指標下方向有沒有變，倍率門檻沿用第一輪的 1.5 倍、1.2–1.5 倍報「不確定」，但這只是描述，不改第一輪的結論。

## 事前預測（供事後打臉）

1. **閘門勉強不過。** 人類網文的判決句不少（敘述者評論、吐槽式內心話），我預測人類中位數約為舊 AI 的 0.5–0.75 倍。如果真的不過，原因比較可能是判據對人類的評論式敘述也判「下判決」，而不是 AI 沒有這個病。
2. **二分 kappa 約 0.5**，過 0.4 但不高；五類 kappa 更低，主要分歧在「下判決」與「重述」、「交代事實」與「其他」之間。
3. **「無法判斷」會偏多**（10–20%），因為只給前後各一句，「前文已演出」常常看不到。
4. **「下判決」佔候選的比例**：舊 AI 稿約 20%，人類約 10%。
5. **受測稿方向**：S1 的 B 臂高於 A 臂（意義句被照抄）；長 context 對短 context 沒有一致方向；Qwen 高於 Claude。
6. **人類反查**：被標下判決的人類句子裡，有一半以上我讀起來是正常寫法（網文敘述者的評語、角色心聲）。

## 已知限制

- 兩個判者都是 Sonnet，kappa 只代表同模型穩定，不代表判得準；Sonnet 對同門腔調可能不敏感。
- 作者盲讀不會做。另出 `作者核對20句.md` 給作者十分鐘核對，作者不一定填；有填的話，以作者為準。
- 候選規則是啟發式：只抽段尾、單句成段與帶標記的句子，會漏掉不帶標記、又不在段尾的判決句。漏抽在人類與 AI 之間未必對稱（例如 AI 偏好把判決放在段尾，人類可能放在段中），這會讓差距偏大或偏小，本實驗無法分辨。
- 只給前後各一句，「前文已演出」的判斷常常要更長的上下文；判者被要求在這種情況選「無法判斷」。
- subagent 是在 Claude Code 環境裡跑的，會載入本 repo 的 `CLAUDE.md`（其中提到「AI 腔實驗」）。prompt 不提實驗目的，候選也不帶來源，但判者二的環境不是乾淨的。
- 人類語料是網文，題材與受測稿不完全相同；篇數少（12、8）。

## 附錄：候選規則核對（2026-11-07，判讀之前）

依 lieflat「改規則前先抽樣看 20 條命中，再看頻率」的規則，抽完先讀樣本再定案。共抽讀三輪 20 條，加上針對性檢查。

**第一輪（隨機 20 條，seed 1）**：20 條全是敘述句，沒有對白、標題或切句錯誤。疑似錯切的「面繞不過去。」查原文 `T1923` 第 47 行，原文就是單獨一行，不是切句錯誤。

**針對性檢查發現三個問題，修正如下：**

1. **對白引導殘句。** 網文常把「克萊恩就勢點頭道：」單獨成段，對白在下一段。這種句子不是完整敘述句，只會落進「其他」，卻佔掉人類稿的候選名額。修正：結尾是 `：` 或 `:` 的句子不當候選。
2. **語料裡的網站浮水印與斷行。** 人類基準 `T2437`、`T2555` 有「72文學網m.72wxa」之類的浮水印黏在句尾；幾段人類語料有句子中途斷行（「但相比起那個時候，他卻是／多了一分難以言喻的震驚。」），會被當成段尾句。修正：抽取前刪除 `的?72文學網[A-Za-z0-9./:]*`；段落結尾不是句末標點（`。！？!?…」』”’）)—：:`）時，與下一段合併。浮水印同時從敘述字數分母中扣除。語料檔本身不動。
3. **「原來」誤中。** 「照原來的速度」「回原來的位置」是形容詞用法。修正：「原來」只在句首或標點之後才算標記。

**第二輪（seed 3）、第三輪（標記類，seed 5）**：修正後 20 條全部是敘述句，前後文正確；結尾無句末標點的候選只剩「答得好進好部門，答得砸——」（刻意的破折號中斷，保留）；「原來」的命中只剩子句開頭的用法。

**定案數字**：69 篇共 2959 條候選（受測稿 1917、人類基準 568、舊 AI 442、S2 原著 32），超過 80 條而抽樣的有 3 篇（`T2299`、`T8556`、`T2744`）。標記命中最多的是「他知道」24、「不過是」10、「這就是」10。之後不再改抽取規則。

**判者二的候選交付方式（補充設計）**：每批候選寫成一個中性檔名的文字檔（scratchpad 下的 `batches/bNNN.txt`），subagent 的 prompt 是判據全文加上「讀這個檔、把 JSON 陣列寫到這個路徑」，不把 50 條候選貼進 prompt（避免主會話重抄約 3,000 條文字）。檔案內容就是判據要求的候選格式，沒有任何來源資訊。判者回傳的 JSON 由 `code/judge_agent.py ingest` 驗證後寫入 `judgments_j2/`。
