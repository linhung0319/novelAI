# 段落判讀表（給判者的全文）

你要逐段判讀中文小說段落。每段都附了前段和後段當上下文，但**只判「本段」**。批次裡的段落順序已經打亂，彼此不一定相連。每段獨立判，不要猜段落出自哪裡、誰寫的。拿不準時照定義選最接近的一項，不要留空。

批次檔開頭附了一份**事件清單**，列出這個故事依序發生的事。每段判下列七個欄位。

## 1. event 事件編號

這段屬於事件清單的第幾條（整數）。只填一個：一段跨兩條時，填這段主要在演的那一條。

- 對白、反應、內心話、插進來的背景說明，只要是在某條事件的過程中出現，就算那一條。
- 不屬於任何一條時填 `0`，例如章首寫景、獨立的過場、清單沒有提到的情節。

## 2. func 段落功能

單選。

| 標籤 | 定義 |
|---|---|
| 預告 | 只宣告下一段要出事，本段本身沒發生事。例：「就在這時，通鋪上傳來一陣窸窣聲。」 |
| 動作 | 角色做事，推進事件 |
| 對白 | 以台詞為主，台詞推進事件 |
| 結果 | 交代事件的結果：誰死了、東西到手了、局勢變了 |
| 反應 | 結果出來以後，旁人或當事人的表情、動作、驚叫 |
| 評語 | 敘述者或角色對剛發生的事下判斷、總結、說道理。例：「那才叫弄巧成拙。」 |
| 內心 | 角色的想法、盤算、回想 |
| 背景 | 插入設定、來歷、規則說明 |
| 描寫 | 景物、外貌、氣氛，不推進事件 |
| 音效 | 整段只有擬聲或聲響。例：「轟隆！」 |

- 一段兼有兩種時，判占篇幅較多的那種。
- 動作和結果在同一段時判「結果」。
- 只有一句「他說道：」之類的引導，台詞在下一段時，這段判「動作」。

## 3–7. 感覺

用一般網文讀者的角度判，判的是**讀到這一段時的感覺**，不判文筆好壞。感覺取決於位置，所以要看前段和後段。

| 欄位 | 維度 | 值 | 說明 |
|---|---|---|---|
| speed | 速度 | `快`／`中`／`慢`／`停` | 讀到這段時故事往前走得多快。`停`＝讀到這裡像被煞車，故事暫停不動 |
| attention | 注意力 | `盯住`／`一般`／`可略` | `盯住`＝每個字都要看；`可略`＝掃過就好，不看也不影響 |
| tension | 張力 | `升`／`持平`／`降`／`懸著` | 和前段比：`升`＝更緊；`降`＝鬆下來；`懸著`＝這段留下一個問題，讀者在等答案 |
| involve | 介入感 | `自己看到`／`被告知` | `自己看到`＝讀者從動作、對白、畫面自己看出來；`被告知`＝敘述者或角色直接把意思、結論、評價說給讀者 |
| load | 負荷 | `省力`／`一般`／`費力` | 讀懂這段要花多少力氣 |

## 輸出格式

輸出一個 JSON 物件，鍵是段落編號，值是七個欄位。每個段落編號都要有，不能多也不能少。

```json
{
  "P0001": {"event": 3, "func": "動作", "speed": "快", "attention": "一般", "tension": "升", "involve": "自己看到", "load": "省力"}
}
```

- `event` 是整數，0 到清單的最大編號。
- `func` 只能是：預告、動作、對白、結果、反應、評語、內心、背景、描寫、音效。
- 其餘欄位只能用上表列出的值。
