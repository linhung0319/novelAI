## 摘要（先看這五行）

1. **這一輪的對象是「讀」，而前十四輪的對象全部是「寫」**——十四輪把每個產物軸的**產出格式**與**守衛**補齊了（12/12 schema 指得出一支 lint、22 個指令、`meta-lint` 守守衛），而**「誰在什麼時候把什麼讀進來」從來沒有被任何檢查器碰過一次**。
2. **7 支 SKILL.md 至今仍在命令讀／寫 5 支已廢除的檔，共 20 處，其中 12 處是寫入／重生命令**——功能 10／11／12 廢除的東西，在系統唯一的執行層裡還活著。兩支 skill 的同一份檔內**直接自相矛盾**（`character:16`／`:60` vs `:67`；`write:29`／`:133` vs `:118`）。
3. **復活它們完全合法**：實測把 `_總覽.ai.md` 造回去、填對格式，`world-lint` 印「世界觀軸格式合規」exit 0，而 `derived-sync check` **主動報 `[STALE]` 要你去 stamp 它**——`core.py:36` 的 `_is_rollup` 是檔名 pattern 級的通用機制，功能 12 廢除了五個實例、**沒有廢除機制**。
4. **doc 側 : book 側 ＝ 2.79 : 1**。`write` 落一章實測載入 **663,919 B**，其中 **488,535 B（73.6%）與書無關、與 arc 無關、與寫哪一章無關**——而 `共同約定.md` 八 的硬規則**只管另外那 26.4%**。系統套件 1,059,132 B ＝一世之尊全書的 **41.1%**，零選擇器、零投影、零哨兵、零覆蓋率行。
5. **十四輪淨值仍然是大幅正的**（`write` 的 book 側因 10／11／12 少讀約 401,828 B、換成 20,108 B 的投影，**20×**）。問題不是十四輪做錯了，是**省下來的那一半有規則、長出來的那一半沒有**。

## 一、六問

> 這個功能不是一支檔，是一組**取用宣告**。逐「筆」跑六問之後它裂成**五種**內容，而它們現在同居在 `共同約定.md` 八、12 支 `SKILL.md` 與 `CLAUDE.md` 三處。

### 一「筆」內容是什麼

**一筆 ＝ 一條取用宣告：`（哪支 skill 的哪一步）×（讀哪一支檔／跑哪個投影）×（整檔還是切片）`。**

但那一節與那 12 支檔裡**還住著另外四種筆**，而它們的答案在 Q1–Q5 上全部不同：

```
EXIT=0

== derived-sync validate ==
檢查範圍：6 支 .ai.md（6 支套節枚舉／0 支只驗 front-matter）；…（**0 個是 schema 外的**）；…
所有 .ai.md 格式合規。

== derived-sync check ==
[STALE] stale     story\設定\世界觀\_總覽.ai.md  ← （rollup：1 個同層源檔）
[STALE] stale     story\設定\角色\_index.ai.md  ← （rollup：1 個同層源檔）
```

**三件事同時成立**：
1. `world-lint` 印**「世界觀軸格式合規」exit 0**——覆蓋率行甚至把「rollup 有」印成一個中性事實；
2. `derived-sync validate` 印**「所有 .ai.md 格式合規」**；
3. `derived-sync check` **主動報 `[STALE]`，要求你去 `stamp` 那支已廢除的檔**。

根因在 `derived_sync/core.py:36`：

```python
def _is_rollup(p: Path) -> bool:
    return p.name.startswith("_") and p.name.endswith(AI_SUFFIX)
```

**這是檔名 pattern 級的通用機制。功能 12 廢除了五個實例，沒有廢除機制。** `world-lint` ④⑤／`char-lint` ⑤⑥／`ch-lint` 的「殘留偵測」都是**相容模式**（「檔還在就照舊比對」），不是**存在性檢查**（「這支檔不該存在」）。所以復活之後，守衛報的是「你這一格填錯了」，永遠不是「這支檔已經廢除了」——**作者把那一格修好，那支已廢除的檔就永久合法了。**

> **這是 E2 第七形態（豁免的射程比它的理由大）的鏡像**：那一條是**豁免**的射程比理由大，這一條是**機制**的射程比它剩下的實例大。功能 11 刪掉 `_is_declarative` 時把整個 predicate 拿掉了；功能 12 廢除五支 rollup 時**只拿掉了實例**。

**所以正解不是把 A–G 整套擴張過去**（13 已記「能決定太多事的原則同樣是錯的」），是**把末節那一句從兩格改成三格**：

| 檔 | 套什麼 | 誰守 |
|---|---|---|
| 書內檔 | A–G 全套 | 12 支 lint |
| `tools/` 底下的 `.py` | 不套 A–G | `meta-lint` ＋ 測試 |
| **`.claude/skills/`、`技巧知識庫/`、`結構定義/` 的非 schema 檔** | **套 A1（身分）、A4（逐欄／逐步取值就要有 lint）、E1、E2；不套 A2／A3／A5／A6／G** | **`meta-lint` 第 10–12 項**（抉擇 2） |

理由：**它們是被 LLM 逐步取值的散文，與書內源檔同形**；而 A2（衍生）、A3（身分衝突）、A5（退役）、A6（無源衍生）、G（狀態物件）在它們身上一句話都說不出來。

**這不影響 01–14 的既有結論。** 前十四輪沒有一輪的判定對象是系統套件檔——功能 14 的對象是 `tools/` 底下的程式，而它那一句射程澄清是**為了擋住「拿 A 章去問 `sentinel.py` 是源還是衍生」**，不是為了把 SKILL.md 也排除掉。**不要據此回頭翻案。**

### 2 · D2 成本函數的第七票，而這一票的量測單位又換了（**建議只記不改**）

前六票量的是「一支檔多大」（05／06／07／08）與「一次查詢讀幾支檔」（09）與「一次完整檢查跑幾個指令」（14）。**這一票量的是「一次 skill 執行載入多少 B，而其中有多少是不隨書變的」**：

實測 `write` 落一章 **663,919 B，其中 488,535 B（73.6%）與書無關、與 arc 無關、與寫哪一章無關**——它是一個常數，而那個常數的成長軸是**功能輪次**（`共同約定.md` **43.53×**／`結構定義/` 合計 **4.53×**／`CLAUDE.md` 16.0×）。

**它與 14 的第六票是同一個機制的兩端**：那一票是守衛的**程式**在長，這一票是守衛的**說明書**在長，而說明書會被載進每一次落筆的 context。

**第七票第一次證明「不隨書長成長」的東西可以比書本身還貴**：系統套件 1,059,132 B ＝ 一世之尊全書的 **41.1%**，而它對**每一本書的每一次執行**收費（書只在自己被寫時收一次）。

建議同 07／09／14 拍板——**只記不改**；但若日後重新表述成本函數，這一票的單位（「每次執行載入 B」而不是「檔多大」）要進去。

### 與提案的出入（逐條）

1. **「20 條指向已廢除檔的宣告」是低估，實際 28 條、9 支 skill**。報告 §四 4.2 那張表漏列 `organize:34`／`organize:35`／`character:76`／`worldbuild:42`／`outline-test:44`／`write:131`，而且「`worldbuild` 7 處全清、`outline-test` 2 處已標註」也不準（各有一處沒清）。**兩支被報告判為「乾淨」的 skill 其實有殘留**——這正是「手工盤點會漏」的又一個實例，而第 10 項現在是機械的。

2. **第 10 項的射程從 SKILL.md 擴到 argparse `description`**（提案沒有這一格）。`--emit guards` 一上線就把**六支指令過期的 description 印成了事實**——`beat-lint`／`outline-lint`／`foreshadow-project` 仍寫著 `_index.md` spine、`ch-lint`／`char-lint` 寫著 `_index.ai.md` 的視圖一致性、`world-lint` 寫著 `_總覽.ai.md` 的核心規則索引。**投影的輸入自己在描述已廢除的檔，投影就會把那句話印成事實**，所以那六支同輪改掉、並由第 10 項守住。

3. **豁免補的是四筆不是三筆**。提案只說「風格軸／`chNNNN.ai.md`／`_順序.md` 三列」，實測第 11 項的反向那一半還抓到 **`story/大綱/_已併入/arcNN.md`**（`organize` 讀它當併入素材）。依 A5 它**不該有查詢入口**（給它入口等於邀請下游去讀一支已退役的檔），所以處置是寫進「不受此限」並說明**豁免的是查詢入口與體積、不豁免存在性與狀態**。

4. **抉擇 1 A 照字面達不到報告寫的 ~23,000 B**。逐段量過之後那 32,087 B 是四塊：bullet 的「驗什麼」11,399（機械來源齊 → 投影）／列舉各工具覆蓋率行內容的 blockquote 4,775（工具自己輸出的複本 → **刪**）／沿革與理由 12,173（**無機械來源**）／哨兵段 5,153。**照字面把 12,173 留在第八節只能降到 ~37,000**。本輪補問作者後拍板：逐段量 8-gram 重疊（實測 **12–51%，沒有一段是純複本**），依 F2 搬進**該軸的 `*.schema.md`**（`## 沿革：這一軸的守衛是怎麼長出來的`）——**射程是那一個產物軸，所以它只被動那一軸的 skill 載入**。實際落到 34,640 B。

#### 交回別功能的疑點

- **（→ 12）`beat-lint`／`outline-lint` 對兩支 `.md` rollup 仍是「照舊比對」的相容模式，不是存在性檢查。** 實測它們今天對 `一世之尊` 報「`大綱/_index.md` 列序非遞增 2 處」「`幕綱/_index.md` 的 `選用結構公式：` 未指路」——**那是在要求作者去「修好」一支 2026-07-28 已廢除的檔**，與 V2 在 `.ai.md` 那一半同形。本輪只處理了 `.ai.md` 那一半（`check_book` 從 `rglob("*.ai.md")` 出發，在定義上看不到 `.md`）。
