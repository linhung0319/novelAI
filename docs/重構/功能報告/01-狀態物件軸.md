## 零、先講三個實測結論（其餘都是它們的展開）

1. **新格式在真實語料上的覆蓋率是 0。** 93 章的 `chNNNN.ai.md` 裡有 `## 本章事實` 的：**0 支**。`約束.co.md`：**不存在**。`裁決流.co.md`：**不存在**。錨：**0 筆**。整套 2026-07-26／27 設計過的三類型事實軸，**從未在任何有內容的書上跑過**。現行實測到的一切都是舊的單檔 `狀態事件流.md`。
2. **唯一的格式閘門在唯一的語料上是靜音的。** `fact-lint --book 一世之尊` 印「事實信封行格式乾淨」、exit 0；同一份檔，成長哨兵報 **119 行內容欄超長（最長 619 字）＋110 行括號佔比 >40%**。若拿掉舊格式豁免，`fact-lint` 會報 **206 個問題**（長度 52 ＋ 括號 110 ＋ 夾帶語彙 44）。閘門與哨兵對同一份資料給出 0 與 229 兩個答案。
3. **🧊 水下這一整條軸沒有任何一個標記是合語法的，而且沒有人會發現。** 設定層 `.ai.md` 裡 🧊 出現 **92 次**，`scan_ice` 解析出「指向伏筆」**0 條**、「跨集留白」**1 條**、其餘 **91 次完全不被視為標記**。`foreshadow-project` 輸出「0 條為可疑點」、exit 0。原因是 schema 自己定了**三種互不相容的語法**，而工具只認其中一種。

### Q1 · 決定權在誰

|            | 決定權                                                  | 現行由誰打字                                                       | 混沒混                                    |
| ---------- | ------------------------------------------------------- | ------------------------------------------------------------------ | ----------------------------------------- |
| A 狀態     | **正文**（不是人也不是 AI——它是 `chNNNN.md` 的函數）    | `write` 章末抽                                                     | ✅ 單一                                   |
| B 錨       | 正文                                                    | 同上                                                               | ✅ 單一                                   |
| C 約束     | **作者拍板的意圖**                                      | `character`／`worldbuild`／`beat-sheet`／`write-test` 寫、作者校訂 | ✅ 單一（設計正確）                       |
| D 伏筆     | **作者**（幕綱是「作者利器·直改」，`幕綱.schema.md:5`） | 人手打機讀語法                                                     | ⚠️ 見下                                   |
| E 🧊       | 作者確認後由 skill 寫（`共同約定.md:168`）              | AI 寫進 `.ai.md`——**而 `.ai.md` 會被重生**                         | ❌ **混了**：決定權是人的，容器是可重生的 |
| F 物件定義 | 作者                                                    | 混寫                                                               | ❌ 無落點可談                             |

**Q1 抓到的最硬的一筆：E。** 🧊 標記是「作者拍板某條設定何時揭」，這是**不可重生的新資訊**（`共同約定.md:43` 的判準：把 `.ai.md` 刪掉、只拿源檔重跑，這條回不回來？大部分回不來），卻被規定住在 `<主題>.ai.md`／`<名>.ai.md`（`共同約定.md:168`）。這是「不可重生的放進 `.ai.md`」，下場是重生直接消失。

**D 的混法不同**：一個 `埋[[伏筆:x]]` 其實是兩筆——「作者決定這一幕要埋這條線」（人）與「這個 ID 叫什麼」（該是 registry 比對，C3）。現行是人自由造字，**零檢查器**（`幕綱.schema.md:126-131` 宣稱標記就是唯一真實來源，但沒有任何工具驗名字合不合法）。實測後果：`呆底下另有東西` 與 `呆底下另有東西（真慧）` 在同一本書裡並存（狀態表 17 個名 vs 幕內標記 15 個名，差的 2 個就是加了括號註解的變體）。`fact-lint` 的命題名檢查靠這個命名空間（`sources.py:209-239`），所以一個括號能讓命題名比對失準。

**E 的三種語法（這是 §零第 3 點的機制）**：

| 語法                                               | 定義在                                     | `scan_ice` 認不認                               |
| -------------------------------------------------- | ------------------------------------------ | ----------------------------------------------- |
| 行內 `（🧊 水下｜揭示於 收[[伏筆:X]]）`            | `共同約定.md:151`                          | ✅ 認（`scan.py:150` 的 `_ICE_RE` 要求有 `｜`） |
| front-matter 鍵 `🧊水下: "收[[伏筆:X]]"` / `false` | `世界觀.schema.md:46`                      | ❌ **沒有 `｜`，regex 不匹配**                  |
| `## 🧊 水下` 整節                                  | `角色.schema.md:89`、`validate.py:30` 枚舉 | ❌ 不匹配                                       |

三種都是 schema 明文授權的。工具只實作了第一種。**這不是書寫錯了，是 schema 自己分裂了。**

| 發現時機                                   | 例                                                  |
| ------------------------------------------ | --------------------------------------------------- |
| 永遠不會發現（無人守）                     | `.ai.md` 重生吃掉的待裁決回饋                       |
