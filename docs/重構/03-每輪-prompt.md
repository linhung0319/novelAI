# 重構盤點：每輪要貼的 prompt

> **這是什麼**：每個功能開一個新的 Claude Code session，從這裡複製對應的 prompt 貼進去。
> **一個功能兩輪**：診斷輪（只提案、不動手）→ 你拍板 → 重構輪（動手）。
> 只需要改 prompt 裡的 `<NN>` 與功能名。

---

## 診斷輪

```
執行 novelAI 重構盤點的診斷輪，功能 <NN>「<功能名>」。

依序讀：
1. `結構定義/設計原則.md` —— 六問與原則 A–G，這是判準
2. `docs/重構/01-功能盤點與測試順序.md` —— 找到功能 <NN>，讀它的「現行落點」與「已知疑點」
3. `docs/重構/02-待用構想.md` —— 候選解法的零件庫，以及**已駁回清單（別重新提案上面的東西）**
4. 功能 <NN> 的現行實作（檔案清單在「現行落點」欄，schema、skill、tools 都要看）

然後：
- 對這個功能跑六問。每一問問在「一筆內容」上，不是問在一支檔上。
- 逐條套用原則 A–G，列出**每一條違反**：違反哪條、現行怎麼做、證據在哪個檔哪一行。
- 每一問盡量交出一個能在 `一世之尊/` 上跑出來的數字（幾份、每份幾行、一次查詢讀幾筆、成長率）。量得到就實際去量，量不到就明說為什麼。
- 特別回答：這個功能有沒有「壞了永遠不會發現」的東西（原則 E2 最後一格）？
- 提出目標形態，以及從現況到目標的遷移路徑（含要新增／修改／刪除哪些檔與工具）。

輸出寫進 `docs/重構/功能報告/<NN>-<功能名>.md`，格式照 `docs/重構/功能報告/_範本.md`。
寫完把 `01-功能盤點與測試順序.md` 的進度表該列改成「已診斷」，並填報告連結。

限制：
- **這一輪只診斷與提案，不要動任何書內檔、schema、skill 或工具程式碼。**
- 承重抉擇一律不代決，全部列進報告的「待作者拍板」節。
- 若發現某條原則在這個功能上無法決定任何事、或反覆需要例外，把它記進報告的「原則的問題」節——原則本身也可能是錯的。
```

## 重構輪

```
執行 novelAI 重構盤點的重構輪，功能 <NN>「<功能名>」。

依序讀：
1. `docs/重構/功能報告/<NN>-<功能名>.md` —— 診斷結論與我的拍板（看「待作者拍板」節，我的決定寫在那裡）
2. `結構定義/設計原則.md` —— 判準
3. `docs/重構/02-待用構想.md` —— 要用的零件
4. 功能 <NN> 的現行實作

然後依報告裡「已拍板」的方案動手：
- 改 schema、skill、tools、書本模板
- 依原則 E1：**這一輪新增或修改的每一條格式承諾，都必須同時交出守它的檢查器**。交不出來就不要宣稱那個格式。
- 依原則 F2：這一輪拍板的理由與被駁回的方案，寫進它保護的那條規則所在的源檔；跨功能的駁回追加進 `docs/重構/02-待用構想.md` 的已駁回清單。
- 把 `結構定義/共同約定.md` 中與本功能相關、且已被新原則取代的段落改成一致（其他功能的段落**不要動**，它們還沒遷移）。
- 現有的書（`一世之尊/`、`gothic_witch/` 等）要不要跟著遷移，在報告裡確認過再動；`一世之尊` 是刻意保留的病例書，預設**不遷移**。

完成後：
- 跑相關的工具與測試，把實際輸出貼出來（不要只說「應該會過」）
- 更新 `01-功能盤點與測試順序.md` 進度表為「已重構」
- 在報告末尾追加「重構實況」節：實際做了什麼、與提案有何出入、還留下什麼

限制：
- 只動功能 <NN> 的範圍。撞到別的功能就記進該功能的「已知疑點」，不順手改。
- 報告裡沒拍板的抉擇不要自己決定，停下來問。
```

---

## 兩輪之間你要做的事

診斷輪結束後，打開報告的「**待作者拍板**」節，把決定直接寫在每一項下面（一句話就夠）。重構輪的 session 會讀它。

不必回到原本的對話——**報告就是跨 session 的交接物**。

---

## 收尾（15 個功能全部跑完後）

```
novelAI 重構盤點的 15 個功能已全部重構完成。做收尾：

1. 讀所有 `docs/重構/功能報告/*.md`，彙總「原則的問題」節——依 `結構定義/設計原則.md` 末節，反覆需要例外的原則要改寫而不是加註解。
2. 依原則 E1 做一次全系統盤點：每一條 schema 宣稱的格式，對上「誰守、何時跑」，列出仍然無人守的。
3. 重寫 `結構定義/共同約定.md` 第零節（三類檔的分類公理）與第八節（context 取用契約），使其與 `設計原則.md` 完全一致——遷移完成後兩者不該再有「現行 vs 目標」的分裂。
4. 更新 `CLAUDE.md` 與 `README.md`。
5. 移除 `設計原則.md` 檔頭「現行系統多處違反本檔」那段過渡說明。
```
