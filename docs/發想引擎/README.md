## 一頁結論

### 一、對「生成型方法」的偏漏出現在三個層級，而且是同一個形狀

| 層級 | 實測 |
|---|---|
| `Data/` → `技巧知識庫/` 的**提煉** | **7 個零提煉 ＋ 5 個半提煉**，全部不在 `_index.md` 那張「刻意不提煉」表裡。7 個零提煉裡有 **5 個**是「給定 A 產出 B」的程序 |
| `技巧知識庫/` → skill 的**引用** | 資訊差引擎被 `write` 列在依據清單當「渲染時參考」；主題只有「防漂移」的否定判準，沒有「該放進哪裡」的生成清單 |
| skill → **產出** | 正文五鐵律 4/5 條是「不得…」；93 章實測每章 2900→1050 字、對白 30→7.5、武打→0，連續 11 章零告警 |

系統自己的診斷（`情境測試/一世之尊/診斷01` §四）把這個形狀講得比誰都準：

> **「系統對『做錯』有密集的懲罰機制，對『什麼都不做』沒有任何懲罰機制。在一個只有負向約束的系統裡，最安全的產出就是最空的產出。」**

它當時是對正文層說的。實測顯示同一個形狀在**上面兩層**也成立。

### 二、「從有到有」——發想引擎的設計論證，出自作者自己的素材

`Data/【靈感】.txt` L430–439：

> 「如果我現在說：『請你想兩個概念組合。』……你是不是連想出『一個』概念都要想很久。因為這是很虛無的，一個『無中生有』的過程……但如果是從自己已有的紀錄中抓兩個組合（或抓一個改造），思考起來就有脈絡可循了，這是一個『**從有到有**』的過程。」

**每一招引擎都是「對已存在的材料做一個具名的變換」。** 這同時解釋了兩件事：引擎為什麼便宜（變換的輸入是少數幾個具名項目），以及現行系統為什麼慢（它要求 LLM 在 497 KB 約束下「無中生有」地寫出正文）。

### 三、skill 慢／產出少，有四個可量的機制

1. **SKILL.md 是 prompt，不是執行引擎。** 12 個步驟不是依序完成再釋放，是同時壓在注意力上的 12 段約束。
2. **零漸進揭露。** 12 支 skill **全部是單一 SKILL.md，沒有任何一支用 `references/` 子檔**——即使 `技巧知識庫/_index.md` 自己引用了「reference 檔在被讀取前不佔 context」這條準則。
3. **housekeeping 是「寫檔」的成本，不是「創作」的成本。** 三支唯讀的 test skill 平均 housekeeping **8.3%**；五支會寫檔的平均 **38.0%**——差 4.6 倍。
4. **往返次數 × 全額 context。** S6 實測：`write` 一支跨 5 輪、八輪對話問 **40+ 題**、產出 **3,700 字**正文；同一 session `裁決流.md` ＋7 列（≈7,600 字）——**治理文字的產出是正文的兩倍**。

外加一個結構性阻斷：**12 支裡除 `develop` 外，每一支都有硬前置閘門。** 作者舉的例子「已經有一段劇情、角色還不確定」會被 `character` 的前置檢查擋下，退回 `develop`。**發想被關在編譯結果的下游。**

### 四、兩檔制不是全冗餘，冗餘的是「設定層衍生檔的散文半身」

**真的付了錢**：`chNNNN.ai.md` 的 front-matter（壓縮比 0.037，六欄逐欄被消費）／`消失的密室/風格.ai.md`（8,703 B 散文源 → **1,166 B 全 front-matter**，五欄逐欄被 `style_lint` 取值，**全 repo 唯一 100% 兌現設計原意的一對**）／角色與世界觀的 LLM 分析（`榮恩.ai.md` 86% 是不可機械導出的判斷）。

**是冗餘的**：設定層 `.ai.md` 的散文節（源檔已寫過，**而且沒有任何程式切得動它**）／零消費者宣告欄（一世之尊仍帶 97 個實例）／**枚舉外節 52.0%（162 KB）**——不可重生的內容住在會被重生的容器裡／**hash/stamp/stale：148 支 `.ai.md`，`derived-sync check` 報 0 支 stale，機制一次都沒派上用場**。

最深的一句：**52% 是不該被重生的內容 → 沒有人敢重生 → stale 偵測失去意義。**

還有一個字要改：`.ai.md` 的合約寫「不得含新資訊」，但 schema 明訂四節必填的分析節在定義上就是新的判斷。正確讀法是「不得含新**設定**」而非「不得含新**分析**」。**作者感覺到的矛盾是真的。**

## 閱讀順序

1. **`01-引擎目錄.md`** — 主體。約 32 招，每招七欄（什麼時候用／輸入／步驟／輸出／依據／載入／不做）。標 ★ 的是 `Data/` 有、`技巧知識庫/` 沒提煉或只留指針的。每組結尾標「現行系統有沒有入口」。
2. **`02-走一遍.md`** — 一個原創前提，從兩條刻意平庸的碎片開始，12 招依序跑一遍。**前提本身也是引擎生出來的**，不是先想好再倒推。每一步標「新增了什麼」，讓你自己判斷引擎有沒有在做事。
3. **`03-現行系統診斷.md`** — 第 2、3 個問題的完整分析，含 12 支 skill 的橫向對照表與重複載入量化。第四節列**現行系統裡可以直接照抄的三個好設計**。

想快速判斷這個方向值不值得走，只讀 `02-走一遍.md`——**驗收標準不是機械的，是你的：看完那幾個候選，你能不能當場挑一個。**
