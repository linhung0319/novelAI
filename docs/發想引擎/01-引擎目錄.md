# 發想引擎目錄（32 招）

> **一招 ＝ 一個具名的「給定 A，產出 B」變換。** 它不是流程、不是 skill、不推進任何層級——它只做一件事：把已經存在的材料，變成還不存在的材料。
> **設計論證見 `Data/【靈感】.txt` L430–439 的「從有到有」**（README 二）。這是全部 32 招的共同形狀，也是它們便宜的原因。

## 每一招的七欄

| 欄 | 意思 |
|---|---|
| **什麼時候用** | 用作者會講的話寫，不用系統術語 |
| **輸入** | 必須已存在的東西。**少、具名、可指認**——這一欄長了，那一招就會變回 skill |
| **步驟** | 3–5 步，每步對應知識庫或 `Data/` 的一個既有方法 |
| **輸出** | **2–3 個候選 ＋ 每個候選的代價**。不是一個答案 |
| **依據** | **逐節指名**（`需求四象限.md §一§二`），不得寫「參考某檔」。寫鬆了就會退回「請只讀相關部分」那種不會被執行的規勸 |
| **載入** | 目標位元組（技法節 ＋ 故事側具名項目） |
| **不做** | 不寫檔、不拍承重抉擇、不順手推進下一層 |

## 三條共同紀律

1. **一律出 2–3 個候選並列，各帶代價**，不替作者選。這是現行系統做對的地方，照抄。
2. **只提案不寫檔。** 落檔是拍板後另一個很薄的動作（見末節）。實測理由：唯讀的三支 test skill housekeeping 平均 8.3%，會寫檔的五支平均 38.0%——**不寫檔，等於免費砍掉四成成本**。
3. **招與招可自由串接、不預設順序、不預設層。** A 組的輸出直接是 B 組的輸入。

## 標記

- ★ ＝ `Data/` 裡有完整方法，但 `技巧知識庫/` **零提煉或只留指針**。每一招附出處行號，可用 `sed -n '<起>,<迄>p' Data/<檔>` 核對。
- 每組結尾一段「**現行系統有沒有入口**」：現行 12 支 skill 誰做得到、在第幾步、被什麼閘門擋住。

# H 組 · 收斂（還沒有故事 → 有一個故事）

## H1　重鑄靈感三密技　★ 零提煉
**什麼時候用**：raw 裡有一堆靈感，每一條看起來都不夠好，不知道要寫什麼。
**輸入**：`raw/` 裡任意兩條靈感（或一條）。**不要求它們相關，越不相關越好。**
**步驟**（三招擇一或連用，每招自帶提問模板）：
1. **無關組合**——「把『○○○』跟『ＸＸＸ』結合，故事會變成怎樣呢？怎樣瞎掰可以讓它們合理呢？」
   > 「兩個越不可能在一起的東西合在一起，才會越有趣……兩個『單獨成文會稍嫌薄弱』的『老哏概念』相加就會讓結局的驚喜度發揮『一加一大於二』的效果。」
2. **版本改造**——「把『○○○』改成『ＸＸ版』會變成怎樣呢？」（《賭神》→ 搞笑版《賭聖》；《小紅帽》→ 驚悚版《血紅帽》）
3. **相異錯配**（五個子型，各一條模板）：
   - 錯配的內在：「如果『○○○』**不做他的本分**，他會怎樣？」進階：「如果『○○○』執行本分**必會發生慘事**，他會怎樣？」
   - 錯配的環境：「把『○○○』**放在哪裡**最奇怪？」
   - 錯配的行動：「把『○○○』**用來做什麼**最奇怪？」
   - 錯配的同類：「把『○○○』**集中起來**會發生什麼事？」
   - 錯配的異類：「讓『○○○』跟**相反的**『ＸＸＸ』相處會發生什麼事？」
4. **強制接合理化**：「『情』就是人性，『理』則是邏輯……去尋找理由，讓創意符合人性與邏輯。」不做這一步就只是惡搞。

**輸出**：2–3 個新概念，各附「它的衝突內核是什麼」與「哪裡還瞎掰不過去」。
**依據**：`Data/【靈感】.txt` L272–458〈重鑄靈感的３個密技〉。**知識庫全庫 grep `重鑄`／`無關組合`／`版本改造`／`相異錯配` 零命中。**
**載入**：≈4 KB（原文該節）＋ raw 裡挑出的那兩條。
**不做**：不判斷新概念好不好（原文明說「新成果是好還是不好，這也是很主觀的」），不開檔。

## H2　連問法
**什麼時候用**：有一個畫面或一個題材，但還不是故事。
**輸入**：一個畫面／一句「我想寫這個」。
**步驟**：為什麼會有這個 → 誰最需要它 → 會拿來幹嘛 → 造成什麼麻煩 → 麻煩會被誰利用 → 就每個答案再深挖一層。
**輸出**：一個有輪廓的故事構想 ＋ 尚未回答的那幾個問題。
**依據**：`選題與收斂.md` §二。
**載入**：≈1.5 KB。

## H3　壓縮測試
**什麼時候用**：覺得想清楚了，想確認。
**步驟**：寫不出三五句有焦點的摘要 ＝ 還沒收斂。
**依據**：`選題與收斂.md` §四。
**載入**：≈1 KB。這是全目錄最便宜的一招，而且它的輸出是「回去做 H1／H2」。

> **現行系統有沒有入口**：`develop` 有 H2、H3（步驟 5），**沒有 H1**。而 `develop` 是 23,701 B、10 步、doc 側 431,493 B、強制跑 9 支工具、**停下問作者 8–10 次且分散在流程各處**的冷啟動流程。H1 這種「兩條靈感硬配一下看看」的動作，現行沒有任何檔位承接得起——輕量模式要求「不產生新結構承諾」，而 H1 的產物正好是結構承諾的種子。

# A 組 · 劇情 → 角色（有戲、缺人）

## A1　阻礙轉恐懼　★ 作者原始構想的直譯
**什麼時候用**：已經確定要寫某段劇情，但不知道該讓誰去完成、他為什麼難以完成。
**輸入**：那段劇情 ＋ 一句「主角在這裡必須克服什麼」。
**步驟**：
1. 把阻礙定成一個**恐懼**（FLBW 的 F）；
2. 由恐懼反推 **Wound 傷痕**——什麼舊傷造成這個恐懼。FLBW 明文：「決定了不足，也幾乎決定了故事主線」；
3. 由傷痕反推 **Lie／Ghost**（他因此相信什麼假話）→ 導出**想要**（假目標）與**需要**（真圓滿）；
4. 判「克服那一刻」落在四個過渡心境（盲目／挫折／醒悟／滿足）的哪一段 → 得到**弧線型**；
5. **討喜檢查**：定出憧憬×代入兩個旋鈕的位置，挑 2–3 個同情鉤子。「這個角色要能讓讀者喜歡」在這一步才有機械判準。
**輸出**：2–3 個角色骨架（`恐懼｜傷痕｜謊言｜想要｜需要｜弧線型｜兩個旋鈕｜鉤子`），各附「選這個版本，你那段劇情會變成什麼樣」。
**依據**：`角色塑造.md` §六／`需求四象限.md` §一 §二 §七（弧線引擎 Lie/Ghost）§八（核心謊言點子庫，僅供發想不填表）／`角色魅力與登場.md` §二 §三。
**載入**：≈14 KB（5 節）＋那段劇情 ＋既有角色名單（避重）。
**不做**：不建角色檔、不取名、不進幕綱。

## A2　缺一個反對的人
**什麼時候用**：某一幕衝突很弱，只剩主角在想事情。
**輸入**：那一幕的主角**具體目標**。
**步驟**：
1. **對手 ＝ 爭同一個目標的人**，不是阻止者；「主角的對手是他自己」是結構性錯誤；
2. **先盤既有角色**——誰能升任、要補他什麼；
3. 補不上才開新角色，用**四角對立**定位（同一個弱點、不同攻法）；
4. **六參數表**與既有角色互比防撞人設（含最常被跳過的「對手之間互比」）。
**輸出**：候選 A「由既有角色 X 擔任，需補 ⟨…⟩」／候選 B「新角色，六參數這樣填」，各附代價。
**依據**：`角色關係網與群像.md` §一 §二 §三。
**載入**：≈6 KB ＋角色名單。
**為什麼這一招特別值**：它**優先重用既有角色**。一世之尊實測 24 支角色衍生檔有 **12 支必填節是佔位**（47 個 slot、11 節整節空）、2 支從未被任何幕的角色欄選中。現行系統的傾向是愈開愈多，這一招反向。

## A3　主線⇄目標互推　★ 零提煉
**什麼時候用**：想不到主角的目標；或有目標但不知道主線是什麼；或不知道反派要幹嘛。
**輸入**：一段主劇情，或一個主角目標。
**步驟**：
1. **有主劇情 → 目標顯而易見**：
   > 「主要上演的劇情就該是主角的目標。」「**故事主線 ＝ 主角目標**」
   （臥底吸血鬼黑幫 → 目標是對黑幫不利；毀滅戒指 → 目標就是毀滅戒指）
2. **有目標、沒主線 → 反過來**：「為了讓主角達成目標而推展的劇情」就是主線；
3. **主角真的沒有目標的特判**：「主角不推動，就交給配角推動」——配一個動力爆表的配角，再用綑綁把主角綁進去（輕小說慣用型）；
4. **反派目標反推**：「反派的目標就是阻礙主角的目標」——由主角目標與主線，反推反派目標與反派主線。
**輸出**：主角目標／主線／反派目標三者互相補齊，缺哪一格就補哪一格。
**依據**：`Data/【人物】.txt` L3455–3560〈【網友提問】我想不到角色在故事中的目標？〉。**知識庫收的是 Truby 版對手論（爭同一目標），沒有這套洛克版的三向互推與無目標主角特判。**
**載入**：≈3 KB。
**它與 A2 的分工**：A2 回答「對手是誰」，A3 回答「主角要什麼、反派要什麼」。兩者都從「爭同一個目標」出發，但 A3 可以在只有一段劇情時就跑。

## A4　這條規則該有誰
**輸入**：一條核心設定規則 ＋ 它的代價。
**步驟**：誰因它得利／誰付代價／誰在鑽漏洞 → 三個角色位置 → 用**綑綁抗衡**把他們綁成無法抽身、且至少三個支點鼎足。
**輸出**：3 個角色位置候選 ＋ 各自與主線的接點。
**依據**：`世界觀與背景.md` §六／`角色關係網與群像.md` §一。
**載入**：≈4 KB。

> **現行系統有沒有入口**：A1 有——`character` Phase 1 步驟 4（提 1–N 個角色草稿）與 `expand` 的「提案生成規則」第一條字面就寫著「缺衝突 → 推演出需要新增某性格角色」。**但兩者都被前置閘門擋在編譯結果下游**：`character/SKILL.md:47`「若連 `00-摘要.md` 主線／題旨或 `story/設定/世界觀/` 都不存在 → 判定粗階段未就緒，**停下**建議先跑 `develop`」。**作者的原始情境（有一段劇情、角色還不確定）在多數時候會被這一條擋下。** A2 部分有（`expand` 缺口偵測第 4 項）。**A3 完全沒有入口。** A4 沒有。
> 另：`character` 自稱「輕量一級操作、不套用大 skill 的全套儀式」，實測 **housekeeping 50.4%**、Phase 2 落檔 8,131 B 是 Phase 1 提案 3,723 B 的 **2.18 倍**。

# B 組 · 角色 → 劇情（有人、缺戲）

## B1　特質要有展場　★ 作者原始構想的另一半
**什麼時候用**：定了某個角色特質、關係或記憶點通道，但故事裡沒有一場戲在演它。（衛斯理雙胞胎需要一段惡作劇；哈利榮恩妙麗的友情需要巨怪那一場。）
**輸入**：一個特質／一段關係／一個記憶點通道。
**步驟**：
1. 問一個很窄的問題：「**什麼事件，只有這個特質在場才會發生、或才會這樣收場？**」——**不是**「哪裡可以順便展現它」；
2. 填**幕的五要素**（角色／時空／行動／衝突／結果）；
3. **結果四選一**（成功／失敗／有成有敗／暫時保留），且必須是「足以催發下一個事件的結果」；
4. 掛到主線的哪一條因果鏈上——掛不上就是**孤兒事件**。
**輸出**：2–3 個候選幕（五要素填好），各附「它兌現了什麼、代價是拖慢什麼」。
**依據**：`因果法則.md` §二 §三 §五 §六／`場景與情節推進.md` §二。
**載入**：≈7 KB。

## B2　弧線缺一節
**輸入**：某角色的四象限四欄 ＋ 已排的幕。
**步驟**：四個過渡心境（盲目→挫折→醒悟→滿足）逐一問「哪一幕在演這一段」→ 空的那一格就是要生的幕 → 該段配一個**兩難**（想要與需要都正確，逼他棄想要選需要）。
**輸出**：缺哪一段 ＋ 2–3 個兩難候選。
**依據**：`需求四象限.md` §一 §二。
**載入**：≈4 KB。
**與現行的差別**：檢查版已經存在（`beat-test` 的角色需求弧線測試）。**檢查版說「缺」，發想版說「補什麼」**——`診斷01` 記過同型教訓：只罰不給替代品，實測會換一種寫法繼續犯（禁掉解說段之後，補上「離題型」才真的有效）。

## B3　關係網缺一條線
**輸入**：角色群 ＋ 主角目標。
**步驟**：**Mirror**（共享同一傷口、加劇內在衝突）vs **Foil**（另一套內在邏輯、複雜化外部選擇）盤點 → 誰跟誰之間完全沒有戲 → 用戲份格／錯開情緒里程碑／中央樞紐／輪換配對四法排 → 守**活躍角色 3–5 人硬上限**（7±2 工作記憶）。
**依據**：`角色關係網與群像.md` §四 §五。
**載入**：≈4 KB。

## B4　阻礙不夠力就回頭改目標　★ 半提煉
**什麼時候用**：這一段的阻礙看起來很大，但讀起來不緊張。
**步驟**：
1. `衝突 ＝ 動力（目標）＋ 阻礙`，阻礙壓過動力 ＝ 挫折；
2. **雙向釘死**：「一邊是一定要達成目標、另一邊是一定不讓他達成目標」（《大白鯊》市長不准封海灘）；
3. 強度依**角色內心的天平**，不依客觀後果；
4. **反向生成（這一招的核心）**：「當你覺得阻礙不夠力時，有時可能是**目標**沒設定好」——回頭烘托目標即可強化阻礙。（養兩年的倉鼠死了 → 先寫倉鼠對這個角色獨一無二的意義。）
**輸出**：兩個候選——加強阻礙／回頭烘托目標，各附代價。
**依據**：`Data/【寫作技巧懶人包】.txt` (7) L863–1056。知識庫收了「阻礙的強度」的描述面（`結構公式.md` §一），**沒有把第 4 步落成判準**。
**載入**：≈3 KB。

> **現行系統有沒有入口**：B1 部分有（`expand` 缺口偵測第 3 項「場景完整」判有無 Goal/Conflict/Disaster，但那是**檢查**這一幕完不完整，不是**生成**一場只有這個特質才會發生的戲）。B2 只有檢查版（`beat-test`）。B3 沒有。B4 沒有。
> `expand` 的診斷驅動與 B 組的素材驅動是兩種問法：**`expand` 問「這裡缺什麼」，B 組問「我有 X，X 能給我什麼」。** 前者要先有一個成形的 arc 才問得出來，後者只要有一個角色特質就能跑。

# C 組 · 題旨 → 劇情

## C1　主題三角演繹
**什麼時候用**：題旨定了，但不知道要寫哪些戲來論證它。
**輸入**：一句「因為 X，導致 Y」。
**步驟**：對核心主題造出**對立／矛盾／極端**三種情境；主角歷經前三種而犯錯、最後選核心主題（或多角各代表一種情境）。進階用**觀念四角**：A 原始 → B 目標 → C 走過頭 → D 平衡；先拉主變化線定兩端，再推 C、再取 D，最後問「D 與 B 差什麼」「各立場由什麼事件／角色觸發」。
**輸出**：**3–4 幕的骨架，直接可排**。
**依據**：`主題題旨.md` §四 §五。
**載入**：≈4 KB。
**為什麼低估**：現行系統裡題旨只是一個要被守住的宣告欄（`summary-lint` 驗它的句型），**從沒被當成產生器用過**。而它是全庫少數幾個能一次吐出多幕的方法。

## C2　傳達主題的五種載體　★ 零提煉
**什麼時候用**：題旨拍板了，接下來不知道它該怎麼進到故事裡。
**輸入**：一句已定的題旨。
**步驟**：從五種載體挑（**可並存，且不同載體可承載不同層次的主題**）：
1. **結局傳達**——主角目標成功與否直接是主題的定論（美人魚化泡沫 ＝ 追逐艱難的愛情招致滅亡；反之則是真愛克服一切）；
2. **對白傳達**——關鍵那句話放在最高潮的時機說出來；
3. **人物傳達**——特定人物的性格與行為承載一個主題（關羽 ＝ 忠義勝過生命利益；曹操承載另一個）；
4. **情節傳達**——結局曖昧時，主題藏在高潮段落的**抉擇**裡（《全面啟動》不知成功與否，但觀眾看見主角選擇回現實）；
5. **意象傳達**——不解釋，只呈現物／景／事，留曖昧空間（《梁祝》雙飛蝶）。
   進階：**讓大小主題並存**（大方向「邪不勝正」＋小主題「壞人都是有苦衷的」＋「正義者與犯罪者只有一線之隔」），甚至讓兩個極端主題並存。
   配額：「**用九分的情節去烘托一分的主題**。」
**輸出**：題旨的 N 個具體落點——**哪一幕、誰、哪句話、哪個物件**。
**依據**：`Data/【主題】.txt` L386–476〈傳達故事主題的５種方式〉。**知識庫 grep `傳達主題`／`意象傳達`／`對白傳達`／`人物傳達`／`情節傳達` 全庫零命中。**（`結局類型.md` §四的象徵四類與圓滿呼應覆蓋了第 5 項的一部分，但那是**餘韻**的角度，不是**題旨投放**的角度。）
**載入**：≈3 KB。
**這一招補的是什麼洞**：現行系統對題旨只有 `主題題旨.md` §三「防漂移／立場詭變」這種**否定式**判準——「別漂移」，但從來沒有「該把它放進哪裡」。這正是 `診斷01`「只罰不給替代品」的形狀，發生在主題軸。

## C3　先寫一個與你觀念相反的角色　★ 半提煉
**什麼時候用**：題旨已定，但寫出來像在說教。
**步驟**：
1. 先寫一個「**跟你的觀念完全相反**」的角色；
2. 用他的看法來講故事，**先讓他贏得讀者的認同**；
3. 讓他經歷一些事件，那些事件改變他的看法（改成你真正想講的那個觀念）；
4. 「當角色的想法變了，這會自然投射在讀者身上」；
5. **失敗判準**：若最終觀念違反人類原始觀念，讀者不會被說服。
**輸出**：一個「載體角色」＋他的觀念翻轉節點。
**依據**：`Data/【主題】.txt` L238–250。知識庫 `主題題旨.md` §四只收了「正言若反」的**情境版**（先製造與主題相反的情境），**沒有這個角色版**。
**載入**：≈2 KB。

## C4　結局 ⇄ 題旨互推
**步驟**：「主題 ＝ 主要衝突 ＋ 最後結果」——同一條主線換結局就換題旨。所以可以從六大結局類型（喜／悲／悲喜／暗示／開放／諷刺）反推題旨，或反向。收尾側再對照**好結局六要素**（驚奇／揭露人物／情感／象徵／**圓滿呼應**／**觀念改變**）預留呼應點。
**依據**：`結局類型.md` §一 §二／`主題題旨.md` §二。
**載入**：≈4 KB。

> **現行系統有沒有入口**：C1 有（`develop` 的承重分叉會問題旨，`organize` 會用）。**C2 完全沒有**——這是本目錄裡我認為最值得優先補的一招，因為題旨在現行系統是「已拍板但無處落地」的典型：拍板結果寫進 `00-摘要.ai.md` 的 `題旨` 欄，然後下游只被要求「別違反它」。C3 沒有。C4 有（`develop` 攤承重分叉時）。

# D 組 · 結局 → 伏筆（往回長）

## D1　由果推因
**輸入**：已定的結局或真相。
**步驟**：① 回推達成它所需的條件 → ② 每個條件設計一處**自然預示** → ③ 配置距離要夠遠、回收要帶感情、埋設不著痕跡。
> 「你不知道炸彈的爆發情形，你就難以埋下炸彈。」
**輸出**：`埋[[伏筆:x]]` 的候選落點清單（哪一幕、該處寫成什麼）。
**依據**：`伏筆與意外.md` §一 §五。
**載入**：≈4 KB。

## D2　謎三角逆推
**什麼時候用**：要藏一個真相，而且想騙讀者兩次。
**步驟**：**真真相 → 反向佈置假真相 → 再反向佈置誤導真相**；配三種紅鯡魚（結局／角色／劇情誤導）。「要寫好人先把他寫壞。」
**輸出**：雙重誤導的揭露序列。
**依據**：`伏筆與意外.md` §三。
**載入**：≈3 KB。
**現行的缺口**：系統對伏筆只有「有沒有回收」的配對檢查（`foreshadow-project`）。**設計誤導層次的那一半沒有任何入口**——而本格推理題材，那一半就是本體。

## D3　隔幕交會＝伏筆的自然生成法　★ 零提煉
**什麼時候用**：想埋伏筆，但不想「為了埋而埋」。
**輸入**：一條主事件 ＋ 一條副事件。
**步驟**：
1. 每個事件拆成**前因／中間／後果**三足；
2. 讓副事件的某一足**先驚鴻一瞥**（讀者當下會覺得那是贅戲）；
3. 讓它**消失數幕**；
4. 相隔多幕之後再登場，**回頭串起因果**。
> 「前面女賊驚鴻一撇，之後消失看似沒頭沒尾的贅戲，卻在相隔多幕之後，再次登場，串起因果，**這樣遠距離的銜接，也是我們俗稱的『伏筆』**。」
**輸出**：2–3 組「先露哪一足、隔幾幕、在哪裡補完」。
**依據**：`Data/【編劇結構】.txt` L318–530〈檢查故事好幫手！事件因果的３足鼎立〉。**知識庫 `因果法則.md` 收的是幕與幕之間的「前果＝後因」與孤兒事件檢查，事件內部的三足模型與交會編織法零提煉；grep `三足`／`前中後` 全庫零命中。**
**載入**：≈4 KB。
**這一招為什麼特別**：伏筆在這裡**不是一個決定，是一個幾何後果**。你不用問「我該埋什麼伏筆」，你只要把副線的三足錯開，伏筆自己就長出來了。

> **現行系統有沒有入口**：D1 有（`expand` 的「伏筆機會」附項、`beat-sheet` 步驟 3）。D2 沒有——`beat-test` 的伏筆測試只驗閉合。**D3 沒有。**

## E4　自訂規則（越早訂，越少質疑）　★ 未登記的對衝軸
**什麼時候用**：核心設定就是誇張、不科學，而你**不打算解釋**。
**步驟**：
1. 判斷「這條規則要不要解釋」→ 決定不解釋；
2. **把宣告時點盡量前移**：
   > 「你越早訂出規則，就越少讀者質疑。**最好是一開場就訂下你的規則。**」
   （《變形記》第一句就訂完規則，全書從不解釋為什麼會變成蟲。）
3. 用情感強度轉移注意力——「我們要用情感讓讀者忘記科學，別擔心圓謊了，別為了圓謊將故事搞砸」；
4. **反向診斷**：從開始到中間都西裝筆挺、中間突然改穿皮衣，所有讀者都會問為什麼；從一開場就穿到結尾，雖然怪，但大家都會乖乖接受。
**輸出**：這條設定該在第幾幕（最好是第幾句）宣告，以及要不要進 E1。
**依據**：`Data/【戲劇手法】.txt` L857–891。**知識庫零命中（grep `自訂規則`／`規則自己定`）。**
**與 E1 的關係**：**這兩招是一組 OR 抉擇，不是矛盾。** E1（Sanderson）管的是「這個能力可不可以拿來解衝突」，E4 管的是「這個前提要不要被接受」。現行知識庫只有 E1 那一側——作者若說「我這條設定就是不打算解釋」，`worldbuild` 無處可查，只會報「缺代價」。**建議至少登記成 `_index.md` 決策點對照表的一列。**
**載入**：≈2 KB。

> **現行系統有沒有入口**：E1、E2、E3 有（`worldbuild` 的缺口偵測引擎）。但 `worldbuild` 是全系統**技法載入最輕、schema 載入最重**的一支——技法 3 支 32,819 B vs schema 7 支 144,832 B，**比例 1:4.4，全系統唯一倒掛**。它花在「格式怎麼寫」的注意力是「怎麼想設定」的四倍多。**E4 沒有入口。**

## F4　機器神三訣竅　★ 零提煉（只收了禁令）
**什麼時候用**：你就是需要一個外力來解圍，而且知道這樣不好。

## G2　內外目標解決順序　★ 零提煉
**什麼時候用**：幕排出來了，但順序感覺不對；或不知道哪些戲可以砍。
**輸入**：主角的外在目標 ＋ 內在問題。
**步驟**：
1. 把目標拆成**一內一外**：外在麻煩（主線）＋內在問題（主題）；
2. 套順序公式：
   > **「外在目標與阻礙 → 內在目標與阻礙 → 衝突 → 內在阻礙消滅 → 外在阻礙消滅」**
   > 「『外在』引發『內在』，**解決『內在』後，才能解決『外在』**。」
3. 「請讓你的外在事件圍繞著內在阻礙安排」；
4. **導出刪戲判準**：
   > 「跟解決主角內在問題無關的事件，**都是可以被省略的**。」
**輸出**：一條幕序骨架 ＋ 一份可刪事件清單。
**依據**：`Data/【編劇結構】.txt` L144–317〈簡單的好故事，編劇檢查的４重點〉。**知識庫有 Want/Need 的定義（`需求四象限.md`），沒有這條幕序生成規則，也沒有由它導出的刪戲判準。**
**載入**：≈3 KB。
**它同時是一把刀**：現行系統沒有任何一支工具或 skill 會說「這一段可以刪」。12 支閘門全都在說「你少寫了什麼」。

## G3　N 型結構　★ 壓成一行附註
**什麼時候用**：只有一個模糊構想，不想學九段十五段那麼多段。
**步驟**：
1. 把三幕劇／起承轉合**改用主角心境**理解：V 型（輕鬆→低落煎熬→放鬆）／N 型（低迷→高昂→低潮→愉悅）；
2. **從低迷開場**——「故事一開始就點出主角的困境與問題，是讓故事主線快速聚焦的好方法」；
3. 非要春風得意開場，也要盡快跌入低潮。
**輸出**：一條情緒曲線 ＋ 開場切入點。
**依據**：`Data/【編劇結構】.txt` L1098–1197。知識庫 `結構公式.md` §二只有一句情緒曲線的附註掛在起承轉合底下，**原文的主張（它是一套獨立、最輕量的排幕工具）沒有進去，也沒有 registry 一行，`structure-project` 投影不到。**
**載入**：≈2 KB。**它是門檻最低的一套公式**，適合 `organize` 面對「作者只有一個模糊構想」的時候。

## G4　15 段的字數換算表　★ 只留指針
**什麼時候用**：幕排好了，但不知道每一幕該落在全書的哪個位置、該寫多長。
**輸入**：預計總字數 ＋ 已排的幕。
**步驟**：對照 15 段（開場／主題宣告／佈局／導火線／覺悟改變／歷險啟程／多線任務／遊戲時間／轉折點／敵人逼近／萬念俱灰／覺醒／重振旗鼓／結局／最後收尾）**各自的字數錨點**（以 7 萬字為例：主題宣告 3000 字內、導火線 7500 字左右、轉折點 3.5 萬字左右、萬念俱灰 4.8 萬字左右），按比例換算到你的總字數。
**輸出**：一張帶字數錨點的幕位分配表。
**依據**：`Data/【編劇結構】.txt` L2898–3010。`結構公式.md` §五**只留指針**。
**為什麼該收進來**：**字數換算是這套公式唯一不能從 Save the Cat! 原表推得的部分**（是原文自己換算的），而它正好是 `beat-sheet` 排幕最缺的量尺——`write` 現在靠「一章約 3000 字」這個單章基準，沒有全書位置的尺。
**載入**：≈2 KB。

## G5　縱橫交會生副線　★ 零提煉（與 D3 同源）
**輸入**：一條主事件（拆好三足）。
**步驟**：
1. **縱向串接**：讓一隻腳兼兩用——「上一個事件的**後果**，觸發下一個事件的**前因**」；
2. **橫向交會**：讓副事件與主事件的某兩足交會。三種錯位各有不同效果：
   - 中間 × 中間（小偷行竊時遇上女竊賊）
   - 前因 × 中間（小偷因老母行竊，結果家中先闖入了女賊）
   - 後果 × 中間（小偷得手後銷贓，結果被女賊偷走贓物）
3. **檢查副事件的頭尾有沒有交代**——「如果事後沒有向讀者解釋女賊的前因與後果，女賊事件也就沒頭沒尾……成為了贅戲」。
**輸出**：2–3 條副線候選，各附「在哪一幕交會、用哪種錯位、代價是什麼」。
**依據**：`Data/【編劇結構】.txt` L318–530。
**載入**：≈4 KB。
**這是 `expand` 最缺的工具**：`expand` 的五類檢查會告訴你「這個 arc 缺衝突」，但不會告訴你**該加什麼副線、副線該在哪一幕跟主線交會**。

## G6　MICE 開線閉線
**輸入**：一個 arc。
**步驟**：這個 arc 開了哪幾條線（M 環境／I 疑問／C 人物／E 事件，各自「開於什麼、結於什麼」）→ 排**巢狀回收**（先開的線最後關）。
**依據**：`結構公式.md` §八。
**載入**：≈2 KB。

## G7　幕的五大書寫內容　★ 零提煉
**什麼時候用**：某一幕寫出來「怪怪的」，但說不出哪裡怪。
**步驟**：對照五類內容盤點缺哪一類——
1. **時空背景**（描述背景／提示轉場兩種用途）；
2. **人物與物的外貌**（只提外在重點，「有時反而比賣力寫個十幾句敘述更能留下印象」）；
3. **動作與對話**（想像自己在拍電影抓特寫，「寫得越少反而畫面感越強烈」）；
4. **意識與內心獨白**——關鍵技法：**不要用「他想／心想」開頭**，把意識敘述流暢地插入行文之間，從寫物轉意識再轉人物行為，夾敘夾思；
5. **資訊、說明、引用**（比例不能太多）。
**附帶特判**：**作者介入**（「這時候的他，還不知道江湖即將掀起腥風血雨」）——第三人稱勉強可，**第一人稱是矛盾**（除非插敘／倒敘／鏡框式）。
**輸出**：這一幕缺哪一類的補寫清單。
**依據**：`Data/【幕綱】.txt` L310–560。**知識庫 grep `五大書寫`／`作者介入` 零命中。** 第 4 項與 `敘事距離與DeepPOV.md` §一的「去過濾詞」高度相關但不等同（後者是英文 craft 路線，這是中文行文路線）。
**載入**：≈3 KB。**「作者介入 × 第一人稱」那條可以直接進 `write-test` 的 POV 檢查。**

> **現行系統有沒有入口**：G1 有工具但接在報錯端（`structure-project` 明文「不是閘門，一律 exit 0」）。G6 有（`結構公式.md` 附錄八，`beat-sheet` 引用）。**G2、G3、G4、G5、G7 全部沒有入口。** 這一組是缺口最集中的一組——現行的結構層工具（`beat-lint`／`beat-metrics`／`structure-project`）全部在量「排出來的幕對不對」，沒有一支在幫你排。

# 落檔：拍板之後的那個薄動作

32 招全部不寫檔。**這不是保守，是實測的成本結論**：三支唯讀 test skill 的 housekeeping 平均 8.3%，五支會寫檔的平均 38.0%。

作者拍板後才走一個**很薄的落檔動作**：結論一句話回寫源檔，格式由既有的 12 支 lint 守（那些 lint 本來就跑得動，該留）。

**這一格對治的是系統自己記過最貴的一課**（`CLAUDE.md` 第二問）：共創問答問出來的具體事實，如果只活在 `.ai.md`，下一次重生會安靜地吃掉它，而 `.ai.md` 沒有 diff 會被審。所以「拍板 → 回寫源檔一句話」這條路徑必須留著——它只是不該和發想擠在同一次執行裡。

**現行系統在這一格是重複的**：`develop`／`organize`／`expand`／`character`／`worldbuild`／`revise` **六支各自寫了一遍同一套 9 個落檔動作**（改源 → 重生 → stamp → 跑該軸 lint → 寫裁決流 → 清待裁決 → 更新就緒 → readiness-lint → decision-lint），每支平均 3,900 B。其中「落裁決流」那 766 B 段落在 4 支之間 **99.6–99.7% 相同**——是全系統唯一被實質複製貼上的流程步驟。**這一套該是一個動作，不是六份規格。**
