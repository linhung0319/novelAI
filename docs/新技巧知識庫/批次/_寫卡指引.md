# 寫卡指引

目標：為 `novel-desk` 寫新技巧知識庫。這個工具以人主導、AI 輔助。AI 預設自由回答，作者卡住或覺得怪時才取用招卡。完成後 `novel-desk` 是獨立 repo，招卡不能指望回頭看原文。

## 開工前先讀

- `docs/新技巧知識庫-工作底稿.md`：判斷標準和寫卡規則，以及前面的批次如何處理
- `docs/新技巧知識庫/索引-發想.md`、`索引-檢查.md`：已有的招
- `cards/` 下的範例：相異錯配、連問法、綑綁抗衡、抽掉就垮、壓縮成摘要

## 怎麼做

1. 親自讀完指定的原文，主要依據是 `Data/` 原文。舊 `技巧知識庫/` 只用來找招和看過去的取法，它有失真，不能當根據。
2. `Data/` 裡標明「僅搜尋摘要」的策展筆記可信度較低，只補原文沒有的招。
3. 依五關寫卡。一招一檔，放 `docs/新技巧知識庫/cards/<招名>.md`，繁體中文。

## 五關的重點

- **內容對不對：** 教學文作者的主張不是事實。沒有根據的刪掉，絕對的說法改成條件。
- **AI 需不需要：** 寧可少。AI 已知的定義和清單不留；留下它自己想不到的做法、問句和有代表性的例子。沒有這種內容的招就不收，不要為了收而收。
- **適不適合這個工具：** 改成 AI 陪作者做。該由作者拍板的地方，給候選並停下來。
- **有沒有重複：** 和已有的卡重複就不要另寫。值得補進現有卡的內容寫成提議，不要自己改現有的卡。
- **不用處理試用：** 第五關由主持人做。

## 一律不做

- 不寫「必須」、評分、配額、門檻、自製數字。公式比例改成大約位置，例如「約在中段」。
- 不提 `Data/`、舊檔名、舊工具、舊系統和教學文作者（如洛克）。作品名可以提。
- 不收起名、書名簡介、投稿上架、數值帳、拆書、敏感詞。
- 不收只適合人養成的習慣，如每天寫、大量閱讀、心態喊話。
- 不收描述舊系統流程的內容。
- 不動 `novel-desk`、舊系統、現有卡片、索引和工作底稿，不做 git 操作。

## 卡片格式

```markdown
# 招名

適用：作者會怎麼描述這個狀況，用他會講的話
吃：需要什麼材料
做：怎麼做。檢查類用問句
吐：輸出什麼。通常是 2–3 個候選；檢查類則是可疑處和改法
例：有代表性才放，不必每張都有
```

`限界` 只有這張卡有特殊限制時才寫。長度不設上限，招的內容留全，其他不留。

## 交付

寫 `docs/新技巧知識庫/批次/<批名>.md`：

1. **讀過：** 檔案和行號範圍。
2. **處理表：** 招、原文位置、處理（收／併入某卡／刪）、一句理由。刪掉的也要列。
3. **索引行：** 新卡片每張一行，`招名：症狀`，標明發想或檢查、領域（構想、世界觀、角色、劇情、正文）和狀況（沒東西、太套路、選不下；檢查類不用）。
4. **給現有卡的提議。**
5. **拿不準的地方。**

最後回報只要幾句：新卡幾張、刪了哪些大類、拿不準什麼。不要貼卡片內容。
