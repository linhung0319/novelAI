> **形狀對照 `docs/重構/`**：那一輪的計畫是 `01-功能盤點與測試順序.md`、逐輪產物是 `功能報告/01`–`15`。這一輪同形。

## 一、為什麼有這條線

重構的方法論是刻意的：拿 `一世之尊/` 當**病例書**，從它的失效模式反推第一性原則（`結構定義/設計原則.md` 六問＋A–G）。做法是對的，但留下三個結構性風險，而重構自己在報告裡承認了大部分：

1. **legacy 接口可能是死重量。** 為了讓病例書跑得動，`tools/` 留了成組的向後兼容分支（spine 兩落點回退 ×4 份實作、`裁決流.co.md` 舊名 ×4 處、`事實流.md`／`狀態事件流.md` 兩代命名、`結構.md`／`結構.ai.md`、`就緒儀表` 舊名、`prose_metrics._arc_of` 雙格式 fallback）。`共同約定.md:42` 自己診斷過其中一條是**「一句半真的相容承諾」**（查詢吃得動、格式守衛吃不動），而它在 `.co.md` 廢除三天後仍原樣活著。未來的新書全是新格式，這些分支就是純負債。
2. **分階段重構製造了跨階段的暫留。** 12 輪報告都有一段「為與舊版自洽而暫留」，多數標「隨 NN 一起裁」，而有幾筆的下游輪次跑完了卻沒接（`功能報告/15` 明文：`beat-lint`／`outline-lint` 對兩支 `.md` rollup **仍是照舊比對的相容模式**，於是今天還在要求作者去「修好」一支已廢除的檔）。
3. **重構的核心成果幾乎沒有真實語料驗證。** 事實層覆蓋率 **0**（93 章 0 章用 `## 本章事實`）、物件檔全 repo **0 支**、裁決軸兩支檔 **0 本書有**、`_已併入/` 程序一次都沒跑過、`風格` 多檔 rollup **0 本書用過**、**22/39 支測試檔零真實語料**（功能 10／11／12 的**全部**新產物都在那 22 支裡）。最傳神的一格在 `功能報告/11`：`_is_declarative` 的五支測試**在真實語料上跑的是 0 支檔**——「測試是綠的，射程是空的」。

### 兩個驗證目標

- **Q-M 機制覆蓋**：系統有沒有涵蓋創作真正需要的機制？例（作者原話）「一個會隨劇情變化的地點狀態」該有 `story/物件/<名>.md`、大綱該有落點。**缺口的症狀是作者的內容被塞進自由散文或自創節。**
- **Q-R 機制重複**：同一個需求有沒有被系統**存了多次而沒帶來多餘幫助**？這是重構反覆撞到的病形（`節奏檔位` 三份、`基調參照` 第四份拷貝、跨套件 42 份同形實作、五支 rollup 獨有內容 47–78%），但**重構是逐軸看的，沒有人從「作者的一個需求」這個角度橫著數過落點**。

Q-M／Q-R 要靠**實際跑一次「模擬作者用本系統寫一本書」**才找得出來（作者判斷）。那是階段 2。

**需求機制帳**（Q-M／Q-R 的量尺）。觀測者每 session 追加，三欄：

`作者說的需求｜系統把它存到哪（落點數 0／1／N）｜證據（file:line、閘門輸出、git diff）`

判定規則，**每一條都有機械症狀，不是讀感**：

- **落點 0 ＝ 機制缺口。** 症狀：閘門報 `夾帶`／自創節／`落點已廢除`；或內容被塞進自由散文；或作者答了但根本沒落檔（`SNN-*.md` 的 elicitation 紀錄有、`git diff` 沒有）。`derived-sync check` 的成長哨兵「事實行肥大／夾帶」是現成偵測器。
- **落點 N ＝ 機制重複**（作者要找的）。症狀：同一個值出現在 ≥2 個落點，**且沒有一個是投影**。逐筆做全書落點計數（`grep` ＋ `fact-refs --entity`／`decision-project --target`／各 `*-lint --emit`）。同形前例可當基準：`節奏檔位` 三份、`基調參照` 第四份、五支 rollup 獨有內容 47–78%。

## 五、為什麼分這樣的階段（context 隔離的理由）

- **階段 0／1／3 是唯讀量測與拍板，各自 context 獨立**：階段 1 要吃 coverage 輸出與 21 支指令的實跑結果，量大且與階段 2 的創作內容無關；混在一起會把 legacy 判斷污染成「這本書需不需要」。
- **階段 2 內部必須再隔離**：系統 agent 一旦看到原著或測試 meta，「系統輔助產出」與「AI 背誦原著」就分不開了，整個階段的結論作廢。這是 `端到端貫穿測試流程.md` §2 的地基決定。
- **而 2026-07-30 之後這條隔離不能只靠 prompt 規勸**：原文以前不在 repo，系統 agent 就算想讀也沒有東西可讀，防火牆的實質保護來自「檔不在」；現在 `examples/消失的密室/` 就在磁碟上，**規勸是唯一的一層**了。這正是 `CLAUDE.md` 那句「規勸不會被執行，工具會」的形狀——所以增修 2 的機械稽核在原文進 repo 之後**從加分項變成必要條件**，且必須稽核 `Grep`／`Glob` 的參數而不只是 `Read` 的路徑。
- **觀測者與系統 agent 必須分開**：受測體不能自評。觀測者寫的是測試 meta，**永不進書資料夾**（進去＝把測試提示餵給系統 agent，`端到端貫穿測試流程.md` §5 記為「HP 教訓」）。
- **階段 1 必須在階段 2 之前**：階段 2 要用 12 支閘門的輸出當 Q-M／Q-R 的偵測器。閘門裡還有指向已廢除檔的相容分支時，它報的問題數是髒的。
- **階段 1a 必須在 1b／1c 之前**：那是全流程唯一不可逆的一步。
