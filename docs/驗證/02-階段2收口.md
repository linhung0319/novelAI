### `_已併入/` 判定不可達 — 卡在分叉一的機械證據

`outline-lint` 本輪逐字印：**「8 支大綱檔（0 支全書版／8 支 scoped／`_已併入/` **0 支**）；跳過 **1** 支骨架」**；`find . -type d -name "_已併入"` ⇒ **全 repo 0 個**。

**卡點是機械的，三段連鎖：**
1. `_已併入/` 的**唯一觸發動作**是「arc 局部大綱收斂進 `01-大綱.md`」（`功能報告/09:439`）。
2. `消失的密室/story/01-大綱.md` 至今是 **1,044 B 的空骨架**——`:3` 逐字「⚠️ **尚未產出**——本檔是空骨架，只是先把位置佔好」，`:16` 的 `結局：` 是括號佔位。`outline-lint` 因此**跳過它**（覆蓋率行的「跳過 1 支骨架」）。
3. 要把它填起來就會撞上 `outline-lint` 第 6 項的**硬閘門**（`outline.py:569-578`）：`結局：` **缺格／空／帶模糊字樣**三者皆報問題。而 `結局：` 的權威在 `00-摘要.md`「結局方向」——**那一格就是分叉一**（`00-摘要.md:27`：「最後他怎麼贏——**送什麼進來已定**（刻名字的劍），**怎麼用還沒定**」），對應 `就緒.md` 就緒清單第 3 條 **`- [ ] 結局方向已拍板`**（六條裡唯一沒勾的）。

**⇒ 這一軸卡在作者的一個未拍抉擇上，不是卡在機制。** 作者 S6 末已明言可能整輪測試都壓不出實例，S7／S8／S9 三輪沒有改變這個判斷。**它本身就是要交階段 3 的一筆**：一個軸的實例可達性可以完全由書的內容狀態決定，而**驗收表上看起來它與其餘六軸同型**。
