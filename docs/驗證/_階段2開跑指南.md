# 階段 2 · 開跑指南（怎麼開 session、給什麼 prompt）

> **這是什麼**：階段 2 的**操作**面——session 怎麼切、每個 session 的 prompt 長什麼樣。
> **這裡刻意不複述方法論**：測試流程的權威是 `情境測試/端到端貫穿測試流程.md`（三／四角色、續跑協定、執行迴圈、評估模型），階段 2 的權威是 `_流程與階段順序.md` 階段 2 那節（四項增修、session 序列、需求機制帳）。**本檔只回答「我現在要開一個新 session，該打什麼字」。**
> **為什麼要有這一支**：commit `9a2e3b8` 記過一次教訓——「計畫本來住在 session 的 plan 檔裡，而下一個 session 看不到它」。開跑方式只活在對話裡是同一個形狀。

## 一、和一世之尊那輪的差別（先講，免得照舊估工）

| | `一世之尊` | **階段 2《消失的密室》** |
|---|---|---|
| 目標 | **規模／長程效應壓測**（卷一全部內文） | **Q-M 機制覆蓋／Q-R 機制重複** |
| session 數 | **S51+** | **8**（S0、P、S1–S6） |
| 範圍 | 卷一四個 arc 全部拆幕＋成文 | `beat-sheet`／`write` **只跑 arc01** |
| 導演能讀原著嗎 | 可以（當時原文不在 repo，只是記憶） | **不行**——見下面「四個踩點」 |
| 角色數 | 3（導演／系統／作者） | **4**（＋觀測者） |

**續跑機制完全沿用**：狀態靠磁碟上的檔案，不靠 agent 記憶。所以 S1 之後每個 session 的 prompt 幾乎是同一句——`session台帳.md` 的「下一步」那段替你記住做到哪。

## 三、Prompt

### S0

```
執行 docs/驗證/_流程與階段順序.md 階段 2 的前置：把基座檔 情境測試/端到端貫穿測試流程.md
做那一節列出的四項增修，並定義「觀測者 agent」與 需求機制帳.md 的格式。
先讀：docs/驗證/_流程與階段順序.md 階段 2 整節、情境測試/端到端貫穿測試流程.md、
docs/驗證/00-系統層邊界與儀器.md §一與§六-5。
這個 session 不碰任何書資料夾。改完跑 meta-lint 確認第 10 項沒有指向已廢除落點的行。
```

### P

```
執行 docs/驗證/_流程與階段順序.md 階段 2 的 P session。
開場讀：情境測試/端到端貫穿測試流程.md（§4 切分原則、§10 換書 onboarding）＋階段 2 整節。
你是導演——你自己不要讀 examples/消失的密室/，讀原著的是你冷啟的 subagent。
```

### S1 之後，每一個 session 都是這一句

```
續跑《消失的密室》端到端貫穿測試。照 情境測試/端到端貫穿測試流程.md §5 續跑協定
開場三讀，跑 session台帳.md「下一步」指定的階段。
你是導演，不讀 examples/消失的密室/。收工前跑觀測者 agent。
```

**這一句之所以夠用，是續跑協定本身的設計**：開場三讀（基座檔 → `session台帳.md` → `就緒.md`／`readiness` 投影）會把上下文重建起來，而台帳的「下一步」段落是上一個 session 的收場二寫留下的。**prompt 不必帶狀態，帶了反而會與台帳分岔。**

## 四、四個踩點

1. **導演不讀 `examples/消失的密室/`。** 這格跟一世之尊那輪不同，也是最容易忘的一格。原文以前不在 repo，「導演認得原著」只是模糊、不成句的記憶；現在它在磁碟上，隨手開一支 `.txt`，轉述裡就會出現原文的**具體字句**——而那正是基座 §9 列的「導演注入」。需要原文的角色是**神諭**與**觀測者**，兩者都有。
2. **主 session 永遠是導演，不是受測體。** 每個管線步驟都要冷啟 subagent。主 session 一旦自己動手寫書，硬防火牆就不存在了——而防火牆是這整個測試有效性的地基（基座 §2 地基決定）。
3. **絕不切斷一次 elicitation 迴圈。** 寧可少做一階段，也不要問到一半就收 session、留懸空線（基座 §5 鐵則）。
4. **`fallback-log.md` 恆空 ＝ 出事了。** 那代表 `raw/`＋情境測試腦 與原著兩條 lane 被合成了一條，而 fallback log 是 elicitation 品質的**唯一量尺**。它非空是階段 2 的出場條件之一。

## 五、每個 session 收工前

照基座 §5「收場二寫」：更新 `session台帳.md` ＋ commit 書資料夾。階段 2 另加兩行（`_流程與階段順序.md` §六 階段 2 出場條件）：

- 防火牆稽核：**「檢查了 N 次呼叫，越界 M 次」，M=0 也印**
- purity：**指得出比對過幾個 token，0 也印**

越界清單見 `00-系統層邊界與儀器.md` §六-5（`examples/`／`情境測試/`／`docs/`／`Data/`／`site/`／`devtools/` ＋標的書以外的其他 4 本書）。**稽核要看任何工具呼叫的 path／glob／pattern 參數，不只 `Read` 的路徑**——一次 repo 範圍的 `Grep` 就會把原文帶進 context，而那不長得像「讀 `examples/`」。
