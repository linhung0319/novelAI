# `Data/` 逐篇台帳（144 篇）

> **這一支在回答一個 `01-引擎目錄.md` 沒問的問題。** 那一支問的是「哪幾篇整篇沒被提煉」（找到 7 個零提煉、5 個半提煉）。這一支問的是**篇內**的：**已提煉的那些文章，提煉時是不是只取了一種用法、丟掉了另外兩種？**
>
> `技巧知識庫/_index.md` 的「刻意不提煉」表只擋得住**整篇**，擋不住這種篇內的單一用法採樣——而實掃結果顯示，篇內落差比整篇漏網**更多、也更隱形**。

## 怎麼讀這張表

- **篇界是機械的**：`grep -n "^標題: " Data/*.txt`，全庫恰好 **144** 篇。本表列數必須等於 144，這是它自己的自檢式。
- **「用法」欄**用模式簡名（`生成`／`診斷`／`選型`／`量尺`／`替代`／`配額`／`排程`／`刪減`／`提問`／`反向`／`互推`／`範例`／`供詞`／`語言`），定義見 `01-用法模式.md`。**一篇通常供得起 2–4 種**——這正是重點：提煉時往往只取了其中一種。
- **「已提煉到」**以技法檔實際內容為據（全庫 grep 關鍵詞核對），不憑印象；空白 ＝ 該篇在 `技巧知識庫/` 零命中。
- **「篇內落差」**是本表的產出欄。標 **★** 者為「該篇最值得補的那一格」。
- 任一列可回原文核對：`sed -n '<起行>,<迄行>p' "Data/<檔>"`。
