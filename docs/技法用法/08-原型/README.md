## ⚠️ 四個明說的警語

**① `rubric-T*.md` 的門檻是先驗猜測，沒有校準過。**
「≥3 處 ＝ 達成」這種數字不是從任何語料算出來的，是我坐在這裡訂的。它唯一的保證是**先寫死、不事後放寬**。若原著基線落在極端（0 或 12），該任務作廢——**不是調門檻**。

**② `checklist-T*.md` 絕不能給評分者。**
評分者一旦看過 checklist 的措辭，它對「這一稿有沒有做到」的判斷就會被措辭帶走，而 checklist 正是 Arm2／Arm3 的自變數。同理，寫作臂也不能拿到 `rubric-T*.md`（那裡有配對表與計分規則）。

| 檔 | 寫作臂 | 評分者 | 主 session |
|---|---|---|---|
| `臂規格.md` | ❌（只拿自己那一節的內容） | ❌ | ✅ |
| `checklist-T*.md` | 只有 Arm2／Arm2′／Arm3，且**只拿分派後的 12 條** | ❌ | ✅ |
| `rubric-T*.md` | ❌ | ✅ **只讀前兩節**（中性問句表＋計分規則） | ✅ |
| `產出/_解封.md` | ❌ | ❌ | ✅ |

**③ 這一輪不測門牌，也不測路由。**
`05 §9` 那個最大的攻擊點（門牌誠實度未稽核、226 行沒人檢查過）**在本輪原封不動**。本輪測的是「**假設路由挑對了，載進來之後產出有沒有變**」——所以 T1／T2 的 3 節直接沿用 `05-原型/路由挑選結果.md` 的既有挑選，不重跑路由。

**④ `真人措辭.md` 是作者的檔，而且它有一節不得外流。**
`## ⚠️ 以下不得送進路由 subagent` 底下是預期落桶表、出處與污染警示——**主 session 只抽十則的「一句話／情況」給路由 agent**，其餘留在手上，送過去等於洩題。

該檔**刻意不入 §5 的 hash 鎖**（`08-應用層驗證設計.md`）——它本來就該被作者改。**不得用 agent 改寫的 14 題補足則數**，那正是 `05 §9③` 判為致命的那件事本身。

**三條出題紀律**（也適用於下一輪加題）：

1. **按創作階段鋪、不綁書、分桶報。** 測項②本來就不讀書，綁書只引進書名與專名這個無關變數。而若只出某一階段的題（例如只用 `gothic_witch`，它 0 章／0 幕／0 大綱），**門牌表 61 節（36.1%）的正文・句子層永遠碰不到，那一桶會安靜地看起來沒問題**。現行分佈：上游 5／幕・場景 3／正文・句子 4／真陰性 1／干擾 1 ＝ 14（與 `05` 同 n）。
2. **循環論證的題不准出。** `診斷01` 的 P7／P9 已被排除——`心理描寫.md §二之二` 與 `氛圍與筆調.md §二之二` 是為了修那兩條才寫進知識庫的。**凡是「知識庫因為這個問題才長出那一節」的，一律不得當測試題。**
3. **留一則已知真陰性。** 第 13 則（合理但無聊的做法 vs 有戲的做法）是 `05 §4` 第 4 列實測過的空格，**正確答案是 0 命中**。沒有這一則，就分不出「路由很準」與「路由什麼都硬塞」。它與第 14 則干擾項的「無」理由不同，要分開報。
