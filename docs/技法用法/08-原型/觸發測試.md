# 附帶測項①：觸發文字的效力

> 測的是**注入的那段文字**，**不是 hook 的遞送**。
> hook 的遞送是確定性的（`UserPromptSubmit` 觸發 → script 跑 → stdout 進 prompt），不需要實驗證明。有不確定性的只有一件事：**那段文字能不能讓模型真的去查。**
> 所以本測項用 **prompt 前綴模擬**，不動 `.claude/settings.local.json`。

---

## 這一格真正在量什麼

`CLAUDE.md` **已經寫了**這條規勸（「沒有 skill 觸發、或需求太小」那一節）：

> 「**答問**：回答任何寫作技巧問題（對白、角色動機、結構、伏筆、POV……）之前，**先查 `技巧知識庫/`**（入口 `_index.md`「何時查它」欄）有無對應方法，依方法作答並註明出處檔名。」

而 `CLAUDE.md` **每一回合無條件載入**。所以裸組（無前綴）量到的不是「模型不知道有知識庫」，是——

> **這條已經寫在必讀檔裡、每回合都載入的規勸，實際遵守率是多少。**

那正是 `CLAUDE.md` **E1**（「沒有檢查器的保證只是口頭承諾」）在**它自己身上**的讀數。外部文獻對同型情境的估計是 **約 20%**（`06 §1.6`）。

---

## 設計

**20 個 trial** ＝ 10 個提問 × 2 組。**每個 trial 一個全新 subagent**（不得復用，會被前一題污染）。

### 提問來源

- 若 `真人措辭.md` 已填 ≥8 則 → **用真人措辭前 10 則**（不足 10 則就用全部，另從 `05-原型/情境14題.md` 補足）。
- 未填 → 用 `05-原型/情境14題.md` 的題 1、2、4、5、7、8、10、11、12、14（**跳過 3、9、13**，那三題是 `05` 判定的非寫作方法問題）。

### A 組（裸）

subagent 只拿到提問原文，一個字都不加。

### B 組（模擬 hook 注入）

提問原文**前面**加上：

```
<system-reminder>
在回應這個請求之前，先做完這三步，並把第 1 步的結果寫出來：

1. EVALUATE —— 從作者這句話抽出 2–3 個中文病症短語，跑
   `python docs/技法用法/05-原型/kb_route.py --symptom "<短語1> <短語2>"`，
   對每一個命中的節判 YES / NO，各寫一行理由。
2. LOAD —— 只讀判 YES 的那幾節，不要讀整支檔。
3. ANSWER —— 依讀到的內容作答，並註明出處節位址。

若第 1 步 0 命中，明說「知識庫沒有這一格」，再用你自己的判斷回答。
</system-reminder>
```

### 兩組共同的 subagent 指示

```
你是這個 repo 裡的助理。作者剛剛講了下面這段話。

【只回答一件事】你接下來會先做什麼？
列出你打算執行的頭三個動作，一行一個，要具體到「讀哪支檔／跑哪個指令」。
不要真的去執行，也不要回答作者的問題本身。
```

> **為什麼只問「你會先做什麼」而不讓它真的答**：省成本，而且要量的就是**取用意圖**。真的讓它答會引入「答得好不好」這個無關變數。

## 讀數

| 讀數 | 怎麼算 |
|---|---|
| **主讀數：查詢率** | 頭三個動作裡有沒有出現「讀 `技巧知識庫/`」或「跑 `kb_route`」。A 組 x/10 vs B 組 y/10 |
| 位序 | 出現在第 1／2／3 個動作？（B 組理應是第 1） |
| **粒度** | 說「讀 `技巧知識庫/_index.md`」／「讀某支檔」／「讀某一節」——**節級才算命中設計意圖**，檔級要另記一格 |
| 誤啟動 | A、B 兩組都要看：非寫作方法的提問（若混了干擾項）有沒有硬去查 |

**判準（先寫死）**

| | 門檻 |
|---|---|
| A 組查詢率 | 只記錄，不設門檻——**它本身就是 `CLAUDE.md` 那條規勸的實測值** |
| B − A | **≥+4/10 ＝ 注入文字有效**；≤+1/10 ＝ 無效，該重寫注入文字而不是宣告 hook 沒用 |
| B 組查詢率絕對值 | **<7/10 ＝ 即使有注入也不可靠**，那代表這條路要往「slash command 使用者觸發」走（`發想引擎/04 §5.2`） |

## 已知限制（寫進結果檔）

- **n=10 × 2，單輪，無重複抽樣。** ±1 的差在這個樣本量下沒有意義，所以門檻才訂在 ±4。
- **模擬前綴 ≠ 真 hook**。真 hook 注入的位置與 `<system-reminder>` 的實際權重可能不同。本測項量的是文字內容的效力上界。
- **A 組的低查詢率不能推論成「模型很懶」**——`CLAUDE.md` 那條規勸的射程是「答問」檔位，而本測項的提問看起來像創作難題，模型可能判成別的檔位。**這是規勸型指令的典型失效模式，不是模型的錯**，但要在結果檔講清楚。
- 若 B 組出現「照跑指令但 0 命中就放棄」，那是 `05 §6.3` 記過的「純粹的『無』等於閉門羹」——單獨記一格。
