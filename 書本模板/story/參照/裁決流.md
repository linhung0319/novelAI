# 裁決流

> ⚠️ **尚未產出**——本檔是空骨架，只是先把位置佔好。實際內容由各 skill 在你拍板後 append。
>
> 依 `結構定義/裁決流.schema.md`：作者拍板的承重決定——判例、護欄、降回閥、母題論證、本輪拍板記錄——的**單一落點**。append-only、**永不人工回收**：射程寫 `至arcNN` 的由程式算過期沒（`--as-of arcNN`），不必有人回頭改狀態欄。
>
> **這支檔的合約**（`共同約定.md` 零）：AI 在你拍板後寫、**你可以直接改、改動會留著**（沒有東西會重生它）、格式由 **`decision-lint`** 守。它與大綱、幕綱、`story/物件/<名>.md` 同一列：**作者利器·直改**。
> 2026-07-27 前它叫 `裁決流.co.md`——那個字位是為了「程式會解析它」而開的，現在由檢查器承擔（`設計原則.md` A4），故廢除。**既有書仍用舊名也讀得動。**
>
> **為什麼它是 append-only 而約束是表**：本檔的查詢天生是歷史查詢（「這個標的過去裁決過什麼」），而且**被駁回的提案永遠不會出現在任何產物裡**——那正是最需要留著的一種記錄，否則每隔幾輪就會有人重新提議同一件事。
>
> **這裡放「為什麼」；「是什麼」放別處**——下游必須守的結論屬 `事實軸（正文釘死的→該章 `chNNNN.ai.md` 的「## 本章事實」；不得寫成 X 的→`story/物件/<名>.md` 的「## 不得寫成什麼」）或對應設定源檔。理由欄可以寫長，它不會擠進 `write` 的 context。
>
> **查詢**：`uv run --project <套件根>/tools/decision_projection decision-project --book <你的書> [--target 設定/角色/<名>/] [--active-only] [--as-of arcNN]`
>
> **標的**比對是**路徑分段**的雙向前綴——單檔升級成目錄形態後，新舊兩種寫法互相命中，舊裁決不會失聯。
>
> 消化 `story/參照/待裁決.md` 的回饋列之前先查一次，避免重新爭論已定案的事——**同一個查詢會一併吐出待裁決那一節**（兩軸共用 `標的` 選擇器）。
>
> **落檔前先跑 `decision-lint --book <你的書>`**：七欄／日期／狀態／射程寫法／標的存在性／「一項裁決一列」／`已升為通則` 指向的檔在不在。
