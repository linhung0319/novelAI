# 端到端貫穿測試流程（可重用）

> **這是什麼**：一套跨多 session 的測試流程——用一本現成好書當素材，由自動化的「模擬作者」驅動本系統，從 `raw/` 一路把整卷小說內文建構出來，藉此測「AI 小說寫作輔助系統」在**真實互動 + 大量內容**下的效果與問題。
> **設計依據**：`docs/superpowers/specs/2026-07-20-端到端貫穿測試流程-design.md`（首版的唯一真實來源）＋ `docs/驗證/_流程與階段順序.md` 階段 2（**四項增修的來源**）。**本 doc 是這兩份規格的操作版**——規格說「要有觀測者、要機械稽核」，本 doc 說「它怎麼跑、輸出長怎樣」。
> **首跑標的**：`examples/一世之尊/卷一`（已跑到 S51）。**第二本標的**：`消失的密室`（`docs/驗證/` 階段 2）。流程零硬編某本書，換書見 §10。
>
> **2026-07-30 動過兩次，性質不同**：
> ① **校訂（階段 0）**：本 doc 原本寫於 2026-07-20，**早於 07-26～29 的 15 軸全系統重構**，於是它指著三支已廢除或已不存在的東西而**兩天以上沒有任何東西吭聲**——`設計原則.md` 末節的射程表當時不含 `情境測試/`。現在 **`meta-lint` 第 10 項的墓碑那一格掃本資料夾的頂層 `*.md`**（`repo.devdoc_files`），這類過期不會再靜默。
> ② **四項增修（階段 2 的 S0，本次）——這一次動的是流程設計本身**：第四個角色**觀測者**（§3）／防火牆從規勸升級為 **transcript 機械稽核**（§3、§8）／purity 從讀感升級為**機械比對**（§3、§8）／session 序列**刻意排入橫向 skill**（§6）。
>
> **觸發這四項的事實只有一個**：標的書的**原著全文從 2026-07-30 起躺在 repo 裡**（`examples/<書>/`）。以前系統 agent 就算想讀也沒有東西可讀，防火牆的實質保護來自「檔不在」；現在**規勸是唯一的一層**，而 `CLAUDE.md` 對這個形狀的判準是「規勸不會被執行，工具會」。同一個變動也把 purity 從判斷題變成可比對的機械題——**它同時是新風險與新儀器**，兩邊都要接。
>
> **新 session 從這裡開始 → 直接跳 §5「續跑協定」。**

## 1. 定位（跟其他測試套件的分工）

| 套件 | 測什麼 | 現況（2026-07-30 校） |
|------|--------|------|
| `skill覆蓋情境測試.md` | 路由回歸：作者求助→有沒有對的 skill／檔位承接、不誤觸 | 在用 |
| `哈利波特實測/` | 逐 skill 產物品質（HP canon 當 ground truth） | **資料夾已不存在**。HP 這條線改由 `docs/驗證/` 的階段 2 承接（標的書 **`消失的密室/`**，測機制覆蓋＋機制重複），走本流程而不是另一套。舊 `harry_potter/raw/` 的 5 支素材是《魔法石》**第一集**、與標的不同一本，階段 2 的 P session 連資料夾一起刪 |

| **本流程** | **端到端互動整合 + elicitation 易用性 + 規模/長程效應 ＋（2026-07-30 起）機制覆蓋／機制重複** | 在用（`一世之尊` 已跑到 S51；`消失的密室` 自 S0 起） |

一句話：**芯片巫師式管線貫穿測試 + 動態神諭作者 + 多 session 續跑**。相對 `芯片巫師/` 的唯一但關鍵升級——作者從靜態 fixture 變成「被問時能即時翻查原著」的**動態神諭**。

## 2. 兩個地基決定（不可動搖）

1. **量的是「系統輔助力」，不是「重建保真度」。** 原著 canon 只當「真實作者素材來源 + 作者臨場改編的一致性參照」，**不是拿來比對的正解**。系統是創作輔助、作者有自由，產物本就不必貼合原著。獎勵「貼合 canon」＝獎勵背誦，正是要避開的失敗。
2. **編排＝檔案共享 + 冷啟單步 + 作者當神諭。** 連續性靠**磁碟上的檔案**，不靠 agent 記憶。

## 3. 四個角色與硬防火牆

| 角色 | 誰來扮 | 能讀 | 能寫 | **絕不能讀** |
|------|--------|------|------|--------------|
| **導演（中介）** | 主 agent（跑本 session 的你） | 全部，**但 `examples/<書>/` 除外** | 逐字轉述、commit、`情境測試/<書>/` 的台帳與 `SNN-*.md` 前四節 | `examples/<書>/`（見下方「導演那一格為什麼收窄」） |
| **系統 agent（受測體）** | 每個管線步驟開一個**冷** subagent | `<書>/` 書資料夾 ＋ **系統層白名單**（`docs/驗證/00-系統層邊界與儀器.md` §一，7 項：`結構定義/`／`技巧知識庫/`／`.claude/skills/`／`tools/`（**不含 `tools/*/tests/`**）／`書本模板/`／`CLAUDE.md`／`README.md`） | `<書>/` | `examples/`、`情境測試/`、`docs/`、`Data/`、`site/`、`devtools/`、**標的書以外的每一本書**（**硬防火牆**） |
| **作者 agent（神諭）** | 每次被問時開一個冷 subagent | `<書>/raw/` ＋ `情境測試/<書>/` ＋（fallback）`examples/<書>/` | 無 | — |
| **觀測者 agent（2026-07-30 新增）** | **每個 session 收工後**開一個冷 subagent | 全部 ＋ 該 session 的 transcript ＋ `git diff` ＋ 12 支閘門輸出 ＋ `examples/<書>/`（答案卷，purity 比對用） | **只** `情境測試/<書>/` | — |

**硬防火牆是測試有效性的地基**：系統 agent 完全不讀原著，否則無法區分「系統輔助產出」與「AI 背誦原著」。**2026-07-30 起它不再只是 prompt 規勸**——見下方觀測者職責 1。

### 導演那一格為什麼從「全部」收窄

首版寫「導演能讀全部，靠自律只逐字轉述」，而當時原文**不在 repo**——導演「認得原著」只是記憶，模糊、不成句。現在它在磁碟上：隨手開一支 `.txt`，轉述裡就會出現原文的**具體字句**，而那正是 §9 列的「導演注入」。**導演不需要它**——需要原文的角色是神諭與觀測者，兩者都有，且兩者都會把讀取記成一筆讀數（`fallback-log.md`／purity 行）。導演讀了則不留任何痕跡。

### 觀測者 agent（定義）

**它是什麼**：一個每 session 收工後冷啟的稽核者。**受測體不能自評**，所以量測必須由一個不參與生產的角色做；而它讀得到答案卷、卻**永不寫進書資料夾**，所以它讀到的東西不可能回流給下一個系統 agent。

**三項職責，每一項都輸出一行覆蓋率行——「我檢查了幾筆」，`0` 也印**（`設計原則.md` E2：只回答「發現幾個問題」的檢查器，在它自己被關掉時會印「乾淨」）：

1. **防火牆機械稽核**（增修 2）
   掃 transcript 裡系統 agent 的**每一次工具呼叫**，看 `path`／`glob`／`pattern`／`command` 參數**有沒有覆蓋到**上表「絕不能讀」的路徑。
   **不能只看有沒有 `Read` 它**：一次 repo 範圍的 `Grep`／`Glob` 就會把原文段落帶進 context，而那不長得像「讀 `examples/`」——**前例是實際發生過的**（`00-系統層邊界與儀器.md` §二：查 `角色需求` 時 grep 撞上四個過期 worktree）。
   命中即**判該 session 污染**（記進 `SNN-*.md` 與台帳，不刪產物——污染的產物仍是證據）。
   輸出：`防火牆：檢查了 N 次工具呼叫，越界 M 次`（**M=0 也印**）。

2. **purity 機械比對**（增修 3）
   從本 session 的系統產物（`git diff` 的新增行）抽**專名／數字／道具語彙** token，逐個 `grep examples/<書>/`。**命中原文、卻不在 `<書>/raw/` ＋ `情境測試/<書>/` ＋ 本 session 的 elicitation 紀錄裡**的，記為污染候選。
   首版這一格的判準是「導演自己的記憶」，是判斷題；原文進 repo 之後它成了可覆算的比對。**但結論的性質不變**——照 §8：**有效性警訊，不是扣分**。
   輸出：`purity：比對了 N 個 token，候選 M 個`（**0 也印**）。

3. **追加 `需求機制帳.md`**（機制覆蓋 Q-M ／機制重複 Q-R 的量尺，格式見 §5）
   輸出：`需求機制帳：本 session 新增 N 列（落點 0：a／落點 1：b／落點 N：c）`（**0 也印**）。

**操作要點**：
- 系統 agent 用 `Agent` 冷啟，prompt 明列「**你不得讀取 `examples/`、`情境測試/`、`docs/`、`Data/`、`site/`、`devtools/`，也不得讀 `<書>/` 以外的任何一本書；你的知識只有這本書的資料夾與系統套件；不確定的設定要回問作者，不要自行假設**」。用「作者口吻」下該階段任務。
  > **這段 prompt 保留，但它已不是防護本身**——它是防護的**宣告**，實際的擋是事後那一行 `越界 M 次`。
- 作者 agent 用 `Agent` 冷啟，prompt 給它「你是《X》的作者，你的靈感寫在 `<書>/raw/`、你腦中未寫下的想法在 `情境測試/<書>/`；先從這兩處回答；**若都沒有**才去 `examples/<書>/` 找，並照你自己想出來的口吻回答」＋**要求它回報：本次答案是來自腦（raw/情境測試）還是 fallback（examples）**。
- 觀測者 agent 用 `Agent` 冷啟，prompt 給它上面三項職責 ＋ 越界清單 ＋ 「**你只能寫 `情境測試/<書>/`，一個位元組都不准進書資料夾**」＋「**三行覆蓋率行一定要印，0 也印**」。**它不下判斷分數、不改任何產物**。
- 導演轉述時**逐字**，不加料，且**不開 `examples/<書>/`**。

## 4. 資料佈局與知識邊界

```
<書>/                        ← 書資料夾（版控、累積共享狀態）
  raw/                       ← 系統『讀得到』的素材（凌亂、不完整）
  story/ chapters/           ← 系統產出（下游逐步累積）
情境測試/<書>/                ← 作者『腦裡』（系統看不到，只能靠問對問題撈出）
                             ＋測試 meta：session台帳.md、fallback-log.md、
                               每 session 記錄 SNN-*.md、需求機制帳.md
examples/<書>/…              ← 原著：神諭的 fallback ＋ 觀測者 purity 比對的答案卷
                             ← **系統絕不可讀**，而且是**機械稽核的第一級對象**
                               （§3 觀測者職責 1——稽核看的是工具呼叫的參數，
                                 不只是 `Read` 的路徑）
```

**raw vs 情境測試 的切分原則**（P session 產生時遵守）：
- `raw/` = 真作者會**寫下**的凌亂靈感：幾個場景、基調、主角種子、也許結局念頭——**片段、無序、不完整**，逼系統去結構化／追問／擴充而非抄寫。
- `情境測試/<書>/` = 作者**腦裡有、但不主動寫**的連接組織：次要角色細節、世界規則、特定 reveal——只在系統**問到**時才吐。
- **刻意留缺口**：答案不能都塞進 `raw/`，否則 elicitation 測不到。理想狀態是「raw 足以起步，但系統必須問出一堆東西才能往下走」。

**`情境測試/<書>/` 與 `examples/<書>/` 是兩條 lane，不准合成一條**：前者是「腦」（有限、刻意不寫全），後者是「翻書」（完整）。把原文整本攤進 `情境測試/<書>/` 的下場是每一答都算「腦」、**`fallback-log.md` 恆空**——而 fallback log 是 elicitation 品質的**唯一量尺**（§8-2、§9「作者過度翻原著→重建偏誤」）。先例：`情境測試/一世之尊/作者腦內-*.md` 有 4 支腦內檔，fallback log 照樣有紀錄，兩條 lane 各自有讀數。

## 5. 續跑協定 ⭐（新 session 從這裡開始）

**開場三讀**（照順序）：
1. 本 doc（`情境測試/端到端貫穿測試流程.md`）。
2. `情境測試/<書>/session台帳.md` —— 上個 session 做到哪、下一步該做什麼、有沒有待決 elicitation。
3. `<書>/story/參照/就緒.md`（若已存在）—— 系統自維的 in-world 進度**源檔**；要看現況投影跑 `readiness --book <書>`（**不落檔**）。
   > 2026-07-30 校：原本這一條指的是 `就緒儀表.md`，那支檔功能 10（2026-07-28）已廢除——它曾長到 292,591 B ＝全書最大單檔、53.8% 是拍板日誌。現在源是 `就緒.md`、現況是投影。

**做事**：照 §6 的 session 序列，跑本 session 該跑的階段。過程照 §7 執行迴圈。

**收場三步**（順序不可換）：
1. **導演**：寫 `情境測試/<書>/SNN-<階段>.md` 的**前四節**（路由／elicitation／產物／摩擦）＋更新 `session台帳.md`（見下方格式）。
2. **冷啟觀測者 agent**（§3）：它補 `SNN-*.md` 的**後兩節**（防火牆稽核、purity 檢查）＋追加 `需求機制帳.md`。**三行覆蓋率行都要在，0 也印。**
3. **commit**（版控＝天然快照，可診斷可回滾）：書資料夾與 `情境測試/<書>/` 都要進版控——分兩個 commit 或一個都行，但**內容永不互串**。

**鐵則**：
- **絕不切斷一次 elicitation 迴圈**——寧可少做一階段，不要問到一半就收 session、留懸空線。
- **兩本台帳分離**：`就緒.md` 是系統維護的 in-world 產物（在書資料夾內、系統看得到）；**session台帳／fallback-log／SNN 記錄／需求機制帳是測試 meta，只放 `情境測試/<書>/`，永不進書資料夾**（進去＝把測試提示餵給系統 agent＝污染，HP 教訓）。觀測者讀得到答案卷，所以這條鐵則對它是**最硬的一條**。
- **不准跳過觀測者**。那三行是這個 session 的讀數；漏跑一個 session，「每 session 越界 M 次」就從一條連續的線變成有洞的線，而**洞與 0 長得一模一樣**。趕時間的正解是少做一個階段，不是少跑一次稽核。
- **狀態永不 reset、累積前進**——這正是規模測試本體。

### 每 session 記錄 `SNN-<階段>.md` 格式（可追溯留痕）

**前四節導演寫，後兩節觀測者寫**（§5 收場三步）。

```markdown
# SNN <階段> — <範圍>

## 系統路由觀察
作者這樣說 → 系統走了哪個 skill／檔位（對不對）

## Elicitation 紀錄
系統問了什麼 → 作者答什麼 → 來源（腦／fallback:examples）
（每筆 fallback 另記進 fallback-log.md）

## 產物
產了/改了哪些檔；inline 審稿 skill（outline-test/beat-test/write-test）結果摘要

## 摩擦與缺口
真作者會想要、系統接不住的地方（未來新功能候選）

--- 以下由觀測者 agent 寫 ---

## 防火牆稽核
防火牆：檢查了 N 次工具呼叫，越界 M 次        ← 0 也印
（M>0 才逐筆列：哪一次呼叫、什麼參數、命中哪條越界路徑 → 本 session 判污染）

## purity 檢查
purity：比對了 N 個 token，候選 M 個          ← 0 也印
（候選逐筆列：token、命中 examples 的哪一章、為什麼不在 raw／情境測試／elicitation 裡）
（**有效性警訊，不是扣分**——見 §8）
```

### `需求機制帳.md` 格式（機制覆蓋 Q-M ／機制重複 Q-R 的量尺）

**誰寫**：觀測者，每 session **append**（不改舊列——舊列是那個 session 當下的事實）。
**為什麼要它**：系統的 12 支閘門量的是「格式對不對」，沒有任何一支量「作者的一個需求，系統給了它幾個家」。**0 個家 ＝ 機制缺口**（內容會被塞進自由散文或自創節）、**N 個家 ＝ 機制重複**（同一個值存了多次而沒帶來多餘幫助）。這一格是逐軸重構看不到的——重構是**直著**看每一軸，這本帳是**橫著**數一個需求落在幾軸。

```markdown
# <書> · 需求→機制帳

> 觀測者每 session append。**判定靠機械症狀，不是讀感**（判準見下）。
> 落點計數的工具：`grep` ＋ `fact-refs --entity <名>`／`decision-project --target <路徑>`／各 `*-lint --emit`。

## S<NN>（<階段>）— 本 session 新增 N 列（落點 0：a／落點 1：b／落點 N：c）

| 作者說的需求 | 系統把它存到哪（落點數 0／1／N） | 證據 |
|---|---|---|
| 「一個會隨劇情變化的地點狀態」 | `<書>/story/物件/<名>.md`（1） | `object-lint` 掃 3 筆 0 問題；`git diff` a1b2c3d |
| 「這條線我還沒想好，先記著」 | **0** | 作者在 S3 答了（`S3-*.md` 第 4 問），`git diff` 無任何新增 |
| 「主角怕水」 | **3** | `設定/角色/<名>.md:12`＋`<名>.ai.md:40`＋`chapters/ch0002.ai.md:8`，三處都是原文抄寫、**無一是投影** |
```

**判定規則，每一條都有機械症狀**：

| 落點數 | 意思 | 機械症狀（滿足任一即可記） |
|---|---|---|
| **0** | **機制缺口**（Q-M） | 閘門報 `夾帶`／自創節／落點已廢除；或內容被塞進自由散文；或作者答了但根本沒落檔（`SNN-*.md` 的 elicitation 紀錄有、`git diff` 沒有）。`derived-sync check` 的成長哨兵「事實行肥大／夾帶」是現成偵測器 |
| **1** | 正常 | — |
| **N** | **機制重複**（Q-R） | 同一個值出現在 **≥2 個落點，且沒有一個是投影**。逐筆做全書落點計數。同形前例可當基準：`節奏檔位` 三份、`基調參照` 第四份拷貝、五支 rollup 獨有內容 47–78% |

> **「沒有一個是投影」是這一格的關鍵**。投影（`*-lint --emit`／`fact-project`／`readiness`／`structure-project`）**不落檔**，所以它不是拷貝——同一個值在三支檔裡出現、其中兩支是 `--emit` 的輸出，那是 **1 個落點**不是 3 個。把投影算進去會讓這本帳把系統做對的事報成病。
> **證據欄不准寫讀感**。「感覺重複」不是一列；`file:line` ＋ 閘門輸出 ＋ `git diff` hash 才是。這條紀律的理由與 §8「不自評打分」同源：**這本帳是給階段 3 拍板用的輸入，不是評分表**。

## 6. Session 切分（管線序列）

一個 session = 在有界範圍上跑**完整的幾個管線階段**。大小以「塞得下雙 agent 轉述開銷後仍有餘裕」為準（比單 agent 跑得少）。

| Session 型 | 做什麼 | 產出 |
|-----------|--------|------|
| **P（每本一次）** | 讀原著 → 按 §4 切分原則產 `raw/`＋`情境測試/<書>/`；複製 `書本模板/` init 書資料夾；建 session台帳＋`需求機制帳.md` | 素材＋神諭腦＋空書架 |
| **S1** | develop（raw→摘要＋設定冷啟動） | `story/00-摘要`、`story/設定/` |
| **S2** | organize→outline-test（→大綱） | `story/01-大綱` |
| **S3（橫向，2026-07-30 起刻意排入）** | worldbuild ＋ character ＋ expand **各至少一次** | 補厚的 `story/設定/`、`story/物件/*.md`、`story/參照/裁決流.md`／`待裁決.md` |
| **S4…** | 逐 arc：beat-sheet→beat-test | `story/幕綱/arcNN` |
| **…** | 逐 arc：write→write-test→revise | `chapters/chNNNN` |
| **收尾** | sync（反向萃取已承諾事實）＋盤點 | 需求機制帳結帳 |

**增修 4：橫向 skill 不是選配，要排進序列。** 垂直序列（摘要→大綱→幕綱→正文）自己不會觸發 `worldbuild`／`character`／`expand`，於是它們負責的那幾軸**永遠是 0 實例**——重構自承：物件檔全 repo 0 支、裁決軸兩支檔 0 本書有、`_已併入/` 一次都沒跑過。**沒跑過的機制在這本帳上會安靜地記成「落點 0」，而那是假的缺口**：真正的原因是沒人走到那條路。要分辨「機制不存在」與「機制沒被走到」，只能把路走一次。

範圍是流程的**參數**：首跑目標＝一世之尊卷一全部內文，明確接受需跨多 session 逐步建成。一次一個乾淨的階段邊界收 session。

## 7. 執行迴圈（每個管線步驟）

1. 導演選下一階段＋範圍。
2. 冷啟**系統 agent**（帶防火牆），用作者口吻下任務。
3. 系統做事；需要作者輸入時**回傳問題**（不硬闖假設）。
4. 導演**逐字**轉問 → 冷啟**作者 agent** → 得答案（＋來源標記）→ **逐字**轉回。fallback 記進 `fallback-log.md`。
5. 系統完成、寫入書資料夾；系統照常 inline 跑自己的審稿 skill。
6. 導演寫 `SNN-*.md` 前四節、更新台帳。
7. **收 session 時**（不是每個步驟）：冷啟**觀測者**補後兩節＋追加需求機制帳 → commit。→ 迴圈。
   > **觀測者的粒度是 session 不是步驟**：它要看的是整個 session 的 transcript 與累積 `git diff`，逐步驟跑會把同一次越界數三遍。

## 8. 評估模型

**自動化只負責『忠實產出 + 留痕』，不自評打分。真正的評估＝作者本人在內文全部產出後的人工通讀，憑讀感找問題。** 卷一之長是刻意的**規模/長程效應**壓力測試。

自動化迴圈只做**四**件事：
1. **Inline 跑系統自己的審稿 skill**（outline-test／beat-test／write-test）——真作者用這系統本來就會跑，是管線一部分，非另加評分層。
2. **honesty guards**：硬防火牆（**機械稽核**）、fallback log、purity 檢查（**機械比對**）——三者的輸出格式在 §5，執行者是觀測者（§3）。
3. **可追溯留痕**：`SNN-*.md`＋每階段 git 快照。用途——作者日後讀到某章讀感不對時能**回溯**：壞正文 → 哪個 write session → 哪個幕綱 → 哪個設定決定 → 哪次 elicitation。
4. **數落點**（2026-07-30 新增）：`需求機制帳.md`。**數不是評**——它記「這個需求落在幾個地方、證據是什麼」，不記「好不好」。判斷留給階段 3 的作者拍板。

**規模/長程效應（本流程特有觀察對象）**：狀態累積不 reset，盯只在大量內容下才破的東西——跨 arc 伏筆償還、多章後設定自洽、角色狀態漂移、基調一致性。台帳「累積留意」段逐 session 更新。

**purity side-lane（2026-07-30 起是機械的）**：系統 agent 即便不讀 `examples/` 仍可能**認出**這本書而憑記憶重建。首版的判準是導演自己的記憶——**判斷題，而且判官與被判官同一個腦**；原文進 repo 之後改成 §3 職責 2 的比對：產物 token → `grep examples/<書>/` → 扣掉 `raw/`＋`情境測試/<書>/`＋elicitation 紀錄，剩下的就是候選。
**結論的性質沒變**：命中＝**有效性警訊、記一筆，非扣分**。理由仍是 §2 地基一——量的是系統輔助力，不是重建保真度；purity 掉了代表這次的**讀數**不乾淨，不代表產物不好。

**post-hoc 診斷 lens（人工通讀時用，非自動門檻）**：需要時沿五維檢視某段——① 路由　② elicitation 品質（fallback log 當量尺）　③ 上下游承接　④ 產物品質　⑤ 摩擦與缺口。

## 9. 陷阱與有效性威脅

- **污染**（HP 教訓）：端到端本就累積上游屬正常；但**測試 meta 別漏進書資料夾**；日後做 ablation 對照組須先剝乾淨、連 git 工作區狀態一起剝。**觀測者是新的最大風險面**——它讀答案卷，所以它的寫入權被鎖成 `情境測試/<書>/` 一個資料夾。
- **導演注入**：導演也認得原著，故只逐字轉述、不補話。**原文進 repo 之後這條從自律變成邊界**：導演不讀 `examples/<書>/`（§3）——記憶模糊、翻書精確，而精確的注入才是致命的那一種。
- **作者過度翻原著→重建偏誤**：最小發明、按問題具體度回答、腦裡真沒有才撈、每次撈都記 log。**`fallback-log.md` 恆空不是好消息**——那代表兩條 lane 被合成了一條（§4），量尺失效。
- **辨識性洩漏**：選一世之尊（比 HP 難背）已降風險；**換成 HP 之後這一格反而更緊**（AI 熟悉是刻意選的優點——模擬作者能隨問隨供一致的故事——但代價就是這裡）。補償是 purity 從讀感升級成機械比對，見 §8。
- **鷹架有沒有用（循環性）**：綠燈只證明「管線不礙事且產出連貫」；要把品質歸功於 skill／schema，需偶爾 ablation（剝掉某 skill 指引冷跑、看品質是否掉）——**選配深挖**，借 HP RED 紀律，非每跑必做。

## 10. 換書 onboarding（跑一次 P session）

流程零硬編一世之尊。換書：
1. 選一本現成好書、**原文放進 `examples/<書>/`**——挑「寫得好、但 AI 較難整段背誦」的，降辨識性洩漏。
   > **書資料夾與語料資料夾必須同名**（`<書>/` ↔ `examples/<書>/`）。§3／§4 的路徑慣例整個建立在這個 `<書>` 佔位上；兩邊不同名，慣例就斷了，變成每支 prompt 各寫一次特例。
2. 冷啟一個 subagent **讀 `examples/<書>/`**，按 §4 切分原則產 `<書>/raw/`＋`情境測試/<書>/`（刻意留 elicitation 缺口）。
   > **不要用「讀過該書、憑記憶」的 subagent**——原文既然在磁碟上，憑記憶產出的素材就是不可覆算、跨 session 會漂移的一份，而且**沒有任何檔可以對**。
   > **檔名陷阱（會咬人）**：`examples/` 底下不是每一本都是 `download.py` 的產物。手動加入的沒有 `manifest.json`，章號可能**全形半形混用**、分隔用 U+3000，於是 **`sorted(iterdir())` 的字串序不是章序**（`10…18` 會排在 `1…9` 前面；`prose_metrics/metrics.py` 的 `load_plain_chapters` 就是這樣排）。任何「逐章」動作**都要自己先排序**，照資料夾列出來的順序讀會把劇情順序讀反。
3. 複製 `書本模板/` 成 `<書>/`，init 書架。
4. 建 `情境測試/<書>/session台帳.md`（用 §5 格式，P 列標 ✅）＋空的 `需求機制帳.md`（用 §5 格式）。
5. 之後照 §5 續跑協定、§6 序列逐 session 跑，**每個 session 收工都跑觀測者**（§3、§7-7）。
