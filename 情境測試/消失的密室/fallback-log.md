# 消失的密室 · 端到端貫穿測試 · fallback log

> 測試 meta，**只放 `情境測試/消失的密室/`，永不進書資料夾**。
> 記每一筆「作者 agent 腦裡（`消失的密室/raw/` ＋ `情境測試/消失的密室/作者腦內-*.md`）真的沒有、去翻了 `examples/消失的密室/` 實檔」的 fallback。
>
> **這是 elicitation 品質的唯一量尺**（基座 §8-2、§9）。兩個方向都要看：
> - fallback **多** ＝ 腦內檔留的缺口太大，作者一直在背原著 → 重建偏誤。
> - fallback **恆空** ＝ **出事了**，不是好消息。那代表兩條 lane 被合成了一條（基座 §4）——腦內檔把整本書都寫進去了，於是每一答都算「腦」，量尺失效。**`fallback-log.md` 非空是階段 2 的出場條件之一。**
>
> **本輪的兩條 lane 是怎麼切的**（P session 拍板，見 `P` 列）：承重的（謎底、世界規則、角色為什麼是這樣、結局要成立什麼）進腦內檔；質地的（誰在第幾場說了什麼、配角癖好、具體數字、單場比賽過程）**兩邊都不寫**，留給 fallback。所以 fallback 預期會在 `beat-sheet`／`write` 這種要臨場顆粒的階段出現，而不是在 `develop`／`organize`。

## 讀數判讀（S1）

**量尺活著，而且切在預期的那一條線上。** P session 拍的兩條 lane 說「承重的進腦內檔、質地的兩邊都不寫，所以 fallback 預期出現在 `beat-sheet`／`write` 這種要臨場顆粒的階段，而不是在 `develop`／`organize`」——實際落點比預期早了一階，但**切分本身完全成立**：前兩輪 16 題問的全是承重項（謎底機制、主線引擎、題旨因果句、基調主從、取向定位、視角），腦內檔一題不漏地接住了，0 fallback；第三輪一問到「句子多長」「大家怎麼互相稱呼」「那個少年碰不碰得到東西」，腦內檔立刻見底。

**提前的原因不是腦內檔留錯缺口，是 `develop` 本身就要落 `風格.md`**——而風格的閘門欄位（`可用句式` 要「碎在分句／句／段 ＋ 阿拉伯數字」）是**可數的顆粒度**，讀感描述過不了。也就是說：**這一階段有一支閘門，它的規格天然要求質地層的答案**。這不是缺口設計失準，是流程圖上「質地何時被需要」這一格畫錯了一階。

**作者自述的共同形狀（值得帶進階段 3）**：五筆 fallback 全是「**我知道結果、沒記過程**」——句子多長（結果：讀起來偏疏）／誰拿了魔杖（結果：武器被拿走）／能力被誰聽過（結果：決鬥社引爆）。作者的筆記格式擅長記規則與結局，不記執行細節，而**細節正好是進正文的那一層**。

## 讀數判讀（S2）

**整個 session 0 筆，而這一次它不是警訊。** 基座 §9 說「`fallback-log.md` 恆空不是好消息」——判準是**恆**空，而本輪的 0 有一個**當輪就可驗證的解釋**，且解釋是作者自己在第 1 輪末主動給的（沒有人問他）：

> 這輪八題我一次都沒去翻原稿，全部落在 `raw/` 跟腦內檔裡答得掉。這對你是好消息也是壞消息——**你問的還是承重層**。等你開始問「這一場誰先開口」「這句髒話砸下來之後現場停了幾秒」，我就得去翻了。

**這正是 P session 那條 lane 切分的原話**（承重進腦內／質地兩邊都不寫）。S2 的 18 題逐題檢查，**一題都不在質地層**：arc 界在哪、要不要立卷級方向、停在哪一秒、哪一個結構公式、分叉怎麼排、哪幾個角色要建、物件在哪兌現、規則要不要載體、四個審稿判斷認不認、計數器的落點——全部是「這本書的結構要長什麼樣」，沒有一題是「那一場實際發生了什麼」。

**所以 S2 的 0 與 S1 第 1、2 輪的 0 是同一種 0**（S1 前兩輪 16 題承重、同樣 0 fallback），不是 S1 第 3 輪那種見底。兩條 lane 仍然分開，量尺仍然活著。

**但這一格要盯著，因為它會在 S4 被證實或證偽。** 可證偽的預測（寫在這裡，讓下一個 session 回頭對）：

- **`beat-sheet`（S4）拆幕時 fallback 必須回來。** 拆幕會逼出「這一場誰先開口」「這一場停在哪一句」，那是腦內檔明文不寫的那一半。**S4 若仍是 0，那就不是 lane 切得好，是問題不夠具體**——屆時要回頭查系統有沒有在拆幕時自己填了質地而沒問。
- **S3（橫向 skill）可能仍是 0，且那也正常**——`worldbuild`／`character`／`expand` 問的是設定與需求，仍在承重層。

**另一個方向的讀數（本輪新出現，值得記）**：作者這一輪雖然 0 fallback，卻**主動去逐條對了一支系統沒讀的 `raw/` 檔**（`名字與人物.md`），撿回 5 格承重內容。這是「翻自己的檔」不是「翻原稿」，所以**不計 fallback**——但它說明腦內檔／raw 這一側**還沒被榨乾**，離見底還有距離。詳見 `S2-organize.md` 摩擦欄第 2 條。

## 讀數判讀（S3）

**S2 那條可證偽的預測，第一半兌現了。** 上一輪寫下「**S3（橫向 skill）可能仍是 0，且那也正常**——`worldbuild`／`character`／`expand` 問的是設定與需求，仍在承重層」。實際 7 輪 30 題只有 1 筆 fallback（3.3%），**而那一筆恰好是唯一一題不在承重層的**——見下方第 6 筆：問的是「這把傘在原著裡到底怎麼處理的」，那是**質地與執行史**，正是兩條 lane 都刻意不寫的那一半。

**這一筆 fallback 的形狀跟 S1 那五筆同源，但更值得記**：S1 那五筆是「我知道結果、沒記過程」；這一筆是**作者連自己有沒有想過都不確定**——他自承這把傘是 S2 第 2 輪才從 `raw/` 撿回來的，撿回來時只寫「目前沒排兌現點」，而**他自己的伏筆帳七節裡根本沒有這一列**。也就是說：fallback 觸發的不是「細節忘了」，是**一個從來沒被登記進收支表的承諾**。

**而這一筆 fallback 的結果是「翻完更確定不照它做」。** 作者翻完的結論是原著「說破＋不兌現」是最差的組合，於是他反而把 `不得被解釋` 留著、改用自己排的 arc04 那一行付掉。**這是 fallback 這條量尺第一次示範它不等於重建偏誤**——翻書可以是「確認別人怎麼做，然後不那樣做」，log 記的是**翻了**，不是**抄了**。基座 §9 那條擔憂（作者過度翻原著→重建偏誤）在這一筆上沒有兌現，但也不能因此放鬆：n=1。

**S4 那條預測仍然掛著、且現在更關鍵**：`beat-sheet` 拆幕會逼出「這一場誰先開口」「這一場停在哪一句」。S3 這一輪讓「承重層＝0 fallback」再多一個 session 的證據（S1 前兩輪 16 題、S2 全部 18 題、S3 的 29 題，合計 63 題承重、fallback 1），所以 **S4 若仍是 0，那就幾乎不可能是 lane 切得好了**——要回頭查系統有沒有在拆幕時自己填了質地而沒問。

## 讀數判讀（S4）

**那條可證偽的預測這一輪沒有被測到，而原因要寫清楚，不能讓它看起來像「又通過了一次」。** S2／S3 兩輪都預告「**S4 若仍是 0，那就幾乎不可能是 lane 切得好了**」——但**本 session 沒有跑 `beat-sheet`**（拆幕移到 S5，理由見 `S4-*.md` 檔頭）。所以 S4 的 26 題全部仍在**承重層**（落點、射程、機制、四象限、兩案並存），與 S2／S3 同性質。**這一輪的 0 不構成那條預測的任何證據，正反都不算。預測原封不動轉給 S5。**

**但這一輪長出一個新形狀，值得單獨記：作者六輪裡有四輪去讀了「系統套件的原始碼」，而不是腦內檔也不是原稿。** 具體是 `tools/decision_projection/…/parse.py:219`＋`cli.py:163`（找出護欄的第四條落點）／`objects.py:387`（證明那行資訊與名字無關）／`objects.py:411`（抓出子字串 near-miss）／`sources.py:344`。
**這不是 fallback**（`examples/` 一次都沒開），但它意味著兩件事：① **腦內檔／raw 這一側在「機制問題」上根本不是候選來源**——問題不在故事裡，在工具裡；② **作者這個角色在承重層的回答品質，有一部分來自他讀得到系統套件**。基座 §3 給神諭的讀取權是 `raw/`＋`情境測試/`＋（fallback）`examples/`，**沒有明文給也沒有明文禁系統套件**。這一輪它被用了四次，而且每一次都推翻了受測體的結論。
**交階段 3 的一個問題**：真作者讀不讀得懂 `parse.py`？若讀不懂，本輪那四格「作者比系統強」的讀數就有一部分是**神諭超能力**，不是系統可用性——而那會讓「摩擦與缺口」欄少記幾筆真正的摩擦。**下一輪若再出現同型，導演要在轉述時標記它。**

## 讀數判讀（S5）——**掛了兩個 session 的可證偽預測，第一次被真的測到，沒兌現**

預測原文（S2 立、S3 加碼、S4 因為沒跑 `beat-sheet` 而原封轉交）：

> **`beat-sheet`（S4）拆幕時 fallback 必須回來。** 拆幕會逼出「這一場誰先開口」「這一場停在哪一句」，那是腦內檔明文不寫的那一半。**若仍是 0，那就不是 lane 切得好，是問題不夠具體**——屆時要回頭查系統有沒有在拆幕時自己填了質地而沒問。

本輪 `beat-sheet` ＋ `beat-test` 都真的跑了，**fallback 仍是 0**。照約定回頭查了，結果是**三種形狀並存，不是預測假設的那一種**（逐筆證據見 `S5-*.md` 摩擦欄第 2 條）：

- **① 自己填了，但同時舉手問了。** 幕008 那個「把簽名書倒進最近那個坩堝」是系統發明來補前因的動作，**而它把這件事寫成「這是大綱沒有的動作，請認或否」並落進 `待裁決.md`**。作者答「否，你的前提就錯了……那是你為了填一個不存在的洞而發明的動作」。**填了，但沒有偷偷填**——這正是預測要抓的那個病，而它抓到的是病的**良性版本**。
- **② 沒填也沒問（真正的漏）。** 幕002 的八欄裡「今年學校會發生很可怕的事」一個字都沒有。**抓到它的不是作者也不是拆幕者，是 `beat-test`。**

**所以那條預測的前提站不住：它把「拆幕」當成質地層的入口，實際上質地層的入口是 `write`。**

**預測不作廢，改掛 S6，判準照舊**：`write` 跑完若仍是 0 fallback，就要回頭查它有沒有自己填了句子層級的東西而沒問——而那一層**沒有 `beat-test` 這種等級的第二道眼睛**（`write-test` 有 11 項，但它跟 `write` 讀的是同一批上游）。

**另一格要一起記的**：本輪神諭六輪全部標 `腦`／`腦（判斷）`，但第 5、6 兩輪自述讀了大量**書內產物與 schema**（`幕綱/arc01.md`、`裁決流.md`、`幕綱.schema.md`、五支角色／物件檔…）。**這不計 fallback**（兩輪都明確自述沒開 `examples/`），但它是 S4 那條「神諭超能力」的同型第二例——差別是這次讀的是**真作者也讀得到的東西**，所以殺傷力較小。**S4 交代導演「下一輪要在轉述時標記」，本輪六次轉述一次都沒標**，如實記在 `S5-*.md` 摩擦欄第 7 條。
