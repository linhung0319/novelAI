## 摩擦與缺口

1. **本 session 有一筆角色越界，而越界的是神諭不是受測體——基座 §3 給作者 agent 的寫入權是「無」，它寫了書內檔。**
   第 8 輪神諭自述並實際執行：改 `chapters/ch0003.md:63`（「整片脫出去摔進花圃」→「窗框摔進花圃」）、改 `story/幕綱/arc01.md:82` 幕004 衝突欄（`窗格`→`窗框`）、重跑 `derived-sync stamp` 重新封章。**導演實查證實檔案確實被改**（git 工作區與 grep 都對得上它的自述）。
   **這不是它偷做的**——它逐字寫明「我自己改，並且重跑了」，而且改得對（那三個字確實是複述與異名）。**問題在角色定義**：基座 §3 那張表寫死「作者 agent／能寫：無」，而**我的神諭 prompt 從頭到尾沒有寫這一條**（八輪都沒寫）。前五個 session 沒出事，是因為它一直沒想到要動手。
   **這一格的殺傷力在於它污染的是歸屬，不是內容**：`git diff` 的新增行從此不再等於「受測體的產物」，而**觀測者的 purity 比對正是拿 `git diff` 新增行當輸入**。神諭讀得到 `examples/`（fallback 是它的職權），所以一個有寫入權的神諭在結構上可以把 canon 直接寫進書裡，而 purity 那條量尺**永遠抓不到**——因為它會被「合法來源」洗白（那正是 S5 觀測者交出的同一格失明）。本輪它 0 次 fallback，所以實害是零；但**這是這條流程目前最大的一個有效性缺口**。
   **S7 起導演的神諭 prompt 必須加「你不能寫任何檔，一個位元組都不行」**，並在本輪的 `git diff` 上標出這三處是神諭寫的。交階段 3。

2. **`*-test` 不落檔頭讀數行，這是第二次，而這一次是導演的 prompt 造成的。**
   S5 `beat-test` 印出「0/1 支 arc 有 beat-test 紀錄」的假 0；本輪 `write-test` 印出「**0/3 支章衍生有 write-test 紀錄**」，同一個形狀。作者的裁決與 S5 逐字相同（「『我跑過了』不是內容，是機械讀數」），但這一次他**要求立護欄**：裁決流一列、標的 `全書`、判準寫成可判單行的形式——**那一行有沒有判斷成分**（正文／八欄／承諾區／就緒格是判斷，讀數行是收據）。
   **但要如實記一筆對導演不利的**：這一輪是**我在 prompt 裡寫了「不要自動幫我改，一個字都不要動」**，所以嚴格說它是照做。S5 那次是 skill 自己的克制，這次是被我加碼的。**兩次的共同點才是要交的東西**：`ch-lint`／`beat-lint` 的覆蓋率行**分不出「沒跑」與「跑了沒記」**，而那兩件事的處置完全相反。交階段 3。

3. **`fallback-log.md` 那條掛了四個 session 的可證偽預測，在它自己指定的到期日（`write`）被測到——仍是 0，而這一次三種解釋全部不成立。**
   預測原文：「質地層的入口是 `write`（S6）……S6 若仍是 0，就要回頭查 `write` 有沒有自己填了句子層級的東西而沒問。」
   本輪 `write`＋`write-test`＋`revise` 三支全跑、寫出 3,700 字正文，**fallback 仍是 0**。回頭查的結果：
   - **它確實自己填了句子層級的東西**——每一句都是它寫的，這是 `write` 的定義。
   - **但它問了 40+ 題**，而且問的全部是「這一句該不該存在」層級的（章末停在哪／哪一句是註腳／貓頭鷹要不要名字／客人姓什麼），**不是「這一場誰先開口」**。
   - **真正的原因是第三種，而它是 S5 那三種以外的第四種**：**作者的腦內檔在質地層並沒有見底，是因為這本書的質地判準被寫成了規則而不是實例**——`raw/基調-我想寫成什麼感覺.md` 有 15 條可執行的句子層規矩（笑點不解釋／恐怖靠位置與生理／章末不總結／可信度與台詞長度成反比），所以八輪裡每一個質地問題都在 raw 裡有落點。
   **這條預測到此應該作廢，不是再改掛一次**：它假設「質地問題必然需要翻原稿」，而這本書證明了反例——**質地寫成規則就不必翻書**。這比預測兌現有價值。交階段 3。

   | 二 | `--for-beat` 撈不到物件檔 | 「工具射程窄，實體集只住人」 | `beats.py:46` docstring：詞彙表本來就是「設定層 ∪ 物件檔名」，**缺的是幕綱欄位內容** |

   前兩次是**它自己**回頭更正的（第二次是作者實跑推翻）；第三次是它自己在查別的東西時撞見的。作者的處置不是記三筆懺悔，是**兩條可當場驗證的規則**：① 講「工具為什麼這樣」的句子必須帶檔名＋行號；② 0 命中或「全是通用列」一律先驗選擇器（拿一個確定會命中的值打正對照）。
   **然後第④條在寫下來的同一小時內攔住了同一支 agent 的第四次**（它跑 `git show` 少了書名前綴拿到 0，念頭是「原檔沒有表格列」）。作者對這一格的評價值得整句帶走：「**一條你以為在管別人的規則，當場管到自己，那才叫規則。**」
   **但代價那一半必須一起交**：`decision-lint` 驗**寫入側**的標的存在性，`decision-project` 在**查詢側**沒有同一個驗證——同一條規則只守了一半，而沒守的那一半是靜默的。**指紋一直印在螢幕上**（coverage 行的「標的 1 個」＝前綴寫錯），只是沒有人讀它。交階段 3。
