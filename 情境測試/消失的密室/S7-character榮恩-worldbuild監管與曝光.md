### 第 1 輪（`character` 榮恩）

作者的回答（來源全部標「腦」）：

- **分叉一 A（平弧線）**、**分叉二 (a)（永不兌現）**——理由是機械的不是氣質的：**這本書的零例外單一視角在機制上就保證了沒有人會替他數**，所以「他那一格不被兌現的原因，就是這本書的視角規則本身」。
- **分叉三：不降級源檔，戲在禁忌森林，是大綱漏寫了。** 埋設點放洞穴屋那個上午（哥哥拿蜘蛛整他），且**屬於溫度不屬於伏筆**。
- **分叉四：理由是窮，但書裡已經寫夠了，不再補一個字**——`.ai.md` 可以寫出這個推導（它是分析檔），大綱與正文一句都不准講出來。
- **分叉五：不立。** 三個理由，第三個最硬：那一場的全部重量在畫面邊緣那個動作，「把『窮』立成一條軸等於在那一場點一盞燈，而那盞燈會照到不該被照的東西」。
- **分叉六：不是分叉，已經裁決過了。**
- **分叉七：`false`**——七格當場全拍完。

**外加三格作者主動給的**：草稿三處不認（`想要`／`兩難`／`伏筆` 欄）、一個大綱缺口（見摩擦欄第 4 條）、兩條要落 `story/物件/榮恩.md` 的排除線（作者的話：「**寫在散文裡的紀律不會被執行，寫成排除線的會。**」）。

## 摩擦與缺口

1. **受測體回報「12/12 exit 0」，而 `char-lint` 實際是 exit 1——而它同一份報告裡又寫著「剩下的 3 個既有問題本輪之前就在」。**
   它**看到了問題、卻報了 exit 0**。根因幾乎確定是 `cmd | tail` ——管線的 `$?` 是 `tail` 的不是閘門的（**導演本輪自己也踩了同一個**，開場基線第一次跑就印出 13 個假的 `exit=0`，重跑才看到 `char-lint` 是 1）。
   **第 2 輪把「取真 exit code」寫進 prompt 之後，同型的 agent 就照實報了 exit 1 並逐筆說明兩筆都不是本輪造成的。** 這是「規勸有效」的一筆正面讀數，但它同時說明**沒有規勸的時候讀數是錯的**——而閘門的 exit code 是這整套流程的機械地基。**交階段 3：`E2` 要求每支閘門印覆蓋率行，但沒有任何東西要求呼叫者去讀 exit code**，而最常見的呼叫寫法（`| tail`／`| head`）會把它靜默吃掉。
2. **`decision-project` 的投影序號被當成檔行號，而代價是漏掉唯一直接管它的那一列。**
   第 1 輪受測體引「`裁決流:117`」證明 `所屬arc: []`，作者查出那個行號指到別的東西；受測體自承根因：**投影會把 157＋列濾成 36 列再重新編號，兩套號碼在數學上不可能相等**。
   代價具體且嚴重：同一次誤引**漏掉了 `裁決流.md:107`**——那是射程全書、生效中、直接釘死「衍生檔的 `伏筆` 欄維持 `{}`」的那一列，**而那一列的理由逐字就是拿榮恩的魔杖當例子寫的**。它查了 5 列裁決、開了一個分叉六去問作者要不要宣告伏筆欄，而正確答案是「這件事三個月前就裁過了，而且是為你這支檔裁的」。
   **這是 S5 操作事實 3（裁決流的「第 N 列」有兩套座標）的第三次命中，但形狀是新的**：S5 說的是「報列號時一律講檔行號」，這次揭出的是**投影的序號系統與檔行號在原理上不可對齊**，所以「講清楚是哪一套」不夠，得是「**引裁決流一律回檔案 `grep -n`**」。第 2 輪把這條寫進 prompt，該輪 0 次誤引。**守衛仍然是人眼。交階段 3。**
3. **兩支生產包 skill 的 `SKILL.md` 逐字指名 `Data/`，而 `Data/` 不在系統層白名單上。**
   第 2 輪受測體的報告裡出現「⚠️ 限制聲明：`Data/` 缺『設定一致性』的原文方法（核心原文〈下筆好設定〉遺失）」。導演查證：那是 `worldbuild/SKILL.md:98` 的**逐字樣板**，`develop/SKILL.md:80` 有同一句——它是照抄 skill 自己的話，不是去掃了 `Data/`（機械確認見下方觀測者稽核）。
   **但這一格本身要交**：`Data/` 對系統 agent 是「絕不能讀」，而生產包裡有兩支 skill 在每一次執行時對它招手，措辭還正好是「那份原文方法遺失了」——**一個沒有被防火牆 prompt 擋住的 agent，讀到這句話最自然的下一步就是去找它**。這與基座 §3「規勸不是防護本身」是同一格、方向相反：**這次是系統套件在對受測體招手**。守它的只有導演 prompt 裡的一行黑名單。
4. **兩輪各出現一次「檢索覆蓋不足」，而兩次漏掉的都正好是答案所在的那支檔。**
   - 第 1 輪：漏 `裁決流.md:107`（見第 2 條）。
   - 第 2 輪：為「動物園那次為什麼沒有信」開了 A／B／C 三個候選，作者**三個全駁**，因為答案已經在 `設定/角色/哈利/來歷.md:5` 與 `:15` 躺了兩行（「十一歲才知道自己是什麼」＋「動物園是十一歲以前」）。它讀了七支世界觀檔、裁決流、八支大綱、幕綱，**沒讀主角的來歷切面**。
   **兩次的共同形狀**：它的檢索是「照我推的方向找」，不是「照這個問題該覆蓋的集合找」。而**兩次都不是工具的錯**——`decision-project`／`settings-select` 都給得出那些檔，是沒有人去要。**沒有任何閘門量得了「一個提案的檢索覆蓋夠不夠」**，這與 S5「一條承重規則沒有任何檔在記」是同一族：沒有守衛，而且它的失敗長得像成功（三個候選、每個都有代價分析、每個都自洽）。
5. **受測體從一行源檔讀出一條作者沒寫的因果，然後替那條不存在的因果做了完整的三段風險評估，每一段都帶行號。**

   作者的定性可直接抄走：「**它三段推論每一段都帶行號、每一格都可覆算，而錯的是最上面那個讀法——行號不保證讀對。**」
