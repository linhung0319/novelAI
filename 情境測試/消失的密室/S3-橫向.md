## 摩擦與缺口

1. **冷神諭會餵過期指令給系統，而系統擋住了——這是本 session 最強的讀數。** 第 5 輪作者交代下一輪時說「`物件/海格的雨傘.md` 的兌現點還沒排到任何 arc，`beat-sheet` 開跑前要排掉」——**那筆本 session 第 1 輪就排掉了**（神諭每輪冷啟，讀不到另一輪的產物）。導演只附了一句「先看檔案現況再動手」，受測體逐檔舉證後**拒絕執行**（物件檔 `:17`／`arc04.md:76`／兩支伏筆表齊備），並指出「照字面動的話會多出第四份宣告，那正是你那輪駁回過的形狀」。
   **但這一格不能當成系統的功勞就收工**：擋住它的是導演那一句附註 ＋ 受測體剛好這一輪自己做過那件事。**換一個冷的系統 agent，它讀不到今天的對話，只會看到一句「作者說還沒排」——然後它會去排第二次。** 真正的缺口是：**沒有任何機制讓「作者的一句話」與「檔案現況」自動對帳**，而神諭本來就是刻意冷啟的。
2. **`expand` 自己量出一個它不肯處理的讀數，而系統裡沒有工具在量它。** arc05 括號佔比 40.7%（arc04 6.8%／arc06 28.7%），它明說「我不打算自己動手削——這是你的紀律，不是我的」。**這個克制是對的，但那個數字是它自己臨時算的**——`outline-lint` 量「連續敘述佔全檔 %」，不量「括號紀律 vs 淨敘述」的分項。作者認了絕對值（2,697 vs 413 ＝ 6.5 倍）並給出三類削法（理由→裁決流／複述→刪／跨 arc 禁令→物件檔），但**下一輪沒有工具會提醒他這件事，除非又有人手算一次**。
3. **「等到 X 之後才填」出現第三次，作者自己把它併成一個缺口。** 這一輪是 `消息與公開性.ai.md` 的 `伏筆` 欄（幕綱標完才填得乾淨，但幕綱不是它的源，所以沒有任何東西會回頭填）。作者原話：「這是我這幾輪第三次看到同一個形狀……這三列合起來是同一個缺口，別當三件事看。」處置是把提示寫在「`beat-sheet` 一定會讀到的那一列上」——**一個規勸，不是一支工具**，而 `CLAUDE.md` 對這個形狀的判準是「規勸不會被執行，工具會」。
4. **`物件.schema.md` 的封閉八型裝不下「事件」，而這本書已經有三件。** 系統自承 `型別: 設定規則` 是「最不壞的選擇，不是正確的選擇」並照 schema 規定停下來問；作者確認**今天不開第九型**，理由是「型別欄現在唯一的下游是那個按型別 fold 的投影，而那件事 schema 自己寫著刻意還沒做」，等三件（分帽子那天／五十年前那一次／書店那個動作）齊了再一次開。**交階段 3：這是一個被正確識別、正確延後、且延後理由可覆算的缺口——形狀很乾淨，值得當基準。**
5. **`decision-lint` 的「標的」欄成了本 session 唯一真正好用的跨輪記憶。** 三輪各自冷啟的系統 agent 都靠 `decision-project --target <路徑> --active-only` 撈到前輪的裁決（第 2 輪撈到 10／10／11 列，其中麥朵那列「她不是喜劇配角，她是這本書的方法論」被當成硬約束沿用）。**94 列裡有 36 列是本 session 長出來的**——這一軸的成長速率值得盯：它現在是全書第二大單檔的候選。
6. **作者兩次糾正系統的「診斷理由」而不是「診斷結論」。** 第 4 輪 Q1（缺口成立但理由錯）與第 6 輪 Q1（同型）——兩次都是系統用一個**機械讀數**（`分叉四` 在 arc05 出現 0 次／`char-lint` 17 支源無衍生檔）推出一個對的結論，而作者說「數字對，推論錯，我用我的理由收下」。**這是機械讀數最典型的誤用形狀：可覆算的計數被當成語意判準。** 兩次的正解都不是關掉讀數，是把讀數降級成線索。
