## S7 為下游釘下的三件操作事實

1. **管線會靜默吃掉閘門的 exit code，而這條流程的機械地基就是那個數字。** `uv run … char-lint --book X | tail -8` 的 `$?` 是 `tail` 的、恆為 0。**導演開場跑基線第一次就印出 13 個假的 `exit=0`**，重跑才看到 `char-lint` 是 1；第 1 輪受測體同樣回報「12/12 exit 0」，而它自己同一份報告裡又寫著「剩下的 3 個既有問題本輪之前就在」——**它看到了問題卻報了通過**。第 2 輪把 `out=$(cmd 2>&1); echo $?` 寫進 prompt，同型 agent 就照實報了 exit 1 並逐筆說明。**這條要一直寫進每一支受測體 prompt**，而它交階段 3 的形狀是：`E2` 要求閘門印覆蓋率行，但沒有任何東西要求呼叫者去讀 exit code，而最常見的呼叫寫法會把它吃掉。
2. **`decision-project` 的輸出序號與檔行號在原理上不可對齊，而錯位的代價是漏掉正好管你的那一列。** 投影把 157＋列濾成 36 列**再重新編號**，所以兩套號碼不可能相等。第 1 輪受測體引「`裁決流:117`」，同一次誤引**漏掉了 `裁決流.md:107`**——射程全書、生效中、直接釘死「衍生檔的 `伏筆` 欄維持 `{}`」，**而那一列的理由逐字就是拿榮恩的魔杖當例子寫的**。它因此開了一個早在三個月前就裁掉的分叉去問作者。**S5 操作事實 3 的第三次命中，但升級了**：不是「講清楚是哪一套」，是「**引裁決流一律回檔案 `grep -n`**」。第 2 輪照做，0 誤引。
3. **`worldbuild/SKILL.md:98` 與 `develop/SKILL.md:80` 逐字指名 `Data/`，而 `Data/` 不在系統層白名單上。** 第 2 輪受測體的報告裡原樣出現「⚠️ 限制聲明：`Data/` 缺『設定一致性』的原文方法（核心原文〈下筆好設定〉遺失）」——導演查證那是 skill 自己的樣板，**它是照抄不是去掃**。但這一格本身要交階段 3：**生產包裡有兩支 skill 在每次執行時對一個受測體被禁止讀的資料夾招手，措辭還正好是「那份方法遺失了」**。與基座 §3「規勸不是防護本身」同一格、方向相反——**這次是系統套件在招手**，擋它的只有導演 prompt 裡的一行黑名單。
