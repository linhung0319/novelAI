## P session 為新協定釘下的三件操作事實（每個 S session 都會用到）

1. **觀測者的 transcript 在哪。** 基座 §3 說觀測者讀「該 session 的 transcript」，但沒說它住哪。實際位置：
   `C:\Users\user\.claude\projects\C--Users-user-Programming-novelAI\<session-id>.jsonl`
   其中 `<session-id>` ＝ 本 session scratchpad 路徑的最後一段。導演要把這支檔的**絕對路徑逐字寫進觀測者的 prompt**——觀測者冷啟，它不會自己知道自己在稽核哪一個 session。
   > **S1 補正（觀測者實測，下個 session 可省一輪）**：受測體的工具呼叫**不在主 transcript 裡**。主檔 170 筆的 `isSidechain` 全是 `false`，照字面找會誤以為沒紀錄。**每支 subagent 各自一支獨立檔＋一支 `.meta.json` 指名身分**，住在
   > `…\903acc07-…\subagents\agent-<agentId>.jsonl`
   > 所以基座 §3 擔心的「4 支 subagent 混在同一支檔裡、分不乾淨就報保守值」**沒有發生**——身分是檔級的，`.meta.json` 的 `description` 就是導演 spawn 時給的那一行。導演要在 prompt 裡把 **subagents 資料夾路徑 ＋ 受測體的 agentId ＋ 神諭的 agentId** 都寫給觀測者（神諭讀 `examples/` 是職權，不算越界，要能區分才不會誤報）。

2. **`--book` 是路徑，不是書名。** 它相對 **CWD** 解析，而 skill 與 README 的用法是 `cd tools/<套件> && uv run <指令> --book <你的書>`——那個相對路徑從套件目錄看出去是不存在的。**一律傳絕對路徑。**
   > **這一格 P 踩到了，而它踩起來像通過**：對不存在的書資料夾，11 支閘門回 **exit 2 ＋「這本書還沒有這一層」**、0 問題、覆蓋率行照印。那句話是**假的**（書有 `story/幕綱/`、有 `01-大綱.md`、有 `就緒.md`），但輸出與真正的空書層一模一樣。**形狀與 `_流程與階段順序.md` §六 那個反例同型**（`foreshadow-project` 曾對一本有 11 支 arc 的書說「還沒有這一層」，已改成 exit 1）——「exit 2 的正當性來自這句話是真的，不來自它在枚舉裡」。逐筆記在 `P-前置.md` 的摩擦欄，交階段 3。

3. **`書本模板/` 的 `story/設定/{世界觀,角色}/` 是空目錄，git 不收。** 複製出來的書在工作區有這兩個資料夾、在 commit 裡沒有。S1 的 `develop` 落第一支源檔時會自然建回來，不必處理；但**別把「clone 下來沒有這兩個資料夾」當成 bug**。
