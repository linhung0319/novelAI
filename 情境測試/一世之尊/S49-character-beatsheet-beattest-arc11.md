## 摩擦與缺口

- **⭐⭐ 新缺口型態＝作者 agent（神諭）越界寫書資料夾·honesty-guard／角色分離破口**：beat-test 4 低發落那輪，**作者 agent 直接編輯了 `幕綱/arc11.md`**（在幕1007 加了一行低3 裁決 blockquote·mtime 落在系統 agent 完成之後），而按協定 §3 **只有系統 agent 能落筆書資料夾·作者 agent 只回答**。內容本身合法（是作者自己的低3 裁決·且幕綱屬作者利器），但**行為者錯了**、且繞過了系統 agent 的 schema 紀律流。
  - **導演偵測**：git status 顯示 `幕綱/arc11.md` mtime 更新＋作者回覆措辭「我已把……落成幕註」→ 讀檔確認 line 182 是作者 agent 加的 → **revert（移除該行）→ 把作者低3 裁決原話 verbatim 轉給系統 agent→由系統 agent 自己 in-lane 落一份**（體例對齊系統自己的 `⚠️…（write-facing）` 幕註寫法·單一份·collision-free）。
  - **根因＝導演 prompt 缺口**：三個作者 agent 的 prompt **都沒有明文禁止作者 agent 動書資料夾檔案**；beat-test 發落那則措辭「審稿員只是提可疑點，你可以判……可以要它改」被作者 agent 讀成「可以自己動手改」的授權。前兩輪（妙音／拆幕）作者 agent 恰好只回答沒踩到，這輪踩了。
  - **修正（釘給 S50＋所有後續）**：**作者 agent 的 prompt 必須明文寫「你只回答、絕不編輯／建立／刪除任何 `一世之尊/` 書資料夾檔案；任何落檔一律由系統 agent 執行」**。這是本流程繼「SNN 洩漏」「honesty-guard 協定用語洩漏」「git-log commit-message meta 洩漏」之後，第四類 honesty-guard 破口（前三類是**資訊**洩漏進系統可讀處，這一類是**角色**越界寫入產物），且**這一類會污染受測產物本體**（產物一部分非系統 agent 所產）——比 meta 洩漏更直接傷測試有效性，須零容忍。
- **降回閥（write 層）**：承段捏汗引擎押「妙音逼近卻不識破」·若 write 非桌面說破不能透，觸降回閥（檔頭已明寫·遇到回問作者）——arc11 write 第一號執行風險。
- **arc11 章數兩端**：起段併章→10 章（合法·工作框非硬約束）／合段三幕不許併——write 提案分章時當場拍。
