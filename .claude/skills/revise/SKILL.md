# revise — 修訂已寫成的正文

`write` 從無到有、`write-test` 回頭審稿，本 skill 補上第三步：**把審出的可疑點（或作者自己指出的問題）修掉**。對應洛克六步驟的「修稿」在句子／段落層級的部分；牽動劇情結構的修改不在此層（那要回幕綱）。

**定位聲明**：共創修訂，非代筆定稿——修訂後的文字仍是草稿，作者可全盤否決或重寫。資源定位與其餘共通規則見 `結構定義/共同約定.md`（必讀）。

## 依據

- 輸入清單：`write-test` 的可疑點報告（`章 id ｜ 測試類型 ｜ … ｜ 建議修正`），或作者在對話中的直接指示。
- 修訂的句子層級標準與 `write` 相同：`展示而非講述與五感描寫.md`、`字詞句法與抗生硬.md`（**定點修訂生硬句／翻譯腔的依據**：M1 動詞、M2 名詞落地、M3 修飾語橫向攤開、M4 句法直接性、M6 語氣顆粒、M7 十病徵——地板、取向定位無關）、`對白.md`（對白句型與七大壞習慣）、`敘事距離與DeepPOV.md`（Deep POV 第一節、心理距離第二節）、`視角與敘事人稱.md`（第四節知識邊界）、`角色塑造.md`（塑造六法、反差）、`動作場面寫作.md`（動作幕特判）、`氛圍與筆調.md`（基調一致）、`修辭與字句鍛鍊.md`（**天花板**：譬喻/擬詩/映襯、改字換詞——文學向才加重手）、`網文與文學取捨.md`（若被點名的問題是節奏／爽點與取向定位不符）。
- **若被點名的是「講述／跳躍／解說（事件塞子句、承重事件被摘要掉、段段宣布意義）」類問題（多來自 write-test 測試8）**，套用 `write` skill 的「正文五鐵律」（單一來源在 `write/SKILL.md`，此處不重述）：戲劇化不摘要／反思讓位給當下／禁解說／逐段時空因果連續／章末不總結·跨章不斷線。**被點名的若是「段落級解說段」**（整段在解說剛才那一手的用意、或把推理結算成條列）：**刪掉該段**，把那個用意改由對方的反應、下一個動作或事後代價演出來——不要把解說改寫得更含蓄，那只會讓工具不再報而病灶還在。刪後若該章篇幅明顯掉下去，是幕綱沒給東西可演的訊號，走待裁決回饋指回 `beat-test` 測試9，不要靠補解說補回字數。**若被點名的是「章末總結式收尾（回顧本章處境＋預告未來）」或「續接章沒硬切」**，依 R5 與 `戲劇張力與懸念.md` §二「章末三種切法」定點改該章末——續接章改硬切/前開軟鉤、刪掉總結段。
- **若被點名的是「行文節奏／碎」類問題（write-test 測試10(b)）**，載入 `技巧知識庫/行文節奏與呼吸.md`（N1–N6＋碎行八病徵）——**這一檔刻意只在修稿時載入**：正面技法在生成時會被套用到每一段，`write` 只拿三條上限，完整判準留到這裡，因為此時手上已有 `prose-metrics` 的實測數字，是定點修而非全篇套用。逐病徵修法：
  - **回聲斷片**（把上一段剛說過的話複製成獨立短段當重拍：`薑湯。二少爺。老奴。`／`穿了。`）：**刪掉那一段**，該有的強調改由下一個動作或對方的反應演出來。**不要改寫成更含蓄的短段**，那只會讓工具不再報而病灶還在（同上一條解說段的形狀）。
  - **高頻煞車**（≤8字非對白段夾在長段之間）：**併回鄰段**，或補進推進性內容讓它成為一個有主謂、有事件的完整句。刪到只剩必要的那一兩處。
  - **重拍裝置超配額**（破折號／換行單列特寫／留白斷句，三者同一配額池）：全章保留至多一兩處真正的轉折重音，其餘**降級成逗號或拆成正常句**。
  - **反面防呆**：**不要靠把所有句子拉長來壓指標**——那會撞回 `字詞句法與抗生硬.md` M7 的翻譯腔嵌套（測試10 的另一端）。三項簽名是**密度**問題不是**句長**問題；刻意的全短風格在三項全清時本來就不該被點名。同段被 (a)(b) 雙點名時，先處理 (b) 的密度（刪多餘重拍），再處理 (a) 的句內品質。
  - **副作用的去向**：刪掉重拍後若該段顯得沒東西可演，是幕綱／素材的問題，走待裁決回饋指回 `beat-test` 測試9，**不要補回裝飾性斷句把篇幅填回來**。若根源是 `可用句式` 宣告本身寫錯（各檔全短、或有無配額的裝置授權），在 `風格.ai.md`「待裁決回饋」記一列交 `develop`，不在本 skill 改風格檔。
- `結構定義/章節.schema.md`——正文源／衍生分離、內嵌幕錨點規範；`結構定義/風格.schema.md`——被點名語域/時代錯亂詞時對照對應章 `風格.ai.md` 禁用詞表，被點名句長勻平／顆粒度不符時對照 `可用句式`（每檔應指明碎在分句／句／段哪一級）；`結構定義/回饋記錄.schema.md`——上游回饋落點（對應衍生 `.ai.md` 的「## 待裁決回饋」）。

## 流程

1. **讀輸入**：修訂清單（報告或作者指示）、對應正文源 `chapters/chNNNN.md`＋衍生 `chNNNN.ai.md`（取 POV／風格欄）、該範圍的 `story/幕綱/arcNN.md`、`story/00-摘要.md`（基調）、該章 `風格.ai.md`（禁用詞表/稱謂/句式）。找不到對應章節 → 停下，建議先跑 `write`。清單若含行文節奏（測試10(b)）項而報告未附實測數字，自行跑一次 `prose-metrics --book <書資料夾>` 取「行文節奏」區塊——**修節奏要對著數字修**，否則容易矯枉過正到另一端。
2. **逐項分類**，每個修訂項判斷屬於哪一類：
   - **句子／段落層級**（過濾詞、講述改展示、POV 越界措辭、基調走調、對白標籤）→ 本 skill 直接修。
   - **結構層級**（漏幕、幕綱本身因果/伏筆有問題、分章邊界要重切）→ **不修**，在輸出中標明「根源在幕綱／分章，建議作者改幕綱後重跑 `write` 該範圍」；上游（世界觀／摘要／角色／風格）問題依 `回饋記錄.schema.md` 在對應衍生 `.ai.md` 的「## 待裁決回饋」追加一列（不改源、不改分析區）。
   - 拿不準是哪類 → 問作者。
3. **執行修訂**（僅句子／段落層級項）：
   - 只改被點名的段落與其必要的銜接句，**不重寫未被點名的部分**、不「順手潤色」範圍外文字。
   - 修訂不得改變幕綱定義的因果與結果、不得提前洩漏未收伏筆、不得移動或刪除 `<!-- 幕NNN -->` 錨點（修訂前後錨點集合必須相同）。
   - 每處修訂對照原可疑點的「建議修正」，但以句子層級標準為準，不逐字照抄建議。
4. **回報**：逐項列 `修訂項 ｜ 位置（章/幕） ｜ 修改前 → 修改後（或摘述） ｜ 依據`；未修項列明原因與去向（結構層級→幕綱、上游→回饋記錄N筆）。明確聲明：修訂後仍為草稿，作者可否決任何一處。
5. **重新封章正文衍生檔**：修訂正文源 `chNNNN.md` 後，其 hash 變了 → `derived-sync check` 會報 `chNNNN.ai.md` stale。對應幕/POV/風格未變時，`chNNNN.ai.md` 內容不變、只需 `derived-sync stamp chNNNN.ai.md` 更新 hash；若修訂改到跨進別的幕（罕見，修訂原則上不動錨點），據新錨點更新 `對應幕` 再 stamp。**`chapters/_index.ai.md` 章序未變則不必重生**（狀態仍為草稿）。修訂幅度大時，建議作者重跑 `write-test` 該範圍複驗。

## 邊界

- 不改幕綱與上游正文（回饋機制照 `共同約定.md`）。
- 不做結構性重寫（換 POV、重排 Scene、增刪幕的內容）——那是「改幕綱→重跑 write」的路徑。
- 不做未被點名的全文潤色；作者若要「整章重潤」，仍逐段列出改動供其否決，不悶頭換血。
- 不建規模化連貫性基建（子專案 C）。
