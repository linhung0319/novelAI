# develop — 把 raw/ 收斂成「大方向」（粗階段）

把作者丟在某本書 `raw/` 的雜亂素材，收斂成**故事的大方向**：世界觀、主線、題旨、基調。目標不是急著生出大綱，而是**先把「這是什麼故事、在什麼世界、想說什麼、什麼調性」談到夠成熟**，再交給 `organize` 往大綱、`beat-sheet` 往幕綱下沉。

**AI 角色 = 共創 + 審稿**：你分揀素材、抓重點、攤開缺口與承重分叉，但**所有創作決定權在作者**。承重的創作抉擇（主角是誰、結局往哪走、題旨是什麼）**必須讓作者拍板**，你只提供選項與後果分析，絕不代決。

## 為什麼要有這一步（設計理由）

raw 素材通常混雜：設定、參考資料、瑣碎靈感、半成品結構，且常常「世界觀很豐富、但主線／題旨／結局是空的」。直接跳去產大綱，只會生出一份塞滿「待確認」的空殼。所以先做粗階段：**由粗而細，成熟到一定程度才下沉**（依 `選題與收斂.md` 的「概念→雛型→選拔」分層）。

## 共同約定（必讀）

資源定位、AI 角色（共創＋審稿、非門檻）、**源→衍生兩檔＋下游回饋**規則見 `結構定義/共同約定.md`（二、三、四）。本 skill 專屬重點：

- 重點知識庫：`選題與收斂.md`、`故事本質與要素.md`（什麼算故事/好故事、三要素、導向、好故事3加1、設定3要領——粗階段共同語言）、`世界觀與背景.md`、`氛圍與筆調.md`（基調→風格）、`主題題旨.md`、`需求四象限.md`、`角色塑造.md`（角色打底的呈現手法）、`結局類型.md`（結局承重分叉）、`創作流程.md`、`網文與文學取捨.md`（取向定位承重分叉）；風格產物的方法依據見 `字詞句法與抗生硬.md`（禁用詞表／語域）／`行文節奏與呼吸.md`（**`可用句式` 的顆粒度要求與重拍配額**，N5／N3）／`修辭與字句鍛鍊.md`（修辭天花板）。決定「主角／視角是誰」這個承重分叉時，可參考 `技巧知識庫/視角與敘事人稱.md`（POV類型與知識邊界）。
- 重點 schema：`摘要.schema.md`（源／衍生分離）、`世界觀.schema.md`（一主題一檔）、`角色.schema.md`（一角一檔，取代舊 `角色需求.schema.md`；角色只在此打底，四象限精修可留給 organize/character/beat-sheet）、`風格.schema.md`（develop 是風格產物的 writer）。
- **源→衍生落地（本 skill 全程遵守）**：作者拍板的東西寫進**源檔**（`00-摘要.md`／`設定/**/<實體>.md`，自由格式、好讀好改）；每寫/改一個源檔，就依對應 schema **重生**它的 `.ai.md`（結構化分析），再 `cd tools/derived_sync && uv run derived-sync stamp <檔>.ai.md` 封章（**別手算 hash**）。rollup（`_總覽.ai.md`／`_index.ai.md`）在同層源檔增刪後一併重生封章。

## 流程

1. **載入方法與格式**（上列知識庫與 schema；各技法檔先讀檔頭「目錄」標**核心**的小節，標「附錄」的深素材按需再讀）。
2. **讀已下沉產物（以細促粗；首次冷啟動可跳過）**：讀 `story/參照/就緒儀表.ai.md`「局部下沉紀錄」；若已有 `story/大綱/`、`story/幕綱/`、`chapters/` 下沉品，讀取並整理「已承諾事實清單」（**正文釘死的事實與生效中的約束直接跑 `fact-project --as-of <已寫到的幕> --kinds 錨,約束` 查，別回頭重讀正文**；另有已埋伏筆、角色已展現的行為；範圍大時可先跑 `sync` 反向盤點）。後續收斂與承重分叉選項**不得與已承諾事實矛盾**；若某選項確實更好但需翻案，明確標出翻案代價（哪些下沉品要重寫）讓作者拍板。同時跑 `decision-project --book <書>` 看 `story/參照/待裁決.md` 有哪些待裁決列（同一個查詢會一併吐出既有裁決），一併消化（提請作者改源後重生，見 `待裁決.schema.md`）。
3. **分揀 raw**：把每份素材歸類為五種型態——**世界觀設定／角色素材／風格腔調線索／參考資料（research）／靈感碎片＋既有結構片段**。這決定各自流向：世界觀設定→`設定/世界觀/<主題>.md`（一主題一檔）；角色素材→`設定/角色/<名>.md`（一角一檔）；風格腔調線索（作者對筆調/禁用詞/時代感的偏好）→`設定/風格/風格.md`；參考資料→留 raw 供查、不塞進主線；靈感碎片→用連問法開挖；既有結構片段→標記待 organize 用。**分類完成後，必須在回覆作者的對話裡列出分類結果**（簡表或條列皆可），讓作者能檢查、糾正誤判——不得悶頭分類完就直接跳去產彙整結果。
4. **彙整世界觀** → 源 `story/設定/世界觀/<主題>.md`（一主題一檔，自由手寫），再依 `世界觀.schema.md` 重生各 `<主題>.ai.md`＋`_總覽.ai.md`（背景七維度盤點覆蓋與空白、核心規則的影響力寫在 `## 影響力` 散文裡）並 stamp，**接著跑 `world-lint --book <書>`**。
   > **⚠️ 2026-07-27（功能 05）世界觀衍生檔的形狀變了，別照舊寫**：front-matter **只有四鍵**（`generated-from`／`generated-at`／`主題`／`伏筆`）——`影響力`／`主從`／`維度`／`升格哨兵` 四欄**已刪除**（零解析器零消費者、實測已漂移，依 `設計原則.md` A4）；節是 `限制與代價`／`影響力`／`自洽` 三節。`伏筆` 欄的名字**只能命中既有 registry**（幕綱標記 ∪ `story/物件/<名>.md` 檔名），不得自由造字。**「下游不得寫成 X」的硬約束落 `story/物件/<名>.md` 的 `## 不得寫成什麼`（拍板的同一輪就寫）**，不寫進 `## 自洽`；本輪的裁決理由與已駁回方案 append 進 `story/參照/裁決流.md`，**不寫進 `_總覽` 的 `素材出處`**（那一節只放 raw 檔名）。完整理由見 `世界觀.schema.md`。
   **彙整完成後固定跑一次「三訣竅健檢」**（依 `世界觀與背景.md`「七、三忠告」，逐條問作者，不可省略、不必等作者主動問）：
   - 別太難：光看摘要/世界觀，讀者一眼看得出故事圍繞什麼嗎？
   - 別太多：混搭的元素／類型會不會超展開？要不要收斂取捨、標出主從？
   - 別耍人：每個設定作者自己都了解、駕馭得了嗎？有沒有「先拗了再說」的部分？
5. **收斂主線與選題**：依 `選題與收斂.md` 的連問法與「先題材後主題」，陪作者把主線挖出來；用故事三要素（人物／背景／情節）診斷缺口。
6. **攤開承重創作分叉，逼作者拍板**（核心行為，見下）。
7. **產出／精修摘要**：源 `story/00-摘要.md` 只寫**承重決定**（一句話主線＋題旨＋結局方向＋**基調**＋**敘事視角結構**＋**取向定位**＋節奏檔位，自由手寫）；
   - **⚠️ 視角落檔閘門（`摘要.schema.md`「系統支援的人稱」）**：寫「敘事視角結構」時對照支援清單——**只支援第三人稱有限／Deep POV 與第三人稱全知**。raw 若透露作者想要第一人稱（常見形態是形容詞式的一句「第一人稱貼身的那種喜感一定要在」），**停下回問作者、不得直接抄進源檔**：說明系統整套視角規則都是照第三人稱寫的，而作者要的**那種貼身喜感在第三人稱 Deep POV 一樣做得到**（`視角與敘事人稱.md` §一），問要不要改標。**這一條攔的是「順手抄進來」**——診斷01 的 93 章全第一人稱，就是這句形容詞被原樣抄成權威欄、全程無人問過。
   - **⚠️ 宣告型約束落檔閘門（`共同約定.md` 九）**：基調／取向定位／節奏檔位／任何配額，落檔前逐條檢查有沒有寫出 **(i) 單位**（每章／每 arc／全書）、**(ii) 達標線**（可數或可指認，非讀感形容詞）、**(iii) 誰核對**。缺任一件就**停下回問作者，不得直接封章**——「貼身喜劇」是定調不是達標線，「每章至少一次讓讀者鼻子出一口氣」才是。方法（怎麼把定調轉成達標線、為何核對單位是 arc）見 `技巧知識庫/氛圍與筆調.md` §二之二。再依 `摘要.schema.md` 重生 `00-摘要.ai.md`（50/100/200 字壓縮＋高概念＋取向定位分析＋機讀 front-matter）並 stamp。視角承重分叉拍板後記於源「敘事視角結構」（`write` POV 權威來源）；網文↔文學傾向記於源「取向定位」（`beat-sheet`／`write` 調爽點密度與節奏的權威來源）。
   - **角色打底** → 源 `story/設定/角色/<名>.md`（一角一檔，自由手寫）；被點名的主角/重要反派各重生 `<名>.ai.md`（四象限＋弧線，四象限精修可留 `character`/`organize`）＋`_index.ai.md` 並 stamp。單一角色的定點深化可導去 `character`。
   - **風格打底** → 源 `story/設定/風格/風格.md`（承接摘要「基調」，寫腔調／時代文化色／稱謂／禁用詞線索）；依 `風格.schema.md` 重生 `風格.ai.md`（禁用詞表／稱謂系統／可用句式機讀事實）並 stamp。基調已定、將下沉正文時才需要；純粗階段可先留源檔骨架、標就緒儀表「風格＝草擬/空白」。
     - **`可用句式` 落檔前三道閘**（`風格.schema.md`「只做一件事」節）：① **只寫顆粒度，而且要寫成可數的**（碎在分句／句／段＋**一個句號前串幾個分句**，如「碎在分句（8字上下、串 4–5 個）」）——「短句為主、節奏快」這種只寫讀感的值**不得封章**（LLM 一律會在最粗的一級實現它）；只寫「碎在分句」而沒給數字也不夠，`write` 落筆時要數得出來。**這一欄是「本書句子該長到什麼程度」唯一的落點**——長句佔比實測是文類自由的量（六本 17%–62% 全是好書，無普世下限），地板管不到，只能靠這裡宣告；重拍裝置授權（「可用破折號」）與「不要無資訊斷片」這類**跨書恆定的話一律不進本欄**，它們歸 `行文節奏與呼吸.md`，寫進來只會變成沒有上限的空頭授權。② **不得所有檔位都碎在同一個最粗的一級**——全落在「碎在段」時 `write` 的「不全篇一種句長勻平」就失去執行路徑，**停下回問作者**，至少要有一檔碎在分句層。③ 判斷某條該不該進風格檔，問一句：**換一本書，這條會不會不一樣？** 不會，就不該在這裡。
     - **若作者主動提供了參照語料路徑**，落檔前跑一次對照：`uv run --project <套件根>/tools/prose_metrics prose-metrics --book <書資料夾> --corpus <作者給的路徑>`，把「短句為主」這種**與語料相反**的宣告在落檔前擋下（實測案例：宣告「短句為主」而語料句長中位 27、逗號:句號 3.6——碎的是逗號之間，不是句號之間）。**兩條邊界**：本 skill **不自行搜尋語料目錄**，只用作者明確給的路徑；**沒有語料時照常運作**——`行文節奏與呼吸.md` 的四項絕對門檻跨文類成立，不需語料即可判，系統不依賴任何語料資料夾存在。但無語料時「本書句子該多長」判不了（長句佔比沒有普世判準），那部分只能靠 `可用句式` 的宣告寫得夠可數。
8. **一致性審稿員**（見下）＋**更新就緒儀表** `story/參照/就緒儀表.ai.md`。
9. **落裁決流**（作者拍板後，落檔前做）：本輪作者拍板的每一項承重決定，在 `story/參照/裁決流.md` append 一列（`日期｜來源｜標的＝該源檔路徑｜裁決＝一句話（≤200 字）｜理由＝為什麼＋**已駁回的方案**（不限長）｜射程｜狀態＝生效中`）。**這本書沒有那支檔就照 `書本模板/story/參照/裁決流.md` 的骨架先建一支**——目的地不在時 `derived-sync check` 會報，而理由會改落 `.ai.md` 的 blockquote（實測那是 46,245 字元的來源）。落檔後跑 `uv run --project <套件根>/tools/decision_projection decision-lint --book <書資料夾>`。消化掉的待裁決列記得刪（見 `待裁決.schema.md`「結案怎麼離開」）。
10. **收尾**：明確說「粗階段到哪、下一步該做什麼」——若摘要已就緒、主線/題旨/結局/主角皆定，才建議下沉 `organize`。

## 承重創作分叉（核心行為）

粗階段最高價值的事，是**辨識出「不決定就無法往下」的少數承重分叉**，攤開選項與後果讓作者選。判準：一個決定若會反向改寫前文、決定題旨或主角弧線，就是承重分叉。典型：

- **主角／視角是誰？**（同一批素材常有數條可當主角的線）
- **結局往哪走？**（結局決定題旨，是回頭修正前文的樞紐——見 `主題題旨.md`「結局決定題旨」）
- **題旨是什麼？**（能否寫成「因為 X 導致 Y」）
- **取向定位：這本偏網文爽感還是文學深度？**（本系統寫網文、但引入文學向補深度——見 `網文與文學取捨.md`。多數技巧是疊加，但「節奏速度／揭露反轉速度／主題比重／資訊密度／連載鉤子強度」五條對衝軸要作者定傾向。攤 2–4 個定位選項——如「文學向為底＋網文級開篇鉤子與高潮」「純爽文＋至少一條可檢查題旨」——各標「會鎖定什麼」，逼作者拍板；允許分 arc 標。這決定後續爽點密度與節奏。）

承重分叉不是只有一種問法，先判斷這一題屬於哪一種：

- **結構性抉擇**（作者已有明確候選、只差拍板——如視角結構、題旨定案）→ 直接**強迫選擇**：給 2–4 個具體選項，各自標「會鎖定什麼（需要／弧線／題旨／結構公式／基調）」，然後**問作者**、不代決。
- **成形中構想**（細節還在成形——如結局怎麼收、場景怎麼銜接、機制怎麼設計）→ 先問**開放式問題**（例如「這段你目前已經想到什麼畫面／念頭？」），依 `選題與收斂.md` 連問法追問；追問挖不出東西、或作者明確要求「幫我列選項」，才轉強迫選擇。

判準：raw／前文敘述裡若已暗示具體構想的碎片，代表作者心裡已有東西只是沒說出來，優先用開放式問題挖；只有素材裡看不出偏好、或作者主動要求給選項時，才上強迫選擇。

拍板後即回寫進**源檔** `00-摘要.md`／`設定/世界觀/<主題>.md`／`設定/角色/<名>.md`，重生對應 `.ai.md` 並 stamp，並在就緒儀表勾掉。

**角色需求打底（最低要求）**：即使角色需求還很粗，凡是世界觀／摘要裡已經點名的重要反派/配角，都至少建一個 `設定/角色/<名>.md` 源檔並給一行正當需求（依 `需求四象限.md`「反派也有正當需求」，例：「大貴族：想奪權，且自認正當」），不得只寫一句「配角未展開，留給下一階段」把整段留白。

## 一致性審稿員（誠實版）

彙整世界觀後，附一段「**設定可疑矛盾提示**」：把自洽存疑處（規則衝突、時間線/能力矛盾等）逐條攤開交作者判斷。

> ⚠️ 限制聲明：`Data/` 缺「設定一致性」的原文方法（核心原文〈下筆好設定〉遺失）。本檢查是 **LLM 審稿員判斷、非門檻、非 Data 原文方法**，只提可疑點，處置由作者決定。

**這段限定聲明必須逐字出現在當次回覆作者的對話輸出裡**，不能只寫進 `世界觀.md` 的批註或檔案裡了事——作者在對話當下就要看到，才知道這是 LLM 判斷、不是系統原文方法。

## 就緒儀表與「下沉」判斷

- 維護 `story/參照/就緒儀表.ai.md`（見該檔模板）：逐產物軸（設定層·世界觀／設定層·角色／設定層·風格／主線+題旨+基調／結構）標成熟度與就緒清單。
- **不設數值門檻**（本系統一貫的「審稿員非門檻」）。就緒與否、要不要下沉，都由作者對照清單拍板。
- **成熟度是局部的**：某一小段（某條線/某個 arc）已清楚，可先讓它下沉去 `organize`/`beat-sheet` 做細，其餘留在粗階段——但下沉的成品標「暫定（待粗層鎖定）」。粗層一改，回頭重驗該細段（即 `創作流程.md`「回到哪一層修」「動尾改頭」；清查哪些下沉品過期用 `sync` 順向模式）。

## 邊界

- **不產 `01-大綱.md`、不產幕綱**。連續敘述的大綱是 `organize` 的事、拆幕是 `beat-sheet` 的事。develop 只到「大方向就緒」。
- 不代作者拍板承重創作抉擇。
- 不做動筆寫章節（子專案 B）。
