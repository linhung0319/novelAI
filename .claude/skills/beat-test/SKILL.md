# beat-test — 幕綱測試（審稿員）

對幕綱跑 9 項結構不變量測試，把可疑點攤開讓作者判斷。這是本系統的核心價值：在**幕綱層**抓問題，等同在設計評審抓 bug，而非等成品散文才發現。

**定位聲明**：小說測試是模糊、需判斷的。本 skill 是 LLM 判斷型「審稿員」，不做自動 pass/fail，處置由作者決定——資源定位與其餘共通規則見 `結構定義/共同約定.md`（必讀）。

## 測試對象

`story/幕綱/`、`story/參照/`。可由作者指定只測某個 arc 範圍。

> **跨 arc 的 `[[幕NNN]]` 存在性不必再靠整批讀檔解析**（2026-07-27 改）。舊版要求「範圍內的幕若引用範圍外的編號，仍需一併讀取該編號所在的其他 arc 檔案以解析存在性」——那與本檔步驟 2、`共同約定.md` 八的「別為了配對而整批讀 arc 檔」直接衝突，而且它是**確定性工作卻交給 LLM 手做**。現在走 `beat-lint`（步驟 0），它一次掃全書、報出每一條懸空前因。

## 9 項測試

每項標明「機械可抽取部分」（確定性檢查連結標記）與「LLM 判語意部分」，及基準知識庫。

| # | 測試 | 檢查什麼 | 機械 vs LLM | 基準 |

| 1 | **因果連續性** | 每幕「結果」是否催發下一幕動機；有因無果／有果無因的孤兒；未連主線的幕 | 抽取 `[[幕NNN]]` 前因鏈（機械）＋ 判結果是否「有意義地」催發下一幕（LLM） | `因果法則.md` |
| 2 | **伏筆閉合** | 每個 `埋[[伏筆:x]]` 是否有後續 `收[[伏筆:x]]`；結尾有無懸空線；若涉及誤導/反轉，是否構成合理的雙重誤導（謎三角：誤導→假真相→真真相）而非隨意反轉；意外的發生是否源自主角努力（非機器神）。若幕綱檔尾有「本 arc 伏筆狀態」表誠實列出跨 arc／全書懸念，該筆列為資訊、不算可疑點——但表中標 `arcNN（未拆）` 的那一端以「該 arc 在 `_index.md` 仍未拆」為前提，該 arc 已拆而未回填幕號者是可疑點。**另核對 `story/物件/*.md` 的 `揭示層級` 欄是否各自解析得到 `收[[伏筆:x]]`** | 掃描並配對 `埋`/`收` 標記、解析揭示層級（機械，確定性）＋ 判回收品質、誤導合理性、是否機器神（LLM） | `伏筆與意外.md`（伏筆閉合／謎三角雙重誤導／機器神／紅鯡魚三種誤導）、`幕綱.schema.md`（本 arc 伏筆狀態表）、`共同約定.md` 六＋`物件.schema.md`（揭示層級） |

| 7 | **設定揭露節奏（設計層）** | (a) **設定傾倒幕**：範圍內有沒有幕的「行動／衝突」欄實質是「解釋世界規則／交代設定」而**無戲劇動作**（讀者只是被告知，主角沒在做什麼）？這種純說明幕是「旁白說明書」的幕綱層根源。(b) **疑問回收時點**：讀者在前期會問的**核心疑問**（主角組織是什麼／為何被追／某世界謎），幕綱有沒有排到**可指認的回收幕**，還是懸空到底或一次倒完？已標記為 `埋/收[[伏筆:x]]` 的走測試2；本項專抓**未被標成伏筆、卻是讀者核心疑問**的那些設定謎。**與測試3的邊界**：測試3問「結構階段齊不齊」，測試7問「設定/謎的揭露是否被排成漸進、有無傾倒幕與懸空疑問」。**渲染層對應**（散文實際怎麼端出設定：旁白傾倒／專名過載）在 `write-test` 測試11——設計層排對了、渲染仍可能傾倒，反之亦然 | 無乾淨機械抽取；LLM 讀各幕「行動/衝突」欄判有無「純解釋、零動作」的傾倒幕；並列出前期拋出的核心疑問，往後找有沒有對應的回收幕（對照衍生 `00-摘要.ai.md` 的 `主線` 欄與 `伏筆與意外.md` 距離配置） | `世界觀與背景.md` §九（設定帶出的操作判準：由動作/對話逼出·先現象後定義·疑問回收時點）、`網文與文學取捨.md`（揭露速度對衝軸）、`伏筆與意外.md`（回收距離） |
| 8 | **節奏檔位與資訊差引擎（段落張力供能）** | 讀 **`story/幕綱/arcNN.md` 檔頭**宣告的節奏檔位（開頭段／常態段）。⚠️ **2026-07-27（功能 08 抉擇 2）起摘要不再存這一項**：摘要那一份實測只覆蓋 1/11 arc（`{ 卷一: 開頭段 }`），而 8/11 支 arc 各自在檔頭宣告了不同檔位——**權威一直在檔頭，摘要那一份是外移後留下的殘骸**，照字面讀會以為「這本書現在還在開頭段」。⚠️ **檔頭本身零格式、零 lint**（實測 arc02／arc03 兩支根本沒寫），所以本項讀不到宣告是常態——**未標檔位不扣分，報「不適用」**，不要回頭去摘要找。(a) **檔位一致性**：本 arc 的幕綱是否與其宣告檔位相稱——開頭段是否幾乎每幕一個轉折／一次變強（別慢熱到讀者不知發生什麼）；常態段是否靠一條長線大謎悶燒、章末鉤降級、**不強求每幕大高潮**（別把開篇緊繃硬套常態段導致疲乏）。(b) **資訊差引擎**：本 arc 的張力是否有可指認的資訊差來源（同步懸念／優越·扮豬吃虎／替他捏汗），還是**資訊全平攤、無落差＝無張力**？未標檔位不扣分，只在標了卻明顯不符、或整段張力無資訊差引擎在驅動時標可疑。**與測試6的邊界**：測試6 管「單一賭注是否兌現」（點）；測試8 管「整段靠什麼供能、節奏檔位對不對」（面） | 無乾淨機械抽取；LLM 讀本 arc 全幕，對照**該 arc 檔頭**宣告的檔位判相稱性，並定位本段主張力的資訊差類型（誰知道什麼）；資訊全平攤、或檔位錯位即標 | `戲劇張力與懸念.md` §一（資訊差引擎：同步/優越·扮豬吃虎/替他捏汗）§六(d)（開頭vs常態兩檔位）、`幕綱.schema.md`（arc 檔頭）、`網文與文學取捨.md`（連載鉤子強度） |
| 9 | **幕的可演性（反空洞）** | 這一段幕綱有沒有東西可以演。五子項：(a) **行動欄可演性**——有沒有幕的「行動」欄只寫了主題陳述／結構功能／讀者效果／元管理標籤（`幕綱.schema.md`「八欄只寫故事事實」四類），而沒有任何鏡頭拍得到的行為？(b) **純內在幕**——本 arc「主角獨處、無對手在場」的幕有幾個？(c) **連續空洞幕**——有無連續兩幕以上皆為空洞幕？(d) **分區衛生**：設計理由（母題論證／判例／拍板記錄）是留在檔尾設計註，還是滲進了承諾區與八欄？(e) **母題自我複製與行動欄膨脹**（診斷01 P10）——同幾句母題語彙在每一幕被複述、行動欄逐 arc 膨脹？`write` 抄的是欄位，複述會被原樣散文化進正文。<br>⚠️ **可疑點判在 (a)∧(b)，不判在 (b) 單獨**：主角一個人在場**不是**病，一個人在場**而且行動欄沒有東西可拍**才是。實測 arc01 有 2 幕主角獨處（入定修行、被什麼遠遠掃過）——兩幕都健康；診斷02 §3 原記「arc01＝0/9」是手數的誤差。工具因此把「空洞幕」（獨處∧行動欄命中禁止詞）當可疑點，純內在幕只當資訊列。**為什麼要有這一項**：系統其餘測試全是「反矛盾」（罰做錯），沒有一項「反空洞」（罰什麼都不做）——在只有負向約束的系統裡，最安全的產出就是最空的產出。**與測試7的邊界**：測試7(a) 抓的是「純解釋**世界規則**」的設定傾倒幕；本項抓的是「純陳述**主題／結構功能**」與「主角一個人在想事情」的空洞幕——兩者都無戲劇動作，但來源不同、修法不同 | **機械走工具、別自己數**：`uv run --project <套件根>/tools/beat_metrics beat-metrics --book <書資料夾> [--arc arcNN] [--detail]`——五個子項全部由它算出（零 LLM、可覆算），**門檻（供排序，非 pass/fail）**：空洞幕 > 1/3、連續空洞 ≥2 幕、分區衛生命中、母題重複率／行動欄長度 > 本書前段基準 3 倍。(e) 的判準**相對本書自己的前段**（同 `prose-metrics` 漂移），不設絕對門檻——絕對值是書/文類相依的 ＋ LLM：複核機械候選是否真的無可演內容（收點餘韻幕、Sequel 型過渡幕**單獨一幕**是合法的，連續多幕或整段如此才是病），並判該幕缺的是外顯載體還是根本該併進鄰幕；(e) 讀 `--detail` 的熱詞，判那幾句母題複述是**本 arc 真的在演這件事**還是**每一幕都在複誦同一句宣告** | `場景與情節推進.md` 二（Scene Goal 須具體可觀察）、`幕綱.schema.md`（八欄只寫故事事實／arc 檔的內部結構）、`共同約定.md` 七（承諾與演出） |

## 執行步驟

0. **先過格式閘門**：`uv run --project <套件根>/tools/beat_metrics beat-lint --book <書資料夾>`（全書，不分 arc——幕號唯一性、`前因` 跨 arc 存在性、spine 涵蓋性本來就只有全書尺度才判得了）。
   - **懸空前因由它報，不要自己用眼睛掃。** 這一項曾經寫成「最高優先級的機械事實，不需 LLM 判斷」卻**沒有任何工具在做**——讀的人以為工具接手了、於是不看，而實際上只有那次 beat-test 的 LLM 手掃。一世之尊 157 條引用 0 懸空是人手維持的乾淨，不是系統保證的（`設計原則.md` E2 第五格）。
   - 它同時報：幕號重複／跳出預配號段、八欄缺欄或留白、`全書順序：` 漏列 arc、缺 `## 本 arc 承諾`、伏筆近似名、設計註沒有搬移目的地。
   - **把它的「檢查範圍：…」那行照抄進報告總覽**（0 也印）。它回答的是「我檢查了幾筆」，不是「我發現幾個問題」——後者單獨存在時，守衛自己被關掉會印成「乾淨」。
   - 閘門報的是**格式**，不是內容：它不判因果成不成立、伏筆收得好不好、幕有沒有東西可演（那是下面 9 項），也**不判孤兒幕**（`前因：—` 是合法值，非首幕卻沒有前因屬測試1 的語意判斷）。
   - **同一步再跑一次結構軸投影**（測試3 的硬事實）：`uv run --project <套件根>/tools/beat_metrics structure-project --book <書資料夾> [--arc arcNN]`。它印大綱宣告的選用公式、階段 ↔ 幕 對應表、**缺哪個必要階段與階段序非遞增**（機械集合差，對照 `技巧知識庫/結構公式.md` 的 registry），以及「幾幕的 `結構階段` 欄不以頂層階段 token 起頭」。**它是投影不是閘門**（exit 0），覆蓋率行照樣照抄進報告總覽。
     > 這一項十天來寫成「LLM 對照 `story/參照/結構.ai.md`」，而那支手抄表**與幕綱已經漂移**（實測某本書 105 幕可比對、1 幕矛盾，活了六天沒人發現）。**那支檔 2026-07-28 廢除**，對應表現在是重算出來的，沒有第二份可以漂。
1. 讀幕綱（指定 arc 或全書，**含各 arc 檔頭的節奏檔位宣告**）與 `story/參照/`、`story/設定/{世界觀,角色}/*.ai.md`；**摘要軸兩支都讀**——源 `story/00-摘要.md`（承重決定的散文與理由，整檔讀）＋衍生 `00-摘要.ai.md`（**六個語意欄**`主線`／`題旨`／`基調`／`視角結構`／`取向定位`／`貫穿大懸念` ＋取向定位分析）。**權威在那六欄**，源檔給的是理由——不要在源檔裡「取某一欄」（自由源沒有欄）。
2. **先做機械抽取**：列出所有 `[[幕NNN]]` 前因鏈、所有 `埋/收[[伏筆:x]]` 配對狀態——這部分是確定性的，先報硬事實（如「伏筆:封脈之術 有埋無收」）。
   - **伏筆配對走工具、不要自己讀檔配對**（`共同約定.md` 八）：
     `uv run --project <套件根>/tools/foreshadow_project foreshadow-project --book <書資料夾> [--arc arcNN]`
     它跨全部 arc 掃描配對、依 `_index.md`「全書順序」定序（**不比幕號大小**）、只認幕的「伏筆」欄為標記來源、解析揭示層級、核對 `arcNN（未拆）` 是否到期，並把「狀態表內出現字面標記」這類會污染掃描的寫法報成 violation。**下面幾個 bullet 描述的正是它已經做掉的事**——保留是為了讓你看懂它的輸出怎麼判，不是要你手做一遍。**別為了配對伏筆而整批讀 arc 檔。**配對 `埋`/`收` 標記時，若命中的伏筆同時出現在該 arc 檔尾「本 arc 伏筆狀態」表，仍列出但標記「資訊，非可疑點」，避免重複回報已知的刻意留白。
   - **`arcNN（未拆）` 到期核對**（同屬機械事實）：「本 arc 伏筆狀態」表的「埋設幕」或「收回」欄若填 `arcNN（未拆）`，查 `幕綱/_index.md` 該 arc 是否仍未拆。仍未拆 → 資訊；**已拆出幕號、該欄卻還沒回填實際幕號 → 可疑點「跨 arc 待補已到期」**（該 arc 下沉時漏了回補，見 `幕綱.schema.md`「本 arc 伏筆狀態」）。
   - 掃 `埋`/`收` 標記時只認幕的「伏筆」欄；「本 arc 伏筆狀態」表是視圖，其四欄提到伏筆時只寫純文字（見 `幕綱.schema.md`）。表格內若出現字面 `埋[[伏筆:x]]`／`收[[伏筆:x]]`，那不是埋設點——照它配對會把還沒埋的伏筆誤判成已閉合。
   - **可演性與母題統計走工具、不要自己讀檔數**（`共同約定.md` 八）：
     `uv run --project <套件根>/tools/beat_metrics beat-metrics --book <書資料夾> [--arc arcNN] [--detail]`
     它逐 arc 算出**空洞幕**（角色欄僅主角一人 ∧ 行動欄命中禁止清單詞式）、純內在幕、連續空洞段、分區衛生（八欄裡的元管理字樣）、**母題重複率**與**行動欄均長**，並把後兩者對照本書前段基準判漂移。**別為了數這幾個數字而整批讀 arc 檔。**
     - **注意它報的可疑點是「空洞幕」不是「純內在幕」**：純內在幕只是資訊列。實測 arc01 有 2 幕主角獨處而兩幕都健康——**獨處＋行動欄有東西可拍是好幕**，別拿純內在幕的數字去要求作者改。
     - 工具只出數字與候選；判「這一幕缺的是外顯載體還是該併進鄰幕」是步驟3 的事。**這一項的價值就在於前半不需要語意判斷即可成立。**
   - **揭示層級解析**（同屬機械事實，`foreshadow-project` 已做掉）：它掃 `story/物件/*.md` 的 `揭示層級` 欄，逐一核對指向的伏筆名在幕綱裡是否找得到 `收[[伏筆:x]]`。四種結果：找到 → 「揭示於 幕NNN」（資訊）；找不到、但該伏筆已埋或還有 arc 未拆 → 「揭示點待落幕」（**資訊、非可疑點**，見 `共同約定.md` 六）；「跨集留白」→ 資訊；**指向一個全書幕綱都不存在、又無未拆 arc 可解釋的名字，或語法根本解析不了 → 可疑點**。
     - **它的輸出一律有「掃到 N 處／解析 N 處／待落幕 N 處／無法解析 N 處」四個數字，直接照抄進報告總覽。** 這一行是刻意加的：舊版只印可疑點，而可疑點是從**已解析的**標記裡挑出來的，於是實測 92 處出現、91 處連標記都不算時，它印的是「0 條為可疑點」exit 0（見 `設計原則.md` E2 第五格）。**看到「無法解析 N 處」不是 0 就要追**。
     - **設定層 `.ai.md` 裡還有 🧊 → 報「落點已廢除」**（可疑點）：揭示層級只住物件檔，寫在會被重生的衍生檔裡下次重生就沒了。
3. **再做 LLM 語意判斷**：對照各基準知識庫的**所引小節**（依各檔檔頭「目錄」定位到對應 §，不需整檔通讀；附錄小節按需才讀），逐項找可疑點。
4. 輸出報告（見下），並**落兩處**：
   - **測試執行紀錄**寫進該 arc 幕綱檔**檔頭**的一行 `beat-test: YYYY-MM-DD·N高N中N低`（一支 arc 一行，重跑就覆寫；形狀由 `beat-lint` 守，見 `幕綱.schema.md`「測試執行紀錄」）。**這一步不做，那個欄永遠是空的**——讀它的是 `write` 動筆前的就緒提醒與 `readiness` 第 3 節。
   - **成熟度**更新 `story/參照/就緒.md` 的「幕綱」欄（**五個 token 之一**；理由 append 進 `story/參照/裁決流.md`）。落檔後跑 `uv run --project <套件根>/tools/derived_sync readiness-lint --book <書>`。

## 輸出格式

每個可疑點一列：

```
幕 id ｜ 測試類型 ｜ 嚴重度 ｜ 說明 ｜ 建議修正 ｜ 建議回寫位置
```

- **嚴重度**：高／中／低（僅供作者排序參考，非門檻）。
- **建議回寫位置**：通常填「—」（問題就在幕綱本身，幕綱是作者利器·直改）；只有判定問題根源在角色本身設計（而非幕排序）時填 `設定/角色/<名>.md`（若問題其實是「正文已釘死的事實」或「下游不得寫成 X」，那屬 事實軸——`錨` 屬該章 `chNNNN.ai.md` 的 `## 本章事實`、`約束` 屬 `story/物件/<實體>.md` 的「## 不得寫成什麼」，別往角色衍生檔塞），判定根源在摘要題旨/立場未收斂時填 `00-摘要.md`——依 `結構定義/待裁決.schema.md` 格式在 `story/參照/待裁決.md` 追加一列（`標的` 欄就寫這個源檔路徑）。
- 範例：
  - `幕023 ｜ 伏筆閉合 ｜ 高 ｜ 埋[[伏筆:封脈之術]] 全書未見收 ｜ 於結局前補一幕回收，或刪除此埋設 ｜ —`
  - `幕017 ｜ 因果連續性 ｜ 中 ｜ 結果「主角睡了一覺」未催發下一幕，疑似孤兒 ｜ 改為有意義的結果，或併入鄰幕 ｜ —`
  - `幕011 ｜ 因果連續性 ｜ 高 ｜ 被[[幕011]]引用（如某幕前因）但未在任何 arc 找到對應小節（**由 beat-lint 報出，非人眼掃**） ｜ 補上幕011，或修正引用改指正確幕號 ｜ —`
  - `物件/古井之約.md ｜ 伏筆閉合（揭示層級） ｜ 中 ｜ `揭示層級` 指向 收[[伏筆:古井之約]]，但全書幕綱無此伏筆名、亦無未拆 arc 可解釋 ｜ 改物件檔那一欄的伏筆名，或確認該伏筆是否已被刪除 ｜ —`

## 邊界

- 不自動修改幕綱（除非作者要求後另行進行）。
- MVP 在主 session 執行；若日後全書測試 context 過大，再考慮改為獨立 subagent（非本階段範圍）。
