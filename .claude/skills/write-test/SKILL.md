# write-test — 正文測試（審稿員）

對已寫成的章節正文跑 11 項檢查，把可疑點攤開讓作者判斷。這是 `write` 的審稿搭檔：`write` 負責「從無到有」把幕綱展開成散文，`write-test` 負責回頭核對這份散文有沒有漏幕、有沒有 POV 跳脫、有沒有該展示卻用了講述、基調有沒有跑掉、節奏與取向定位合不合、分章邊界合不合理、有沒有把承重事件摘要進子句而讀者沒經歷到（跳躍）、句子本身有沒有生硬／翻譯腔或反過來太碎（短句斷句、每隔幾行煞一次車）、新設定是不是靠旁白說明書突然蹦出（而非由動作／對話逼出）——比照 `beat-test`（審幕綱）／`outline-test`（審大綱），補齊子專案 B 的檢測層。

**定位聲明**：正文測試是模糊、需判斷的。本 skill 是 LLM 判斷型「審稿員」，不做自動 pass/fail，處置由作者決定——資源定位與其餘共通規則見 `結構定義/共同約定.md`（必讀）。

## 測試對象

`chapters/`（正文源 `chNNNN.md`＋衍生 `chNNNN.ai.md`）、`story/幕綱/`、`story/設定/`、`story/參照/`。作者可指定測試範圍：
  - **指定 arc**：反查 `chapters/_index.ai.md`「所屬 arc」欄，展開為該 arc 已寫成的 chNNNN 範圍。
  - **直接指定 chNNNN 範圍**：如「測 ch0001–ch0002」或單一章「測 ch0003」。
  - 若指定範圍在 `chapters/_index.ai.md` 找不到對應已寫章節 → 回報「這個範圍還沒有正文」，建議先跑 `write`；不得對不存在的章節杜撰檢查結果。

每項標明「機械可抽取部分」（確定性檢查）與「LLM 判語意部分」，及基準知識庫。對應 `結構定義/章節.schema.md`「檢查點（供未來 write-test 參照）」一節列出的項目。

## 執行步驟

1. **讀輸入**：
   - 依作者指定的 arc（反查 `chapters/_index.ai.md`「所屬 arc」欄展開為 chNNNN 範圍）或直接指定的 chNNNN 範圍，讀對應正文源 `chapters/chNNNN.md`＋衍生 `chNNNN.ai.md`（對應幕/POV/基調參照/風格）。
   - 讀取範圍涵蓋之幕所在的 `story/幕綱/arcNN.md`（若章節「對應幕」有 `[[幕NNN]]` 引用到範圍外/跨 arc 的編號，一併讀取解析，比照 `beat-test` 的跨 arc 讀取規則）。
   - 讀源 `story/00-摘要.md`（基調／題旨）＋衍生 `00-摘要.ai.md`（取向定位分析）、`story/參照/結構.ai.md`（分章合理性判準）；**風格軸兩支都讀**——源 `story/設定/風格/風格.md`（腔調・時代文化色的判準理由，供測試5 判筆調轉調）＋各章 `風格.ai.md` 的五欄（禁用詞表/稱謂/句式/語域/基調參照，供測試5/10）。**衍生檔 2026-07-27 起沒有本體**（那四節是源檔的同長度改寫，已廢除），腔調要讀就讀源檔。
   - **設定層走選取、不整批讀**（`共同約定.md` 八）：
     `uv run --project <套件根>/tools/settings_select settings-select --book <書資料夾> --arc arcNN`
     只讀它列出的角色／世界觀 `.ai.md`（供判斷角色內心戲、動機呈現是否越界，及測試9 的上游比對）。**不要 `設定/角色/*.ai.md` 全撈。**
   - 讀 `chapters/_index.ai.md` 確認指定範圍確有對應已寫章節；找不到 → **停下**，說明「這個範圍還沒有正文」，建議先跑 `write`。
2. **先做機械抽取**：
   - **正文結構統計＋跨 arc 漂移**（供測試7(b)，**全書範圍、不隨 scoped 縮小**）：
     `uv run --project <套件根>/tools/prose_metrics prose-metrics --book <書資料夾> [--per-chapter]`
     零 LLM，出逐 arc 的「字/章、引號/千字、人/章、獨白章佔比」與相對本書前段的漂移可疑點。**判準是相對的**（拿這本書自己的前段當基準），故不依賴文類。**先報這些硬數字，再由 LLM 判它是設計還是退化。**
   - **正文層格式閘門**（供測試1／2，**這一項不再由 LLM 逐章做集合差**）：
     `uv run --project <套件根>/tools/beat_metrics ch-lint --book <書資料夾>`
     零 LLM、可覆算。它做完整的差集（**宣告涵蓋卻無錨點**＝漏幕、**有錨點卻不在宣告範圍**＝越界）＋幕號存在性、章內單調、一幕不跨章、過渡錨點兩端、`--- 幕NNN ---` 人性寫法殘留、front-matter 六鍵（含 `POV`／`基調參照`／`風格` 非空，供測試2／5）、`_index.ai.md` 的視圖一致性與備註欄。**它報的每一條都是確定性事實，直接照抄進報告，不要複判**；LLM 只做測試1 剩下的那半（錨點段落是否掛名湊數）。
     **開頭那行「檢查範圍」要看**：它印幾章正文源／**幾個幕錨點**／幾支章衍生／幾列章序。印 0 個幕錨點不是乾淨，是它沒讀到檔（`設計原則.md` E2）。
   - 逐章掃描過濾詞候選句，列成清單（附上下文，供步驟3複核，非直接判定為問題）。
   - **解說段候選**（供測試8）：上面那一次 `prose-metrics --book` 呼叫**同時**已出「解說段（R4·段落級）」逐 arc 密度與漂移可疑點；要逐條複核時加旗標取受測範圍的段落全文：
     `uv run --project <套件根>/tools/prose_metrics prose-metrics --book <書資料夾> --exposition-list --range chNNNN-chNNNN`

   - 逐章掃描「事件塞子句」候選（承重動詞落在時間狀語/從屬子句），列成清單（附上下文，供步驟3複核，非直接判定為問題）——供測試8。
   - 逐章掃描 **M7 生硬病徵候選**（供測試10(a)，附上下文、非直接判定）：名詞化「進行/作出/使得/得以/造成＋抽象名詞」、被動「被…所…」、翻譯腔連接「當…的時候／由於…而／儘管…但是／隨著…」、的的不休（連續三個以上「…的…的…的X」）、句首情緒副詞＋動作（「他殘忍地／驚恐地…」）。

## 輸出格式

每個可疑點一列：

```
章 id ｜ 測試類型 ｜ 嚴重度 ｜ 說明 ｜ 建議修正 ｜ 建議回寫位置
```

- **嚴重度**：高／中／低（僅供作者排序參考，非門檻）。
- **建議回寫位置**：通常填「—」（問題就在章節正文本身，作者直接改文字即可）；若判定問題根源其實在幕綱本身（如分章邊界追溯到幕綱結構階段誤置、或幕涵蓋缺口其實是幕綱本身漏了一幕、或測試8 的賭注根本沒在幕綱兌現）→ 仍填「—」，但「建議修正」註明「建議作者直接修改幕綱或重跑 beat-test（測試6）」（幕綱是作者利器·直改、無待裁決列，不可代寫，見 `章節.schema.md`／`write` skill 步驟10邏輯）；若追溯到**設定層或摘要的源檔** `設定/世界觀/<主題>.md`／`00-摘要.md`／`設定/角色/<名>.md`（**測試9 判承重的細節即屬此類**）→ 填該源檔路徑，並依 `結構定義/待裁決.schema.md` 格式在 `story/參照/待裁決.md` 追加一列（測試9 來源標「write-test 測試9（chNNNN）」）。
