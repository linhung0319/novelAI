# outline-test — 大綱測試（審稿員）

對摘要與大綱跑 6 項結構不變量測試，把可疑點攤開讓作者判斷。這是補齊「檢測層不對稱」的一塊：`beat-test` 只審幕綱層，摘要／大綱層的檢查點雖然 schema 早就定義好了，卻一直沒有執行者——本 skill 就是那個執行者。

**定位聲明**：大綱測試是模糊、需判斷的。本 skill 是 LLM 判斷型「審稿員」，不做自動 pass/fail，處置由作者決定——資源定位與其餘共通規則見 `結構定義/共同約定.md`（必讀）。

## 測試對象

**摘要軸兩支都讀**——源 `story/00-摘要.md`（承重決定的散文與理由，整檔讀）＋衍生 `story/00-摘要.ai.md`（**六個語意欄**`主線`／`題旨`／`基調`／`視角結構`／`取向定位`／`貫穿大懸念` ＋50/100/200 字壓縮＋取向定位分析）；**權威在那六欄**（它們有 `summary-lint`），源檔給的是理由。另讀 `story/01-大綱.md`（或 `story/大綱/arcNN.md`）——**選用結構公式與 α 就在它的 `## 選用結構公式` 節**（`story/參照/結構.ai.md` 2026-07-28 廢除，階段 ↔ 幕 對應改跑 `structure-project`）。可由作者指定只測某個 arc（讀對應的 `story/大綱/arcNN.md`）；未指定時預設測全書 `story/01-大綱.md`（若存在）。若兩者皆不存在，回報「尚無可測的大綱」，建議先跑 `organize`。（測試5 壓縮一致的四段壓縮讀 `00-摘要.ai.md`；若它報 stale，代表源改過未重生，先提示回 `organize`/`develop` 重生再測。）

> **`01-大綱.md` 與 scoped 大綱按卷分工**（2026-07-28）：`01-大綱.md` 涵蓋已收斂的卷、未收斂的卷走 scoped，**兩者並存是常態**。測某個尚未收斂的卷時要讀 scoped 檔，不要因為 `01-大綱.md` 存在就以為它涵蓋全書——那正是舊路由踩過的坑。

## 6 項測試

每項標明「機械可抽取部分」與「LLM 判語意部分」，及基準知識庫。

| # | 測試 | 檢查什麼 | 機械 vs LLM | 基準 |
|---|------|----------|-------------|------|
| 1 | **結局定稿** | 大綱「結局與題旨」是否已定、非模糊待定用語；結局類型（喜/悲/悲喜/暗示/開放/諷刺）是否明確且與題旨綁定 | 機械：**`outline-lint` 第 6 項已驗**（`結局：` 非空、不含 `待定`／`未定`／`大概`）＋LLM：判是否真的「定」了，而非「大概是這樣」式的模糊表述——**lint 只問「有沒有寫著還沒定」，「這段文字算不算已定」是這一格** | `大綱.schema.md`／`主題題旨.md`／`結局類型.md` |
| 2 | **題旨可檢驗** | 題旨是否符合「因為 X 導致 Y」的可檢查形式 | 機械：**`outline-lint` 第 6 項已驗**句型含「因為…導致/所以…」＋LLM：判 X 是否為行為/觀念、Y 是否為結果，且與大綱內容相符 | `主題題旨.md` |
| 3 | **立場一致** | 大綱「故事全文」有無中途立場詭變 | — | 通讀全文（LLM）＋對照題旨 |
| 4 | **結構對應完整** | 選用的結構公式，必要階段是否都有對應到 | 機械：**`structure-project` 已做完集合差**（第 0 步）——它拿大綱 `## 選用結構公式` 宣告的公式名去查 `結構公式.md` 的 registry，對照幕綱各幕 `結構階段` 欄算出缺哪個階段、階段序有無非遞增＋LLM：判各階段是否**有意義地**被覆蓋、非掛名湊數，以及 α 變形能不能解釋那幾處偏離 | `結構公式.md`／`大綱.schema.md`「選用結構公式」 |
| 5 | **壓縮一致** | 摘要一句話/50/100/200 字四段是否存在且不矛盾 | 檢查四段皆非空（機械）＋判是否為同一主線、彼此不矛盾，且與大綱一致（LLM） | `選題與收斂.md`／`摘要.schema.md` |
| 6 | **節奏檔位與貫穿大懸念** | (a) 若 **`story/幕綱/arcNN.md` 檔頭**標了**節奏檔位**（開頭段／常態段），各段檔位是否與其結構位置相稱（早期＝開頭段·高密度事件驅動；中段＝常態段·靠長線供能）——中段仍套開篇緊繃、或開頭就走常態鬆弛＝可疑。⚠️ **2026-07-27（功能 08 抉擇 2）起摘要不存節奏檔位**：權威在檔頭，摘要那一份實測只覆蓋 1/11 arc、是外移後的殘骸。檔頭本身零格式零 lint（實測 11 支有 8 支寫了），所以讀不到是常態。(b) 常態段若宣告「靠長線大謎供能」，摘要／大綱裡有沒有一條**可指認的貫穿核心大懸念**（一個養十幾章到全書、故意慢燉的問題），還是常態段黏性無著落？未標檔位不扣分（誠實未定即可），但標了就要自洽 | 機械：`summary-lint` 第 1 項已驗 `貫穿大懸念` 欄非空、第 6 項已驗它裡面的 `幕NNN`／`arcNN` 引用不懸空（**懸空＝那個「已坐實」的宣稱靜靜地變成假的，而摘要不會 stale**）＋掃各 arc 檔頭有無節奏檔位字樣＋LLM：判檔位與結構位置是否相稱、貫穿大懸念是否真的可指認且慢燉未過早倒完 | `戲劇張力與懸念.md` §一（懸念型態·資訊差引擎）§六(d)（開頭vs常態兩檔位）、`摘要.schema.md`（`貫穿大懸念`）、`幕綱.schema.md`（arc 檔頭）、`網文與文學取捨.md`（連載鉤子·揭露速度） |

### Scoped 模式（測 `story/大綱/arcNN.md`）判準調整

| # | 全書模式判準 | Scoped 調整 |
|---|---|---|
| 1 結局定稿 | 「結局與題旨」是否已定 | 改測「本段收束與鉤子」是否明確非空、非模糊（三格齊全那一半由 `outline-lint` 第 7 項給）；不要求「對全書結局的關係」已定，但若該欄寫「已定」卻與 `story/參照/就緒.md` 的「大綱」格矛盾才標可疑 |
| 2 題旨可檢驗 | 全書題旨是否可寫成因果句 | 該 arc 若有局部題旨可選填檢驗；全書題旨未定不扣分，只在 scoped 大綱謊稱代表全書題旨時標可疑 |
| 3 立場一致 | 通讀全文 | 範圍縮小到本段全文 |
| 4 結構對應完整 | 必要階段是否全覆蓋 | 只檢查本 arc 涵蓋的階段有無對應；其餘未下沉階段缺是預期、非破綻，需加注 |
| 5 壓縮一致 | 摘要四段是否存在且一致 | 若摘要尚無對應本段的壓縮版本，標「不適用（該段細節尚未寫入 00-摘要.md）」 |
| 6 節奏檔位與貫穿大懸念 | 全書檔位相稱＋貫穿大懸念可指認 | 只判本 arc **檔頭**標的檔位是否與其位置相稱；「貫穿大懸念」屬全書層，scoped 模式不要求本段自證，只在本段宣告「常態段靠某長線供能」卻與摘要既有大懸念矛盾時標可疑 |

## 執行步驟

0. **先跑格式閘門**：`uv run --project <套件根>/tools/beat_metrics outline-lint --book <書資料夾>`。**硬事實由它給，不要用眼睛抓**——節枚舉、檔頭狀態、`結局：` 非空且不含待定字樣、`題旨：` 的因果句型、`本段收束與鉤子` 三格、`幕NNN`／`chNNNN` 引用不懸空、`[[伏筆:x]]` 命中 registry、`本 arc 伏筆狀態` 的三欄意圖表、卷級方向的卷 token 與指路紀律、`## 選用結構公式` 的公式名命中 registry、檔內路徑的目的地存在。（第 ③ 項是**舊 `_index.md` 的殘留偵測**——那支檔 2026-07-28 已廢除，缺檔不是問題；arc 清單與狀態改由 `outline-lint --emit` 印。）它印的問題**逐條併進本次報告**（測試類型欄標 `outline-lint`、嚴重度依它的性質判），覆蓋率行的數字直接引用。
   > **它報的是「格式還是不是它宣稱的那個樣子」，不是「內容好不好」**——後者才是下面 6 項。特別看兩個數字：**連續敘述佔全檔的百分比**（這一軸還在不在做它該做的事；實測某本書 54.0% → 11.1%）與**枚舉外節數**（無家內容寄居的總量）。
   - **同一步跑結構軸投影**（測試4 的硬事實）：`uv run --project <套件根>/tools/beat_metrics structure-project --book <書資料夾> [--arc arcNN]`。**集合差是它算的**——大綱 `## 選用結構公式` 宣告的公式名 → `技巧知識庫/結構公式.md` 的 registry → 必要階段清單，對照幕綱各幕 `結構階段` 欄，印出缺哪個階段、階段序有無非遞增。覆蓋率行照抄（特別是「幾幕的欄不以頂層階段 token 起頭」＝**這個投影看不見多少**）。
     > 測試4 十天來自稱這一段是「機械」的，而 `結構公式.md` 當時**沒有 registry**、階段名只寫在粗體 bullet 與散文裡——那個「機械」從來跑不了（`設計原則.md` C3／E1）。2026-07-28（功能 11）補上 registry 之後它第一次真的跑得動。
1. **摘要軸兩支都讀**——源 `story/00-摘要.md`（承重決定的散文與理由，整檔讀）＋衍生 `story/00-摘要.ai.md`（六個語意欄＋壓縮＋取向定位分析）；再依模式讀 `story/01-大綱.md`（全書模式）或作者指定 arc 的 `story/大綱/arcNN.md`（scoped 模式）——**選用結構公式與 α 變形就在那支檔的 `## 選用結構公式` 節裡**（`story/參照/結構.ai.md` 2026-07-28 廢除，別去找它）。
2. **不要重做第 0 步已經做完的機械抽取**：欄位存不存在、題旨句型合不合、引用懸不懸空由 `outline-lint` 給；**缺哪個必要階段由 `structure-project` 給**。這裡只做它們做不到的那一半——各階段是不是**有意義地**被覆蓋（測試4 的 LLM 那一半），以及所有需要讀懂內容的判斷。
3. **再做 LLM 語意判斷**：對照各基準知識庫的**所引小節**（依各檔檔頭「目錄」定位到對應 §，不需整檔通讀；附錄小節按需才讀），逐項找可疑點。
4. 輸出報告（見下），並更新 `story/參照/就緒.md` 的「大綱」欄（**五個 token 之一**，理由 append 進 `story/參照/裁決流.md`；落檔後跑 `uv run --project <套件根>/tools/derived_sync readiness-lint --book <書>`）（測試1/2/3/5/6 對應「主線＋題旨＋基調」列——測試6 的節奏檔位/取向定位屬定位範疇，測試4 對應「結構」列）；scoped 模式下，只更新該 arc 對應的粒度（如「草擬（僅 arc01）」），不得把單一 arc 測試結果誤寫成代表全書大綱已定稿。

## 輸出格式

每個可疑點一列：

```
項目 ｜ 測試類型 ｜ 嚴重度 ｜ 說明 ｜ 建議修正 ｜ 建議回寫位置
```

- **嚴重度**：高／中／低（僅供作者排序參考，非門檻）。
- **建議回寫位置**：通常填「—」（問題就在大綱本身，直接改大綱即可，大綱是作者利器·直改）；只有當判定問題根源其實在 `00-摘要.md` 或 `設定/世界觀/<主題>.md`（例如大綱結局已改但摘要題旨沒跟著更新、或大綱撐不住世界觀的某條規則）時，才依 `結構定義/待裁決.schema.md` 在 `story/參照/待裁決.md` 追加一列（`標的` 欄寫 `00-摘要.md`／`設定/世界觀/<主題>.md`），此欄填該源檔路徑。
- 範例：
  - `題旨 ｜ 題旨可檢驗 ｜ 高 ｜ 「她漸漸長大」不符合「因為X導致Y」可檢查形式 ｜ 改寫為明確因果句 ｜ —`
  - `摘要-題旨 ｜ 壓縮一致 ｜ 中 ｜ 大綱結局已改為命定反諷，但00-摘要.md的題旨仍是舊版直白結局 ｜ 回頭同步改源 00-摘要.md 題旨再重生 ｜ 00-摘要.ai.md`
  - `貫穿大懸念 ｜ 節奏檔位與貫穿大懸念 ｜ 中 ｜ arc02 檔頭宣告「常態段·靠長線大謎供能」，但摘要/大綱裡找不到一條可指認的貫穿核心大懸念，常態段黏性無著落（章末鉤降級後靠什麼追更？） ｜ 於源 00-摘要.md 補明一條慢燉貫穿的核心大懸念（如「主角真身之謎」）再重生，或在 story/幕綱/arc02.md 檔頭改回開頭段檔位 ｜ 00-摘要.ai.md`
- 結尾給一段**總覽**（各測試各幾項可疑點），並**明確聲明：以上為審稿建議，處置由作者決定，本測試不下 pass/fail**。

## 邊界

- 不自動修改大綱/摘要（除非作者要求後另行進行）；「建議回寫位置」欄只允許在 `story/參照/待裁決.md` 追加列，不改源、不改分析區。
- 不做角色弧線/伏筆/因果連續性檢查（那些要幕綱才具體化，仍屬 `beat-test`）。
- scoped 模式不檢查「全書結局/題旨是否已定」（本來就允許未定）；只檢查「被指定的 arc 是否誠實標注其與全書結局的關係」。
- MVP 在主 session 執行。
