# beat-sheet — 幕綱共創

從大綱生成候選幕綱，把故事拆成有序、離散的「幕」。這是創作的最大難關，也是本系統把測試 shift-left 的著力點。

**AI 角色 = 共創 + 審稿**：你提幕綱草稿以降低白紙恐懼，但**所有創作決定權在作者**——排序、增刪、改劇情都由作者拍板。你負責讓每一幕結構完整、因果扣連、伏筆可追蹤。

## 共同約定（必讀）

資源定位、AI 角色（共創＋審稿、非門檻）、**源→衍生兩檔＋下游回饋**規則見 `結構定義/共同約定.md`（二、三、四）。beat-sheet 讀設定層一律讀衍生 `.ai.md`；發現設定問題於 `story/參照/待裁決.md` append 一列（`標的` 欄寫該源檔路徑），不改源。

## 依據

> 讀技法檔時先讀各檔檔頭「目錄」標**核心**的小節；標「附錄（按需取用）」的深素材只在實際觸及時再讀對應小節。

- `結構定義/大綱.schema.md`——大綱的全書版與局部下沉版格式（兩者**按卷分工**）；若讀的是 `story/大綱/arcNN.md`，其「本段收束」對應本次拆幕範圍的收尾，不是全書結局。**它的格式由 `outline-lint` 守**（2026-07-28 新增），所以逐節取值是安全的。**大綱層的 `## 本 arc 伏筆狀態` 只寫意圖（本 arc 打算怎麼動哪幾條線、為什麼），不寫既成事實**——埋設點與回收點一律走 `foreshadow-project --arc`（見下）。
- `結構定義/幕綱.schema.md`——幕的固定八欄位與 `[[幕NNN]]`、`埋/收[[伏筆:x]]` 連結規範（**務必嚴格遵守**），以及選用的「本 arc 伏筆狀態」表（跨 arc／全書懸念時使用）。
- `技巧知識庫/因果法則.md`——幕的五要素、前果＝後因、具意義的結果、貴精不貴多；**§七 賭注兌現＋角色反應可信度**（升起重大威脅/秘密曝光/底線被踩時，同幕綱裡就要設計它的了結，勿留賭注孤兒；對抗降溫偏誤）。
- `技巧知識庫/結構公式.md`——選用公式與結構階段。
- `技巧知識庫/伏筆與意外.md`——伏筆埋設與由果推因。
- `技巧知識庫/需求四象限.md`——讓幕推進角色弧線。
- `技巧知識庫/主題題旨.md`——題旨公式與主題三角演繹法（對立／矛盾／極端），排幕時預留鋪陳點用。
- `技巧知識庫/戲劇張力與懸念.md`——每幕幕尾懸念結尾（七種停止點）、悶燒與兩難的節奏安排、開場鉤子；**§一 資訊差引擎**（同步／優越·扮豬吃虎／替他捏汗——設計每場張力來自誰知道什麼）、**§六(d) 開頭vs常態兩檔位**（開頭懸主角命運·高密度；常態懸這場誰死/怎麼打臉·靠長線大謎供能，章末鉤降級）。
- `技巧知識庫/世界觀與背景.md` §九「**設定帶出的操作判準**」——排「哪一幕揭什麼」的揭露節奏：先現象後定義、術語延後、一次1–2詞＋功能標籤、硬設定塞進有動機問答、疑問要有回收時點（對治「設定突然蹦出」）。
- `技巧知識庫/結局類型.md`——排收尾幕時對照六大結局類型與好結局六要素（首尾呼應／觀念改變預留點）。
- `技巧知識庫/角色塑造.md`——排幕時安排情節逐步揭露角色三層行為、消除或揭穿內外落差。
- `技巧知識庫/網文與文學取捨.md`——依衍生 `00-摘要.ai.md` 的 `取向定位` 欄決定爽點鋪設密度 vs 弧線鋪陳的比重（逐軸理由讀源 `00-摘要.md`「取向定位」節與衍生「取向定位分析」）；可把爽點三步／五段式與結構公式並列選用。

## 流程

1. **讀輸入**：
   - **大綱來源判斷（2026-07-28 路由反轉）**：**先查目標 arc 有沒有對應的 `story/大綱/arcNN.md`（同一 arc 編號）**——有就讀它作為本次拆幕的大綱來源（含選用結構公式、本段收束與鉤子）；此時給的是「本段收束」而非全書結局，排幕時不得假裝已知全書結局。
     > **為什麼是這個順序**：`01-大綱.md` 與 scoped 大綱**按卷分工**（`大綱.schema.md`「收斂規則」）——`01-大綱.md` 涵蓋已收斂的卷，未收斂的卷走 scoped。舊路由（「`01-大綱.md` 存在就讀它」）在這個狀態下指向**一個字都沒有寫該卷情節的檔**：實測某本書連續 3 個 arc 都是這樣，**沒出事的唯一原因是有人在 `01-大綱.md` 檔頭手寫了一句指標**——散文在替一條錯的規則兜底。
   - 若該 arc 沒有 scoped 檔，改讀 `story/01-大綱.md`（含選用結構公式、結局、題旨）。**這幾節有 `outline-lint` 守**（節枚舉、`結局：` 非空且不含待定字樣、`題旨：` 是「因為…導致」句型），所以逐節取值是安全的；印象中該有而讀不到時先跑一次 `outline-lint`，不要自己補。
   - **卷級方向（`設計原則.md` F2 第五格「綁單一卷」的載入承諾）**：讀該卷大綱檔的 `## 卷級方向（卷X·本卷權威）` 節——卷級主事件、段位分工、跨階與線的分配住在那裡。**它只在該卷第一個 arc 的大綱檔**，所以拆本卷第二段以後的 arc 時，要回頭讀該卷第一個 arc 的大綱檔（同卷其餘檔只會給你一個指標，不會複述）；該卷已併入 `01-大綱.md` 的話，那一節已經升進全書版。
   - 若兩者都不存在 → **停下**，向作者說明「找不到這個 arc 的大綱依據」，建議先跑 `organize`（全書模式，或只整理這一段），不要在缺乏大綱依據時自行憑空拆幕。
   - **設定層走選取、不整批讀**（`共同約定.md` 八）：本 arc 幕綱尚未存在時，先跑 `char-lint --book <書> --emit`／`world-lint --book <書> --emit` 兩支投影挑出這一段會用到的實體，只讀那幾支；**改動既有 arc 時**改用
     `uv run --project <套件根>/tools/settings_select settings-select --book <書資料夾> --arc arcNN`。
     兩種情況都**不要 `設定/角色/*.ai.md` 全撈**。
   - 既有 `story/幕綱/`：**接口走工具**（`共同約定.md` 八）——
     `uv run --project <套件根>/tools/foreshadow_project foreshadow-project --book <書資料夾> --arc arcNN`
     取得「進入本 arc 時仍開著的伏筆」清單（逆推本段該收哪些、哪些續行）。另讀**前一 arc 的收點**當銜接。**不整批讀所有 arc 檔。**
2. **選用/確認結構公式**：讀上一步那支大綱檔的 `## 選用結構公式`（**含 α 變形宣告**）；沒有就與作者確認。**公式名照 `技巧知識庫/結構公式.md` 的 registry 字串寫**（三幕劇／起承轉合／七問題公式／編劇九階段／Save the Cat! 15 節拍表／雪花法／序破急），`outline-lint` 第 12 項在守。要看「上一輪拆出來的階段長什麼樣」就跑投影（下一步的指令），**別去找 `story/參照/結構.ai.md`——那支檔 2026-07-28 廢除了**。
3. **生成候選幕綱** → 寫入 `story/幕綱/arcNN.md`：
   - **檔案分區（硬規定，見 `幕綱.schema.md`「arc 檔的內部結構」）**：`## 本 arc 承諾`（節奏檔位／統一母題／必須發生／**不得發生**＝排除線）→ 各幕 → `## 本 arc 伏筆狀態` → **檔尾** `## 設計註（下游不抄）`。**所有「為什麼」（母題論證、判例、本輪拍板記錄、降回閥推導、與其他 arc 的對比、給某個測試的說明）一律進檔尾設計註，不放檔頭、不滲進欄位。** 負向承諾（排除線）屬承諾區，不是設計理由。
   - **配號**：依 `幕綱.schema.md`「幕號配號規則」——每 arc 預配 100 號段（arcNN 從幕((NN-1)×100+1) 起），幕號是穩定 ID、不代表全書順序，arc 可亂序下沉；已存在的幕號一律不重編。
   - 每幕一個 `## 幕NNN · 幕名` section，填齊固定八欄位（角色／時空／行動／衝突／結果／前因／伏筆／結構階段）。**八欄只寫故事事實**，不寫主題陳述／結構功能／讀者效果／元管理標籤（見 `幕綱.schema.md`「八欄只寫故事事實」四類禁止清單）。
   - **可演性自檢（每幕填完就問一次）**：**這一幕拍成一個鏡頭，鏡頭裡有什麼？** 答不出來的（畫面裡只有一個人在想事情、或只剩一句主題陳述）**就不是一幕**——併進鄰幕當 Sequel，或替它找一個外顯載體（一件正在做的事、一個在場的人、一個被推到眼前的物）。「想事情」合法，但必須附著在外顯行為上。
   - **別讓整段長成內心戲**：一個 arc 內「主角獨處**且行動欄只剩主題陳述**」的幕不宜超過三分之一，且**不排連續兩幕**。**注意是兩個條件的合取**——主角獨處但有具體行為（一個人入定修行、獨處時被什麼掃過）是好幕，不必為了湊人數硬塞角色進去。缺喜劇／缺聲音可以在句子層補，缺場面不行——那是幕綱的病。
   - **細節留白是預設，不必宣告**：承諾區與八欄沒寫的東西自動歸 `write`（`共同約定.md` 七「沉默＝授權」）。**不要寫「留 `write` 現場長」**；要限制某個細節，就把它寫成承諾。
   - **因果**：用 `[[幕NNN]]` 標前因；確保每幕「結果」能催發下一幕動機；避免「有因無果／有果無因」的孤兒與離題幕（貴精不貴多）。**升起重大賭注的幕（威脅／秘密曝光／底線被踩），要同時設計它的兌現**——中和／升級成跨章懸而未決的威脅線／給足主角按兵不動的動機，勿留「賭注孤兒」（軟退縮＋放行＋威脅後文蒸發）；主動對抗把衝突寫軟的降溫偏誤，供 `beat-test` 測試6 事後核對（見 `因果法則.md` §七）。
   - **伏筆**：由（全書模式）結局、或（局部模式）該 arc 的本段收束與鉤子，逆推需要哪些伏筆，用 `埋[[伏筆:x]]`／`收[[伏筆:x]]` 標記；局部模式下，跨出本 arc 範圍才會回收的伏筆允許「埋而未收」，於「本 arc 伏筆狀態」表註明原因（不另立登記簿）。
   - **結構階段**：每幕標明對映公式的哪個階段，**值要以頂層階段 token 起頭**（`起·失衡開場（…）`）。這一欄是 `structure-project` 的**唯一輸入**——全書的「階段 ↔ 幕」對應表由它當場重算，**不必也不要另外維護一份對應表**。
   - **主題回指**：每條主線幕盡量能回指題旨（因為 X 導致 Y）；若摘要或作者已定義主題三角（核心／對立／矛盾／極端），排幕時預留至少一處鋪陳點呼應對立／矛盾／極端情境（供角色犯錯或抉擇），供 `beat-test` 測試5 事後核對。
4. **同步維護**：
   - ~~`story/參照/結構.ai.md`~~ **已廢除（2026-07-28 功能 11），不必維護**：幕 ↔ 結構階段對應表改成投影，落檔後跑一次確認這一 arc 的階段長對了——
     `uv run --project <套件根>/tools/beat_metrics structure-project --book <書資料夾> --arc arcNN`
     它印選用公式、階段 ↔ 幕 對應、**缺哪個必要階段／階段序非遞增**（機械），以及「幾幕的 `結構階段` 欄不以頂層階段 token 起頭」。**投影不是閘門**，可疑點交作者與 `beat-test`。
   - **各 arc 範圍與標題**跑 `uv run --project <套件根>/tools/beat_metrics beat-lint --book <書> --emit`（**不落檔**；舊 `_index.md` 2026-07-28 廢除）。故事順序讀 `story/幕綱/_順序.md`；選用公式讀大綱的 `## 選用結構公式`；階段 ↔ 幕跑 `structure-project`。
   - **設計註搬走（落檔前做，別讓檔案一路長）**：`uv run --project <套件根>/tools/derived_sync derived-sync check --book <書資料夾>`，看成長哨兵有沒有報本 arc「幕綱肥大（B/幕）」。**報了就當場把檔尾設計註搬進 `story/參照/裁決流.md`**（見 `幕綱.schema.md`「設計註要搬走」）——一項裁決一列，`標的` 欄填 `幕綱/arcNN.md`，`理由` 欄放原本的論證（可長，它不會進 `write` 的 context），`射程` 填 `全書`／`至arcNN`。搬完幕綱檔尾的設計註區應該接近空的。
     - 這**不是刪除**：2026-07-26 起原本的三條回收判準降級成裁決流的 `射程`／`狀態` 兩個欄位，由程式過濾——已升為通則的狀態填 `已升為通則`＋理由改成一句指向 `結構定義/` 或 `技巧知識庫/`；已過射程的填 `已過射程`。**沒有東西需要被丟掉。**
     - **排除線不動**（那是承諾區的負向承諾，不是設計註）。搬完再封檔。
     - **這本書沒有 `story/參照/裁決流.md` 就先建一支**（照 `書本模板/story/參照/裁決流.md` 的骨架）。`beat-lint` 會把「有設計註、卻沒有目的地」直接報成問題——箭頭指向空氣是搬移工作流斷掉的第一現場，實測一世之尊就是這樣讓「為什麼」滲進八欄、`行動` 欄從 76 字/幕 長到 513 字/幕。
     - **搬完跑一次格式閘門**：`uv run --project <套件根>/tools/decision_projection decision-lint --book <書資料夾>`——驗七欄／日期／狀態／**射程寫法**（`decision-project` 從不驗這一欄）／標的存在性／`裁決` 欄 ≤200 字。
   - **格式閘門（落檔後必跑）**：`uv run --project <套件根>/tools/beat_metrics beat-lint --book <書資料夾>`。它守幕號唯一與號段、**`前因 [[幕NNN]]` 的目標存在**、八欄齊全、`_順序.md` 的 `全書順序：` 涵蓋所有 arc、每支 arc 有 `## 本 arc 承諾`、伏筆近似名、設計註目的地。**有問題就當場修再交付**——這幾項全是機械事實，不該留給作者或 `beat-test` 用眼睛抓。
     - 它會印一行「檢查範圍：N 支 arc／N 幕／N 條前因／…」，**0 也印**。看到不該是 0 的地方是 0，先查解析而不是慶祝乾淨。
     - 伏筆名沒有 `story/物件/<名>.md` 只是**提示**（沒有物件檔的 ID 合法，開檔走內容測試）；但**近似名是問題**（`X` 與 `X（Y）` 並存＝同一條伏筆兩個名字），當場統一。
   - **可演性自檢（落檔後跑一次）**：`uv run --project <套件根>/tools/beat_metrics beat-metrics --book <書資料夾> --arc arcNN`。空洞幕比例、連續空洞段、分區衛生、母題重複率四項有任一報可疑點，**在交付時一併講給作者聽**——不擋落檔（`beat-test` 才是審稿），但別悶著不說。
5. **世界觀回饋**：排幕時若發現世界觀規則不夠用、或與幕的行動矛盾，於 `story/參照/待裁決.md`（見 `結構定義/待裁決.schema.md`）追加一列，`標的` 欄寫 `設定/世界觀/<主題>.md`，**不改世界觀源、不改其分析區**；交付候選幕綱時提示作者「已記錄 N 筆待裁決」，交 `worldbuild` 消化。
6. **交回作者共創**：以「候選草稿」姿態呈現，明列可重排/增刪/改的點，等作者決定；不擅自定案。

## 邊界

- 產出的是幕綱（藍圖），**不是散文章節**（動筆寫章節＝子專案 B）。
- 幕綱定案後，用 `beat-test` 跑結構測試。
