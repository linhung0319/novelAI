# organize — 把已就緒的大方向整理成大綱

把**大方向已收斂**的素材，整理成結構完整的 `story/01-大綱.md`（連續敘述、結局與題旨已定）與角色/結構參照，並診斷「還缺什麼、哪裡弱」。**若只有某一段（arc）已收斂、全書結局/題旨仍未定**，改整理成局部的 `story/大綱/arcNN.md`（見 `結構定義/大綱.schema.md`「局部下沉（scoped）大綱」節）——不因為要拆一小段就被迫替尚未收斂的全書結局搶先拍板。

> ⚠️ **先確認粗階段已完成**：organize 假設 `story/00-摘要.md`（含題旨、基調）與 `story/設定/世界觀/`（至少一個源 `<主題>.md`）已大致成形、主線/結局/主角已拍板。**若 raw 還很亂、主線/題旨/結局未定，先用 `develop` 做粗階段**（分揀素材、彙整世界觀、攤開承重分叉），再回來 organize。發現粗層未就緒時，就把控制權交回 develop，不要在大綱裡硬塞一堆「待確認」。

## 共同約定（必讀）

資源定位、AI 角色（共創＋審稿、非門檻）、**源→衍生兩檔＋下游回饋**規則見 `結構定義/共同約定.md`（二、三、四）——你提草稿、指出缺口，但所有創作決定權在作者。**維護角色時改源（單檔 `設定/角色/<名>.md` 或目錄 `設定/角色/<名>/<切面>.md`，見 `角色.schema.md`）再重生 `.ai.md`＋`_index.ai.md` 並 `derived-sync stamp`；大綱本身是作者利器·直改、不走衍生。**

## 流程

1. **載入方法與格式**：讀 `結構定義/*.schema.md`（含 `大綱.schema.md` 的全書版與局部下沉版兩節）與 `技巧知識庫/*.md`。重點：`創作流程.md`、`故事本質與要素.md`（故事三要素/導向/好故事3加1/設定3要領——整理大綱時的判準地基）、`因果法則.md`、`主題題旨.md`、`需求四象限.md`、`結構公式.md`、`結局類型.md`（結局與題旨綁定）、`角色塑造.md`（角色呈現）、`網文與文學取捨.md`（依衍生 `00-摘要.ai.md` 的 `取向定位` 欄調結構的爽點/弧線比重，理由讀源 `00-摘要.md`「取向定位」節）。各技法檔先讀檔頭「目錄」標**核心**的小節，標「附錄（按需取用）」的深素材按需再讀。
2. **讀粗階段產物與 raw/**：**摘要軸兩支都讀**——源 `story/00-摘要.md`（承重決定的散文與理由，整檔讀）＋衍生 `00-摘要.ai.md`（**六個語意欄**`主線`／`題旨`／`基調`／`視角結構`／`取向定位`／`貫穿大懸念` ＋壓縮＋取向定位分析）。**權威在那六欄**（它們有 `summary-lint`），源檔給的是理由——**不要在源檔裡「取某一欄」**，那是自由源、沒有欄（`設計原則.md` A4 第三條路）。這是 develop 收斂出的大方向。**設定層走索引、不整批讀**（`共同約定.md` 八 context 取用契約）：先讀 `story/設定/世界觀/_總覽.ai.md` 與 `story/設定/角色/_index.ai.md` 兩份索引，挑出這一段真正會用到的實體，**只讀那幾支** `<主題>.ai.md`／`<名>.ai.md`；本段已有幕綱時改用 `settings-select --arc arcNN`（見契約）。**不要 `設定/角色/*.ai.md` 全撈。**再讀 `raw/` 補既有的大綱/幕綱片段、角色與情節細節。再讀源 `story/參照/就緒.md`（作者的就緒清單與成熟度判斷），並跑 `uv run --project <套件根>/tools/derived_sync readiness --book <書>` 看機械現況（六條清單的前哨結果、哪幾個 arc 已下沉到哪一層——**那一節由檔案系統重算，不是手抄的**）。**若連局部都摘要缺主線/題旨、或 `story/設定/世界觀/` 無任何源 `<主題>.md`，判定粗階段未就緒 → 停下並建議先跑 `develop`。**
3. **判斷模式：全書或局部**：
   - **全書模式（預設）**：`story/參照/就緒.md` 的「就緒清單」大致勾齊（機械前哨跑 `readiness` 看，**六個勾不等於六條都過**），或作者明確要整理全書 → 走 4a。
   - **局部模式**：全書結局/主線仍多處未定，但作者已在「局部下沉紀錄」指出某 arc 已清楚可下沉，或直接說「先幫我整理這一段」→ 走 4b。**不得**因為要拆一小段而強迫作者替未定的全書結局／配角搶先拍板。
   - 判斷不確定時，直接問作者：「要整理全書大綱，還是只先整理某一段？」
4. **產出／更新 story/**（依 `大綱.schema.md`）：
   - **4a 全書模式**：
     - `story/01-大綱.md`——把摘要擴寫成連續敘述的完整故事；標註選用結構公式；**結局與題旨已定**。**`## 結局與題旨` 的「結局」只寫一句話＋回指 `00-摘要.md`「結局方向」，不複述**（2026-07-28 抉擇 5 A：實測兩邊 8-gram 重疊 45.4%、源↔源、零守衛）；本節只寫大綱層獨有的——通向結局的情節路徑、分簇與匯流、揭底手法、結構公式怎麼收。
     - 若 `story/大綱/` 已有先前局部下沉的 arc 片段，**讀入作為素材來源**併入連續敘述，然後照 `大綱.schema.md`「收斂規則」的**四步**做完：① 併入 → ② 該卷的 `## 卷級方向（卷X·本卷權威）` **升進 `01-大綱.md`**（它是仍在生效的方向宣告，不是沿革）→ ③ **驗收：印出「本次併入 N 支、8-gram 保真率 X%」交作者確認**（實測某本書 arc05–08 只有 **2.7–4.7%** 的 8-gram 真的進了全書版，而那 8 支檔的檔頭當時已經寫著「正文以 `01-大綱.md` 為準」——**保真率必須在搬檔之前被看見一次**）→ ④ `git mv story/大綱/arcNN.md story/大綱/_已併入/arcNN.md` ＋ 檔頭加註「⚠️ 已併入 `01-大綱.md`（日期）」＋ 同輪改掉舊路徑的引用。`story/大綱/_index.md` 的那一列**留著、狀態改成「已併入」**。
   - **4b 局部模式**：
     - 產出／更新 `story/大綱/arcNN.md`（**索引不必動**——2026-07-28 廢除，跑 `outline-lint --emit`），依「局部下沉（scoped）大綱」節格式：本段全文、本段收束與鉤子、對全書結局的關係誠實標「未定」。
     - **不寫**全書結局/題旨；arc 編號需與該段未來對應的 `幕綱/arcNN.md` 共用同一識別碼。
     - 檔頭標「⚠️ 暫定，待粗層鎖定」。
     - **節是封閉枚舉**（`大綱.schema.md`「節枚舉」）：逐題發落紀錄／拍板來歷／護欄推導走 `story/參照/裁決流.md`（第 6 步）；編號排除線走幕綱的 `## 本 arc 承諾`；**`## 本 arc 伏筆狀態` 只寫意圖（三欄），不得出現 `幕NNN`／`chNNNN`**——既成的埋設點與回收點跑 `foreshadow-project --arc arcNN`。射程＝一整卷的方向宣告寫成 `## 卷級方向（卷X·本卷權威）`，只放該卷第一個 arc 的檔，同卷其餘檔只指路。
     - **索引已廢除**（2026-07-28 功能 12）：arc 清單與狀態跑 `outline-lint --book <書> --emit`；沿革與逐題發落紀錄走 `story/參照/裁決流.md`。
   - **兩模式共通**：同步維護角色（大綱點名的主角/要角，改源 `story/設定/角色/<名>.md`＋重生 `<名>.ai.md`／`_index.ai.md` 並 stamp；一角一檔、就地深化不建重複檔，規則同 `character`）；**選用結構公式與 α 變形寫進大綱自己的 `## 選用結構公式` 節**（全書級進 `01-大綱.md`、arc 級進該 arc；公式名照 `技巧知識庫/結構公式.md` 的 registry 字串寫，`outline-lint` 第 12 項在守）——**`story/參照/結構.ai.md` 2026-07-28 廢除，不必也不要再維護它**，「哪一階段對應哪幾幕」跑 `structure-project` 投影；摘要微調改源 `00-摘要.md` 再重生 `00-摘要.ai.md`、stamp，接著跑 **`summary-lint --book <書>`**——**第 3 項（人稱非支援值）或第 7 項（基調缺單位與達標線）有命中就停下回問作者、不得封章**（`摘要.schema.md`「系統支援的人稱」／`共同約定.md` 九）。**衍生 front-matter 只寫六個語意欄**，不要寫 `基調主從`／`終局`／`節奏檔位`（2026-07-27 依 A4 刪除）。**兩類內容不留在源檔**：被捨棄的方案＋為什麼捨棄 → `story/參照/裁決流.md`（`標的`＝`00-摘要.md`）；「臨場拍板」帶「已定案／已鎖定／已寫定」字樣的條目歸位到承重節、仍未定的進 `raw/`。但主線/結局/主角的**承重改動應退回 develop**；更新既有檔時保留作者已寫定內容。
   - **兩模式共通·格式閘門（落檔後必跑）**：`uv run --project <套件根>/tools/beat_metrics outline-lint --book <書資料夾>`。它守節枚舉、檔頭狀態、`本 arc 伏筆狀態` 的三欄意圖表、卷級方向的卷 token 與指路紀律、`幕NNN`／`chNNNN` 引用不懸空、`[[伏筆:x]]` 命中 registry、`結局與題旨` 與 `本段收束與鉤子` 的形狀、`_index.md` 視圖 ≡ 資料夾、檔內路徑的目的地存在。**有問題就當場修再交付**——這幾項全是機械事實，不該留給作者或 `outline-test` 用眼睛抓。
     - 它會印一行「檢查範圍：N 支大綱檔／**連續敘述佔全檔 X%**／…」，**0 也印**。**最該盯的是連續敘述那個百分比**：它是「這一軸還在不在做它該做的事」的單一數字（實測某本書 54.0% → 11.1%，11 個 arc、5 天、零警報）。
     - 伏筆名沒有幕綱標記也沒有物件檔只是**提示不是門檻**（沒有物件檔的 ID 合法），但那代表它是第三份自由造字的名冊——正解是改成幕綱既用的那個名字。
5. **拆幕交 beat-sheet**：提醒作者 `beat-sheet` **先找對應的 `story/大綱/arcNN.md`（同一 arc 編號），找不到才讀 `01-大綱.md`**（2026-07-28 路由反轉）。
6. **落裁決流**（作者拍板後，落檔前做）：本輪作者拍板的每一項承重決定，在 `story/參照/裁決流.md` append 一列（`日期｜來源｜標的＝該源檔路徑｜裁決＝一句話（≤200 字）｜理由＝為什麼＋**已駁回的方案**（不限長）｜射程｜狀態＝生效中`）。**這本書沒有那支檔就照 `書本模板/story/參照/裁決流.md` 的骨架先建一支**——目的地不在時 `derived-sync check` 會報，而理由會改落 `.ai.md` 的 blockquote（實測那是 46,245 字元的來源）。落檔後跑 `uv run --project <套件根>/tools/decision_projection decision-lint --book <書資料夾>`。消化掉的待裁決列記得刪（見 `待裁決.schema.md`「結案怎麼離開」）。
7. **輸出缺口診斷報告 + 更新就緒源檔** `story/參照/就緒.md`（狀態格**只准五個 token 之一**；落檔後跑 `uv run --project <套件根>/tools/derived_sync readiness-lint --book <書>`）。局部模式下，「大綱」欄照樣只填 `草擬`——**「僅 arc01」這種註記不寫進格子裡**（哪幾個 arc 已下沉跑 `uv run --project <套件根>/tools/derived_sync readiness --book <書>` 第 3 節，它由檔案系統重算），並在「局部下沉紀錄」補一列（同時記大綱層與幕綱層下沉狀態）。

## 缺口診斷報告（核心行為）

依 `創作流程.md` 的「回到哪一層修」觀念，整理後回報各階段狀態——**哪些有了、哪些缺、哪些弱**，並指引下一步。範例語氣：

- 「還沒有結局 → 大綱無法定稿（結局是回頭修正前文的樞紐）」
- 「題旨待定 → 摘要的『因為 X 導致 Y』填不出，主線可能還沒收斂」
- 「幕023 的結果沒有催發下一幕（有果無因/有因無果），建議修結果或補前因」
- 「主角『需要』不明確，角色弧線測不了」

報告格式建議：分「✅ 已具備／⚠️ 偏弱／❌ 缺」三類，每條附「建議下一步」，最後點出**最該先補的一到兩項**（通常是前三步：主線／題旨／結局）。

## 邊界

- **上游**：粗階段（分揀素材、彙整世界觀、收斂主線/題旨、攤開承重分叉）是 `develop` 的事；organize 不做冷啟動，發現大方向未就緒就退回 develop。
- **下游**：不負責把大綱拆成完整幕綱（那是 `beat-sheet`），但可產出雛形。大綱/摘要大致定稿後，可用 `outline-test` 跑形式化的結構不變量測試（organize 本身的缺口診斷是共創過程中的非正式版本，outline-test 是定稿前的正式審稿）。
- **兩者按卷分工，不是二選一**（2026-07-28 抉擇 4 A，**取代舊的「局部模式不是常態」禁令**）：`01-大綱.md` 涵蓋**已收斂的卷**；尚未收斂的卷走 scoped，收斂時回填（程序見 4a）。**同一個 arc 兩邊都有內容才是問題**（`outline-lint` 第 8 項報），未併入的 scoped 只是常態資訊。
  > **為什麼改**：舊條文寫「一旦全書結局/題旨拍板…**不會有**繼續新增局部 `大綱/arcNN.md` 的狀況」，而實測某本書有 3 支（arc09／10／11），**全在 `01-大綱.md` 定稿之後產出、由 `organize` 自己產的**，連續 3 個 arc、5 天、0 警報，而且每一輪都是作者逐題拍板、沒有出過錯——它與作者已明文拍板的「一卷一卷立、底一次講死後面沒得玩」的留白紀律直接相符。**這是規格錯了不是書錯了。** 配套是 `beat-sheet` 的路由反轉（舊路由在這個狀態下指向一個字都沒寫該卷情節的檔，**沒出事的唯一原因是有人手寫了一句指標**）。
- 不做動筆寫章節（子專案 B）。
- 大綱的逐步精修不另開 skill——用本 skill + 對話即可。
