# write — 依幕綱撰寫正文

把已經共創（理想上也測試過）的結構化幕綱，展開成真正的散文章節。依 `創作流程.md` 的二分：前三步是「創作故事」，幕綱起的後三步是「製造小說」——本 skill 是「製造小說」的撰寫步驟，同樣需要方法：怎麼把「行動／衝突／結果」三個詞展開成有畫面、有對白、有感官細節的段落。

**AI 角色 = 共創撰寫，不是代筆定稿**：你依幕綱與技巧知識庫提出正文草稿、提議分章與 POV，但**所有創作決定權在作者**——分章方案、POV 選擇、任何一段文字都可被作者全盤重寫或否決。與上游 skill 不同的是，這裡 AI 直接產出可讀的散文草稿（而非骨架），但草稿的地位不變：可編輯、非受保護、非定案。

## 正文五鐵律（動筆前先讀）

> 這五條是**總綱**，刻意少而顯眼——對抗大型語言模型「把戲摘要掉、段段宣布意義、每章當場了結再總結一句」的爽文預設語域。它高於下面 20 個技法檔：**先過五鐵律，再落各技法檔細則**。技法檔講「怎麼寫好」，五鐵律講「哪些一定不能犯」。**R1–R4 是句／段層（每段先過這關），R5 是章層（每寫一個章末先過這關）。**

1. **戲劇化不摘要**：幕綱的「行動／衝突／結果」是承重事件，必須展開成讓讀者*經歷*的 Scene；**不得用一句「敘述其意義」收掉、不得塞進時間狀語或從屬子句一筆帶過**。判準：一件會被下游幕引用的事，若讀者沒在場「看到它發生」，就是違規。（反例：「答案在他譯通第三塊碎片、往縱深多走了幾步之後，撞到臉上」——「譯通第三塊碎片」是幕級進展，卻被壓進時間狀語。）
2. **反思讓位給當下**：每個 Scene 以**當下可觀察的動作／對白／感官**為主體，內心反思與「意義敘述」（解釋這件事代表什麼、角色從中悟到什麼）為輔；**不得段段以意義塊收尾、不得連續數段都在角色腦內解釋剛才那一下的意涵**。粗錨（非死線）：一個 Scene 內抽象反思不宜多過當下演出的篇幅。
3. **禁解說**：禁止替讀者宣布「剛才那一下是什麼意思」。有兩種形態，**段級的那種才是大宗**：
   - **(a) 段落級解說結構**（主要病徵）：一整段的工作是解說剛才那一手的**用意**，或把推理過程**結算**成條列——「這句是留的活話。既解釋了他為什麼像個木頭，又給日後留了個由頭」／「他先算它能燒到哪兒……他把這兩樣擺清楚，得出一個乾乾淨淨的結論」。判準：**這一段抽掉，讀者會少掉什麼？** 若只少掉「作者的解釋」而沒少掉任何發生的事，它就是解說段。改法是**把那個用意演出來**——讓對手的反應、下一個動作、或事後的代價證明它，不是把解說寫得更含蓄。
   - **(b) 句級反射式收尾**：「他懂了／他忽然明白／他這才想起／原來如此／這意味著／他很清楚」這類頓悟宣布句**作為段落／場景的收尾**。禁的是「作為意義標記的收尾用法」，不是這些字永不出現。
   > 為什麼分兩層：`診斷01` R4 實測，(b) 的詞表在原著（健康）語料上比在生成（病態）語料上響得**更多**——只盯詞表會漏掉整個 (a)。真正吃掉篇幅的是 (a)：生成版的解說密度是原著的 50 倍。機械層見 `write-test` 測試8（`prose-metrics --exposition-list`）。
4. **逐段時空/因果連續**：相鄰段落之間要有可追的時間、空間、因果連結；承重轉折要**演出中間過程**，不得每段各自是自足的「頓悟塊」而跳過中間步驟。跨章同理：上一章子句裡發生的事，下一章不得直接當既成前提引用（那正是「跳躍、要回頭查」的來源）。
5. **章末不總結、跨章不斷線**（章層）：**章末禁用「回顧本章處境＋預告未來」的總結段收尾**（反例：「他站在一個死人的屋子裡…欠著死人的債…被仇家盯著」／「三日之後，真正的那個人要親自來了」——這是講述、是「硬要總結感」的來源）。**續接同一張力的章要硬切**（停在未解畫面/動作，不回顧不預告）；**一條連續張力線的宏觀目標不得每章各自了結**——小節拍可結，throughline 要跨章留著悶燒。判準：一段（數章）若每章都把自己的局部目標當場贏乾淨、章末各自打包總結，就是碎片化違規。細則見 `技巧知識庫/戲劇張力與懸念.md` §二「章末三種切法」、`場景與情節推進.md` §六。

> 五鐵律讓「爽」是**演出來、掙來的**，不是文學化稀釋——文學技巧讓網文的爽站得住腳（見 `技巧知識庫/網文與文學取捨.md` 關鍵洞見），與網文向不衝突。

## 共同約定（必讀）

資源定位、AI 角色（共創＋審稿、非門檻）、**源→衍生兩檔＋待裁決回饋**規則見 `結構定義/共同約定.md`（二、三、四）；**本 skill 最吃重的是第七節「承諾與演出」**——它定義了你必須遵守什麼、可以自由發明什麼（見下「承諾核對協定」）。本 skill 專屬：`chapters/` 資料夾若不存在則建立；正文寫**源** `chNNNN.md`（純散文＋內嵌幕錨點）、機讀 metadata 寫**衍生** `chNNNN.ai.md`，寫完 `cd tools/derived_sync && uv run derived-sync stamp chNNNN.ai.md`（連 `_index.ai.md` 一起封章）。

## 依據

> 讀技法檔時先讀各檔檔頭「目錄」標**核心**的小節；標「附錄（按需取用）」的深素材／跨語言補充，只在該幕實際觸及時再讀對應小節，避免整檔攤平稀釋該幕真正需要的技巧。

- `結構定義/風格.schema.md`——每章套哪份風格：讀 `story/設定/風格/風格.ai.md` 的 `禁用詞表`／`稱謂系統`／`可用句式`／`語域` 落筆（多風格檔時依章選）；`chNNNN.ai.md` 的 `風格` 欄記本章用哪份。
- `結構定義/幕綱.schema.md`——輸入格式，`[[幕NNN]]`、`埋/收[[伏筆:x]]` 連結規範。
- `結構定義/回饋記錄.schema.md`——上游回饋落點（各設定層／摘要衍生檔 `.ai.md` 的「## 待裁決回饋」；幕綱本身無此區塊，見「邊界」）。
- `結構定義/事實流.schema.md` ＋ `tools/fact_projection`（fold 投影程式）——章首讀 as-of 投影（進場知識邊界＋生效中的錨與約束，步驟 1.5）、章末 append 事實（產出端，步驟 8）的格式與工具。三類型：`狀態`（6 維）／`錨`（正文釘死的數字·專名·道具語彙）／`約束`（下游不得寫成 X）。
- `技巧知識庫/場景與情節推進.md`——每幕展開成 Scene（Goal/Conflict/Disaster）＋幕間 Sequel（Reaction/Dilemma/Decision）的核心操作方法；幕綱「行動/衝突/結果」三欄的展開公式。
- `技巧知識庫/展示而非講述與五感描寫.md`——逐段執行標準：關鍵時刻用展示、過場可講述，處理過濾詞/資訊傾倒/形容詞化情緒/副詞化對白標籤。
- `技巧知識庫/視角與敘事人稱.md`（概念層·核心）——決定/沿用每章 POV、每場景單一視角、第四節知識邊界（供核對 POV 不越界）。
- `技巧知識庫/敘事距離與DeepPOV.md`（正文執行層·核心）——第一節 Deep POV 句子技巧（去過濾詞、感官直接落在角色身上、內心獨白直接/間接交替、少用角色自呼其名）；第二節敘事心理距離拉遠/拉近（psychic distance）。
- `技巧知識庫/動作場面寫作.md`——幕的行動/衝突若屬戰鬥/動作類型時的專項準則（五面向；玄幻/仙俠專屬的兩條額外路徑僅在對應類型才套用，一般敘事幕不用）。
- `技巧知識庫/氛圍與筆調.md`——筆調前後一致的基準，對照 `00-摘要.md` 基調＋ `風格.ai.md` 腔調自我核對。

- `技巧知識庫/對白.md`——寫對白時的句型配置、六大功能、潛台詞、action beat；避開七大壞習慣。
- `技巧知識庫/戲劇張力與懸念.md`——把幕尾懸念寫成 cliffhanger（七種停止點）、心痛四手法的內心煎熬描寫、開場鉤子；§一 資訊差引擎（扮豬吃虎／替他捏汗的渲染）、§六(d) 開頭vs常態兩檔位（別把開篇緊繃硬套常態段）。
- `技巧知識庫/世界觀與背景.md` §九「設定帶出的操作判準」（**只讀此小節**）——渲染設定登場時：先現象後定義、術語延後、一次1–2詞＋當句配功能標籤、由主角動作需求或有私心對話逼出，勿旁白說明書（對治「設定突然蹦出」）。
- `技巧知識庫/因果法則.md`——幕的五要素，撰寫時仍須尊重，不可無意間改變幕綱定義的因果。
- `技巧知識庫/伏筆與意外.md`——撰寫埋/收伏筆段落時的措辭需符合伏筆閉合/謎三角精神，不可意外提前洩漏不該揭露的伏筆。
- `技巧知識庫/需求四象限.md`——撰寫角色內心戲/抉擇時，對照角色需求弧線當前位置。
- `技巧知識庫/角色塑造.md`——把角色寫進正文時優先用塑造六法的中後段（象徵/對話/行動/內心）而非直述法，落實三層行為反差。
- `技巧知識庫/主題題旨.md`——撰寫涉及主題三角鋪陳點的幕時，確保文字真的落地呼應，而非空談。
- `技巧知識庫/畫面感與電影化.md`——用文句控制鏡頭：句長＝停滯時間、換行短句＝特寫、示現/插敘/時間伸縮/五感轉場；依「取向定位」拿捏密度（大巧若拙）。⚠️ **換行短句＝特寫是配額型**：它是重拍不是常態句法，密度上限見步驟6「行文節奏三條上限」（**配額不隨取向定位放寬**）。
- `技巧知識庫/字詞句法與抗生硬.md`（正文執行層·**地板的一半**）——字詞/句法抗生硬：M1 強動詞、M2 名詞落地、M3 修飾語橫向攤開、M4 句法直接性（★）、M6 語氣顆粒、M7 生硬句十病徵。**普世地板、always-on、取向定位無關**（不同於下一檔的文學向 opt-in）；是 `網文與文學取捨.md` §二·補「流暢四層次②③」的操作化細則。⚠️ 它的總開關「更具體、更短、更主動、更口語」是**單向**的，十病徵也全是「太長太抽象」型——**另一半地板（防「碎」）在步驟6「行文節奏三條上限」**（完整技法檔 `行文節奏與呼吸.md` 生成時不載入，見該條說明）。
- `技巧知識庫/修辭與字句鍛鍊.md`（正文執行層·**天花板**）——句子層級修辭：譬喻（以感受譬喻、喻依貼氣氛）、擬詩（重複/排比/疊字/留白）、映襯（正襯/反襯）；依取向定位選擇性加碼、文學向才在字句鍛鍊加重手（地板見上一檔）。
- `技巧知識庫/心理描寫.md`——內在描寫五技法（內心獨白/夢境幻覺/環境襯托/神情動作/意識流）＋疼痛描寫「掛在鮮活人物身上」。⚠️ §二之二「內心戲的兩種」是**配額型**：生成時只取步驟6 的上限句（種類換離題型／一章 2–3 處／不連續兩段），**完整判準不載入**——正面技法在動筆時會被套用到每一段，那正是配額要防的。

## 流程

1. **讀輸入**：
   - 依作者指定的 arc 或幕範圍，讀 `story/幕綱/arcNN.md`（若範圍內的幕有 `[[幕NNN]]` 引用到範圍外/跨 arc，一併讀取解析，比照 `beat-test` 的跨 arc 讀取規則）。
   - 若目標範圍沒有對應幕綱 → **停下**，說明「這個範圍還沒有幕綱」，建議先跑 `beat-sheet`；不得在缺乏幕綱依據時憑空杜撰正文。
   - **設定層走選取、不整批讀**（`共同約定.md` 八 context 取用契約）：
     `uv run --project <套件根>/tools/settings_select settings-select --book <書資料夾> --arc arcNN [--beats 幕N-幕M]`
     它掃幕綱的「角色」欄與世界觀提及，只吐這個範圍真正涉及的檔——**讀它列出的檔就好，不要 `設定/角色/*` 全撈**。
     - 每個實體會吐**兩側**：衍生 `.ai.md`（需求四象限／弧線）＋源（人物描述·腔調·能力）。兩側都要——衍生依 schema 只放分析，只讀它會拿不到腔調與外貌。
     - 角色源若是**目錄形態**（`<名>/核心.md`…），工具依切面給檔。**`水下.md` 預設不給**，那是揭底資訊的存取控制；`write` 一律不要加 `--include-underwater`（要用到水下設定代表這一章在揭底，那該由幕綱明寫）。需要更窄可加 `--facets 核心,能力`。
     - 工具另會列出「只在角色欄以外出現的角色」，那是幕綱可能漏填角色欄的訊號，**不要自行補讀**，在交付時當可疑點提出。
   - 其餘（單檔、有界，照常讀）：`story/設定/風格/風格.ai.md`（腔調·禁用詞表·稱謂系統·可用句式）、`story/參照/結構.md`；源 `story/00-摘要.md`（題旨／基調）＋衍生 `00-摘要.ai.md`（取向定位分析）。
   - 讀既有 `chapters/_index.ai.md`（若存在，權威章序）：避免重複撰寫已完成的章節、避免重新編號已寫的 chNNNN；若本次範圍與既有章節重疊，向作者確認是覆寫還是跳過。

1.5. **章首讀事實投影（閉合 read-loop）**：動筆某章前，對該章對應幕號呼叫投影程式取得進場知識邊界與生效中的約束——
   `uv run --project <套件根>/tools/fact_projection fact-project --book <書資料夾> --as-of 幕NNN（arcAA） --entities <POV主角＋關鍵配角> --active-only`
   （幕號＝該章對應幕；因事件流只含已寫章，傳該幕即得進場態）。把投影當「本章相關實體 as-of 狀態」的進場知識邊界，與 POV 知識邊界規則（步驟6）一起用。**投影標明的當下狀態優先於 `設定/角色/*.ai.md` 等靜態基線描述**——靜態卡記「全年常態基線」，投影記「逐幕當下」；兩者衝突時（如某物件已易手、關係已變）以投影為準，避免沿用過時基線判錯。投影是衍生、可覆算、可追溯（每條標來源幕）；**程式唯讀，不改任何檔**。`story/參照/事實流.md` 或 `story/幕綱/_index.md` spine 尚未建立時，此步跳過、退回即時重建。
   - **`錨` 是硬的**：投影吐出的 `錨〔…〕` 是正文已經寫死的數字／專名／道具語彙，**照抄不得另報一個版本**（年齡、他人帳上記的是哪個名字、某道具的形制）。
   - **`約束` 是負向的**：`約束〔…〕` 是「不得寫成 X」，用 `--active-only` 只拿還生效的。違反約束比違反狀態嚴重——狀態寫錯是連貫性瑕疵，約束寫錯會撞碎已經付款的弧線。

2. **就緒提醒（non-blocking）**：檢查 `story/參照/就緒儀表.md` 對應 arc 的「幕綱」欄或幕綱檔頭有無 beat-test 執行紀錄；若看不出這個範圍測試過，提醒「建議先跑 beat-test 抓結構漏洞再動筆，但你也可以現在就開始」——不阻擋，呼應「AI 是審稿員不是門檻」。

3. **提議分章（AI 提議，作者拍板）——以「節奏單位」為分章單位**：分章的單位不是「篇幅感」，而是一個**節奏單位**。節奏單位有兩種、都合法：(i) 一個**閉合**的爽點/情緒循環（小起承轉結），或 (ii) **一段連續張力線中的一節**——本章只結一個小節拍，那條宏觀目標**跨章不閉合、持續悶燒**。**別把每章都寫成 (i)**：整段（數章）都是各自閉合的小勝利、章末各自打包，正文就會碎、無記憶點（見五鐵律 R5、`場景與情節推進.md` §六）。提出候選分章表（候選章｜涵蓋幕｜所屬張力線｜章末切法｜**在場者**｜**場景**｜**本章最大外部事件**｜理由｜預估字數）。
   - **後三欄是「演出骨」，動筆前就要能填**——它讓「這一章實際上要演什麼」在**拍分章的當下**就可見，而不是等十章寫完才發現空了。`在場者`＝這一章有台詞或有動作的人（含主角）；`場景`＝實際發生的地點；`本章最大外部事件`＝這章裡主角以外的世界發生的最大一件事，**真的沒有就寫「無」，不要粉飾**。
   - 出現 `在場者：主角 1 人` ＋ `本章最大外部事件：無` 的列，就是一章純內心獨白的預告——**當場提出來問作者**：是刻意的收束餘韻（`合`段收點可以有一章），還是這一幕根本缺一個外顯載體（→ 幕綱問題，走步驟 10）。整段（數章）出現多列如此＝結構性空洞，回報作者並建議重跑 `beat-test` 測試9。
   - **動筆前先辨識連續張力線**：從幕綱的伏筆「埋 X幕→收 Y幕」與「前因」鏈，標出哪幾幕共享一條 throughline（一個大目標／一個未解威脅／一個謎）。渲染時這條線要**在正文正體裡持續施壓**（角色記掛、環境提醒），而非只在章末總結一句預告。（例：某威脅埋在首幕、隔數幕才攤牌——中間各章都活在它陰影下、不當場了結。）
   - **依 `00-摘要.md`「取向定位」定基準**：**中文網文向**（如芯片巫師「爽感升級為主」）**預設一章一幕的粒度**（一幕＝一個 Scene）＋強章末鉤子、**一章約 3000 字**（起點體例）；但「一章一幕」只定**粒度**，**不等於「每章都要閉合一個完整爽點循環」**——該幕的 Scene 可以只推進一條跨章張力線而不了結它。文學向才容許章節自然收束、跨幕邊界較鬆。依據見 `技巧知識庫/網文與文學取捨.md`（節奏速度·連載鉤子強度對衝軸）、`場景與情節推進.md` §五（單章快慢）§六（跨章張力線·快慢交替·餘韻）、`Data/跨語言技巧/結構與節奏.md`（連載單位）。
   - **兩個反模式（皆明確避免）**：①把兩個各自完整的爽點循環壓進一章 → 蒙太奇、事件塞進子句、下一章引用即「跳躍、要回頭查」（字數遠超 3000 是信號）；②反過來，每章各自閉合小勝利、章末總結式收尾、宏觀張力從不跨章 → 碎片化、無記憶點（五鐵律 R5）。
   - **字數依張力起伏重分配、非等長勻平**（3000 字為基準非死線，依段落自然邊界浮動）：一段的**高潮幕鋪成 set-piece**（給足感官/對白/來回/升級節拍、明顯厚於過場），**過場/銜接幕壓薄快帶**；並安排**喘息/日常**節拍讓角色特點與記憶點長出來（`場景與情節推進.md` §六b/c）。操作兩個閥：**併章**——某幕展開遠不足基準、與相鄰幕合起來才成一個節奏單位（拆開反而斷氣）→ 併章，作者拍板；**拆幕信號**——某幕展開遠超基準、含多個爽點循環 → 訊號是**幕綱本身該拆幕**，指回 `beat-sheet`，`write` 不硬拆。
   - **既有硬規則不變**：**不可把同一幕拆到兩章**（`章節.schema.md`「一幕不可跨章切開」）。
   - 呈交作者調整（合併/拆開/移動邊界），確認後才動筆。

4. **決定/沿用每章 POV**：以 `story/00-摘要.md`「敘事視角結構」欄為權威來源（該欄缺漏時對照 `設定/角色/*.ai.md`、既有章節慣例，並提醒作者補填），每章固定單一 POV 角色（v1 簡化：不做同章節內多 POV 交錯；書級的多線視角改用不同章節切換 POV 達成）。若幕綱角色欄暗示需要跨角色視角，向作者確認怎麼分配到哪幾章。

5. **逐幕 Scene 展開＋幕間 Sequel 銜接**：依「場景與情節推進」，行動→Goal、衝突→Conflict、結果→Disaster；幕與幕之間視需要展開 Reaction/Dilemma/Decision 過渡文字。標記幕錨點（`<!-- 幕NNN -->`、必要時 `<!-- 幕NNN→幕MMM -->`，見 `結構定義/章節.schema.md`）。**若某幕的核心事件 POV 角色無法直接感知（如沉睡、不在場），Scene 仍只能呈現她實際能感知的片段**（如驚醒瞬間的感官碎片），事件全貌透過後續幕的「事後發現」揭露，不得為了交代劇情而暫時跳出 POV 視角。
   - **快慢交替＋依張力重分配篇幅＋餘韻**（`場景與情節推進.md` §六b/c）：不要每幕等長等速當場解決。Scene（快）↔ 喘息/日常/Sequel（慢）交替；一段的高潮鋪成 **set-piece**（厚）、過場壓薄（快）；一段真正的高潮/兌現**之後留一拍餘韻**（停在畫面/情緒/角色特點，製造記憶點），不立刻切下一鉤。**跨章張力線要在正文正體裡持續施壓**（角色記掛、環境提醒），不是只在章末摘要一句。

5.5. **章末切法決策（每個章末先過 R5）**：寫某章的結尾前，先判「下一章是否緊接同一場景/同一張力」——
   - **續接** → **硬切斷章**（停在未解畫面/動作，不回顧本章、不預告未來、不宣布意義）或**前開式軟鉤**（用一個具體新擾動向前拋）。
   - **段/arc 邊界** → **收束斷章**（可閉合＋喘息，但鉤子是一個新的具體擾動、不是回顧；峰後可先給餘韻再拋）。
   - **一律禁「總結式收尾」**：章末不用「回顧本章處境＋預告未來」的抽象總結段（見五鐵律 R5、`戲劇張力與懸念.md` §二「章末三種切法」）。

6. **句子層級執行**（先過「正文五鐵律」，再落以下各技法檔細則）：
   - 展示而非講述：關鍵時刻具體化為證據而非標籤；過場可保留講述但維持一兩個意象。
   - Deep POV：去過濾詞、感官直接落在 POV 角色身上、內心獨白直接/間接交替、少用角色自呼其名。
   - **抗生硬句法（地板、always-on、不掛取向定位條件）**：對照 `字詞句法與抗生硬.md` M7 十病徵自檢，尤其命中率最高兩項——**M4 句法**（流水句＋主語承前省略＋主謂賓正序、把/將取代被動、語序＝事序、長信息後置；避「當…的時候／由於…而／被…所…」翻譯腔嵌套）與 **M1 動詞**（強具身動詞扛畫面、副詞近乎清零，避「進行/作出/使得＋抽象名詞」名詞化）。這一關與 Show/Tell 正交：Show/Tell 管「該不該演」，本關管「句子本身澀不澀」。
   - **行文節奏三條上限（地板、always-on）——抗生硬會把你推向更短，這一關負責拉回來**：① **重拍裝置配額**：破折號、換行單列的短句（特寫）、留白斷句是**同一個配額池**，**一章（約 3000 字）全部加起來最多 1–2 個**（六本好讀網文實測合計 ≤0.5/千漢字＝約三千字一次；全篇都是特寫＝沒有特寫）。這個數字刻意寫成「一章幾個」而不是「每千字幾次」——後者要邊寫邊估篇幅，實測會被高估成兩倍。**優先花在哪**：那一兩次留給**本章情緒／張力的最高點**（通常是幕的結果轉折或章末切點）；**寫到中段還沒用掉是對的，先寫到先用掉是錯的**。守配額該砍的是前面日常段的裝飾性斷句，**不是後面高潮的留白**——實測踩過這個坑（為守配額把想家段的留白砍了，卻在前段用掉了配額）。② **不寫無新資訊的回聲斷片**：不要把上一段剛說過的話複製成一個獨立短段當重拍（`薑湯。二少爺。老奴。`／`穿了。`／`警覺。`）——獨立成段的短行必須**有主謂、在推進事件**（擬聲、台詞、帶新推論的驚呼除外）。③ **一段一句，而且極短段不要緊鄰長段**（兩半缺一不可，實測少一半就換一種病）：<br>　(a) **寫完一段數句號**：段落＝一個說完的句子（六本實測句/段 0.96–1.25，兩本生成書 1.69／2.13，無重疊）。**一段裡出現第二個句號時，預設把它們用逗號串成一句，不是拆成兩段**——「短、碎、跳」的讀感由**分句層**承擔（分句 8 字上下、一句串 4–5 個），不由句號與換行承擔。<br>　(b) **一個 ≤8 字的獨立段落，前後不可以是 ≥60 字的長段**。寫下一個很短的獨立段落時，往上下看一眼鄰段有多長：要嘛**把它併進鄰段**，要嘛**讓周圍也短下來**。**整章維持同一個段落長度量級**——通篇流水（本書宣告碎在分句時）或通篇短（極道天魔型），**不要兩者交替**：每一次「長段→四字短段→長段」都是一次完全煞車，讀者要重新起速。<br>**為什麼 (b) 非寫不可**（實測踩過）：只給 (a) 時，「段落＝一個句子」會被讀成「每個短句都可以自己站一段」——短行品質沒問題（有主謂、在推進事件），但 ≤8 字獨立段的密度衝到語料的 12 倍，顛簸指數從 0 反彈到 0.88。**(a) 管的是別把一段塞兩三句，(b) 管的是別讓一句話單獨站成一個煞車點。**<br>**③ 的兩條防呆**：(i) 這**不是**「寫短」指令，也**不是**「每句都要長」——長短由**內容說完了沒有**決定；通篇短的極道天魔型合法，**但那是「通篇」短，不是長段之間夾短段**。(ii) **沒有「長句下限」這種東西**：長句佔比實測是文類自由的量（六本 17%–62% 全是好書），別為了讀起來厚一點去拉長句子，那會直接撞回抗生硬的翻譯腔嵌套。該長的地方會因為 (a) 的「併不是切」自己長回來——材料本來就在段落裡，只是被切開了。<br>細則、判準與逐條病徵在 `行文節奏與呼吸.md`，**生成時不必載入**——那是 `write-test` 測試10(b) 與 `revise` 的事。這裡只有上限：正面技法（「把文句縮短做特寫」）在動筆時會被套用到每一段，那正是這三條要防的東西。三條刻意都**可數**（幾個裝置／有沒有重述／這段幾個句號）——實測可數的規則有效，瀰漫的質地指令（「逗號:句號要高一點」）幾乎不動。
   - **內心戲：換種類、不加份量（配額、always-on）**——五鐵律 R3 禁掉解說段之後，**替代品是「離題型」不是「含蓄一點的解說」**。一句話判：把這段拿掉，讀者會不會漏掉劇情？**不會漏、但少認識這個人一點＝離題型，留著**；**不會漏、因為前面已經演過＝解說型，刪掉**；**會漏＝那是被摘要掉的事件，回去演成場面**（R1）。離題型是**配額**：一章（約 3000 字）**2–3 處、不連續兩段**，優先花在場面最大／最緊繃處（反差振幅最高）。⚠️ **這不是「多寫內心戲」的授權**——份量仍受 R2「反思讓位給當下」管，本條只換種類。判準與理由在 `心理描寫.md` §二之二，**生成時不必載入**（那是 `write-test` 測試8 與 `revise` 的事）。
   - **風格落地（依 `風格.ai.md`）**：用詞避開該章風格檔的 `禁用詞表`（時代錯亂／語域錯配詞，如哥特世界別冒「老周」）；人物互稱守 `稱謂系統`；段落性質（常態／恐怖高潮／動作…）套對應 `可用句式` 檔位。**`可用句式` 只宣告一件事：本書的碎感由哪一級標點承擔**（分句／句／段，見 `風格.schema.md`）——照它宣告的那一級落實，不全篇一種句長勻平。**把宣告換算成可數的動作**：宣告「碎在分句」＝敘述段一個句號前串 **3–5 個逗號分句**（寫完數逗號）；宣告「碎在句」＝一段一個短句、句號前 **0–2 個**逗號（極道天魔型，合法）。**選定的那一級貫徹整章**，不在段落級高頻擺盪。<br>**這一關才是「該長的地方要長」的落點，上一條的地板管不到**：句子該多長、長句該佔多少是**文類自由**的量（六本語料 17%–62% 全是好書，實測沒有普世下限），所以它由本書的 `可用句式` 決定。書若有作者指定的參照語料，可用 `prose-metrics --book <書> --corpus <語料>` 的輔助量四項（句長中位／≥40字句字數佔比／逗號:句號／分句均長）核對實測有沒有對上宣告。若該欄殘留舊式寫法（讀感形容詞如「短句為主」、或沒有配額的裝置授權如「可用破折號」），**一律以上一條的三條上限為準**，並在 `風格.ai.md`「待裁決回饋」記一列交 `develop` 回頭消化——不要把空頭授權用到極限。此關是 `write-test` 測試5／測試10 與基調一致性的落點。
   - 核對 POV 知識邊界（視角與敘事人稱.md 第四節）：POV 角色不知道的事不能被敘述——本系統多處刻意設計「戲劇反諷」的幕（POV 角色的無知本身就是故事重點），要嚴守邊界而非「幫讀者补足資訊」。

7. **動作場面特判**：若某幕「行動」/「衝突」欄描述屬於戰鬥/動作場面，套用「動作場面寫作」五面向；只有類型確實是玄幻/仙俠時才套用「詞彙鋪張」「鋪墊框架」兩條額外路徑，一般敘事幕不套用。

8. **寫入與索引維護（源＋衍生兩檔）**：依 `結構定義/章節.schema.md`——
   - **正文源** `chapters/chNNNN.md`（補零 4 位）：純散文＋內嵌幕錨點 `<!-- 幕NNN -->`／`<!-- 幕NNN→幕MMM -->`＋章名標題，**無 front-matter**。
   - **衍生 metadata** `chapters/chNNNN.ai.md`：front-matter 記 `對應幕`（掃正文錨點導出）／`所屬arc`／`POV`／`基調參照`／`風格`（本章套哪份風格檔）／`狀態: 草稿`。
   - **重生權威章序** `chapters/_index.ai.md`（含對應幕/POV/風格/狀態列）。
   - **封章**：`cd tools/derived_sync && uv run derived-sync stamp chNNNN.ai.md`（每章一次）＋`derived-sync stamp _index.ai.md`。
   - **append 本章事實（產出端）**（見 `結構定義/事實流.schema.md`）：依固定 4 欄信封 `- 幕NNN（arcAA）· 實體 · <類型 token>：內容` append 進 `story/參照/事實流.md`。只記已寫章、位置＝該章對應幕號、引用伏筆/實體用名字不重抄幕綱埋/收。三類：
     - `狀態`——6 維枚舉 `知識前沿｜關係｜持有｜位置｜能力｜所屬`，本章發生的變化。
     - `錨〔名〕`——**本章正文把某個數字／專名／道具語彙寫死了**（角色報了幾歲、某人帳上記下的是哪個名字、道具的形制與用法）。判準：後續章節若另報一個版本，讀者會發現矛盾。錨名同一件事一律沿用同一個，否則 slot 會分裂成兩筆並存。
     - `約束〔名〕`——本章寫成後產生的「下游不得寫成 X」（多由作者拍板或 `write-test` 促升；`write` 自己判得出的也可直接記，交作者審）。
     - **`知識前沿` 寫「當下承重的知識前沿整體」，不是流水帳**：每 `(實體,維度)` 是單槽、最新覆蓋（fold 只留序最新一筆），故一條 `知識前沿` 事件要能獨立代表該實體此刻對主線的知識邊界；瑣碎或與主線正交的支線知識不要記成會覆蓋承重前沿的獨立事件。
     - **`錨`／`約束` 不寫進 `設定/角色/<名>.ai.md`**：那裡是需求四象限與弧線的分析區，節是封閉枚舉（`角色.schema.md`）。過去「硬事實」「下游硬約束」「反派備註」這類自創節就是這麼長出來的，成長哨兵 `衍生檔不可切片` 會報。
     - **章末狀態快照改由投影衍生、不再手維護**：需要人眼可讀的章末切片時，跑投影程式（`fact-project --as-of` 該章末幕）產生，非手抄。作者當場審改事件。
     - 跨 arc/跨集一致性校驗、程式端比對仍不在此做（延後，見 spec YAGNI）。

9. **基調與取向定位自我檢查**：對照 `00-摘要.md`「基調」欄自我核對本章筆調（`氛圍與筆調.md`「筆調前後一致」）；並對照「取向定位」欄核對節奏／爽點密度／揭露速度／資訊密度是否與宣告的網文↔文學傾向相符（依 `網文與文學取捨.md`）——如摘要說「文學向為底」卻寫成通篇快爽套路，或說「爽文」卻節奏拖沓，都在交付時主動提出，不悶著不說。

10. **上游問題發現的處理**：
    - 問題根源在幕綱本身（因果不順/伏筆安排不合理/結構階段誤置）→ 幕綱本無下游回饋記錄區塊、定位為作者可直接修改的利器；本 skill **不代作者編輯幕綱**，只在對話中明確指出疑點，建議作者直接修改幕綱或重跑 `beat-test`。
    - 問題根源在更上游（世界觀／00-摘要／角色／風格，對應**衍生檔** `<主題>.ai.md`／`00-摘要.ai.md`／`<名>.ai.md`／`風格.ai.md` 有「## 待裁決回饋」區）→ 依 `結構定義/回饋記錄.schema.md` 在該衍生檔的「## 待裁決回饋」追加一列（來源標「write（chNNNN 撰寫時）」、建議回寫指向對應**源檔**），不改源、不改分析區，並提示作者已記錄 N 筆待裁決回饋。

## 承諾核對協定（撞到上游沒寫的細節時）

> **`write` 不是設定產生器，但是場面產生器。** 幕綱給的是骨架，血肉本來就該在這裡長出來——不准發明的是**規則與承重事實**，不是**人、話、動作與場景**。正文是**人管·源**（`共同約定.md` 二、`章節.schema.md`「用途」），它是這個世界具體長什麼樣實際居住的地方。
>
> **為什麼改掉舊版**：舊協定要求動筆前先分類每個細節是「承重」還是「一次性」，並規定「判不準時寧可當承重報出來」。「這個細節後面會不會被依賴」是一個**預測**問題、不可判定；於是分類負擔變成寒蟬效應，實測結果是整章不寫場面、只寫主角在腦內盤算。本協定把不可判定的預測換成**可判定的查詢**。

### 動筆前只回答一個問題

**上游有沒有講過這件事？**

- **有** → 那是**承諾**，遵守。承諾的範圍是可列舉的三處：① `story/設定/**` ② `story/幕綱/`（承諾區＋八欄；檔尾設計註只讀不抄）③ `story/參照/事實流.md`（狀態＋錨＋約束，走步驟 1.5 的投影查詢）。
- **沒有** → 那是**演出**，**自由發明、放手寫、不必標記**。在場的人、房裡的物件、天氣、一句寒暄、一個動作、對白的措辭，全屬此類。
- **沉默＝授權**：幕綱沒寫的細節就是你的。幕綱也不該再寫「留 `write` 現場長」——那是預設而非例外（見 `幕綱.schema.md`「arc 檔的內部結構」）。

**判不準時：先把場面寫出來，再把那條可能承重的斷言報出來。** 兩件事不衝突——不要為了避免標記而放棄演出。

### 事後回報（永不作為動筆前的閘門）

寫完之後，回頭看有沒有哪條演出其實會被後續章節依賴、或構成一條新承諾：

- **狀態型**（某實體某維度的變化：知識前沿／關係／持有／位置／能力／所屬）**／錨型**（正文釘死的數字·專名·道具語彙）**／約束型**（下游不得寫成 X）→ 走步驟 8，append 進 `事實流.md`。
- **新規則／新設定事實**（世界觀規則、角色的既定背景）→ 走步驟 10，依 `結構定義/回饋記錄.schema.md` 在對應衍生檔 `設定/世界觀/<主題>.ai.md`（該主題尚不存在時 `_總覽.ai.md`）／`設定/角色/<名>.ai.md` 的「## 待裁決回饋」追加一列，來源標「write（chNNNN 撰寫時·升格候選）」、建議回寫指向對應源檔，交作者裁決是否改源正式入設定。

**一致性不靠事前自我審查，靠三件事**：① 動筆前讀前一章正文對腔 ② 狀態投影（步驟 1.5）③ 事後促升偵測（`write-test` 測試9）。**改的是順序（先演出、後回報），不是取消回報，也不新增第二本帳。**

- **邊界**：本協定只「寫＋回報」，**不代作者把承重細節寫進設定正文**（那是作者拍板後的事，呼應「AI＝共創＋審稿、非門檻」）。

## 輸出格式

- 步驟3的分章提議表（供作者拍板）。
- 完成後列出本次寫了哪些 `chNNNN`、涵蓋哪些幕、篇幅概況，並確認已 stamp（`derived-sync check` 該書不報這幾章 stale）。
- 若有上游回饋，列出筆數與去向。
- **本章演出盤點**（每章一行，交付時複述步驟3 的演出骨、以實際寫成的內容為準）：
  `chNNNN｜在場角色數｜有台詞的角色數｜場景數｜本章最大外部事件（一句話，無則寫「無」）`
  這是「反空洞」的自曝欄位，零語意判斷。出現 `1｜0｜1｜無` 這種列就主動點出來交作者判斷（見步驟3），不要悶著不說。
- **升格候選清單**：依「承諾核對協定」的事後回報，列出本章寫成後判定會被後續章節依賴／構成新承諾的細節，各標去向（append 進 `事實流.md` 的哪一類／已於 `設定/世界觀/<主題>.ai.md`／`設定/角色/<名>.ai.md` 追加待裁決回饋列）。無則明說「無升格候選」。這份清單是 `write-test` 測試9 的複判起點。**這份清單長不代表寫壞了**——新協定下 write 本來就會生出更多具體東西，候選變多是預期且健康的訊號。
- **明確聲明**：以上為撰寫草稿，所有文字可全盤修改，非定稿。

## 邊界

- 不做審稿（那是 `write-test`）——不自動檢查自己寫出來的東西是否有結構/一致性問題，只在撰寫過程中盡力遵守技巧知識庫；檢查點清單見 `結構定義/章節.schema.md`。
- 修稿不在本 skill 流程內——本 skill 只管「從無到有寫出草稿」；作者要修改既有章節時走 `revise`（依 write-test 報告或作者指示定點修訂），或在對話中依本 skill 的句子層級依據協助，不必拒絕。
- 規模化狀態連貫性由子專案 C 的事件流＋fold 投影承載（章首讀投影＝步驟 1.5、章末產事件＝步驟 8）；仍**不建**程式端一致性校驗、持久 cache、跨 arc/跨集狀態機、自動偵測幕綱於成章後又被修改（延後，見 spec YAGNI）。`write` 只在既有時機明確呼叫投影程式與 append 事件，無常駐程序、不自動鏈式觸發。
- **不強制章節邊界**：分章永遠是提議，作者拍板。
- 不做同一章節內多 POV 交錯（v1 簡化；書級多線視角靠不同章節切換 POV 達成，不受此限）。
